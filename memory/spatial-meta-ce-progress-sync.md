# 进度同步与新会话接手

> 整理日期：2026-10-05。来源：Claude 项目记忆 `spatial-meta-ce-progress-sync.md`。
> 本文件是整理后的项目内副本，不会自动与 Claude 原记忆同步；原文件保持不变。

## 固定入口

[实验文档/99-进度与下一步.md](../实验文档/99-进度与下一步.md) 是主要接手文档。新会话开始先读它，再核对最新提交、对应结果 JSON 和正在运行任务，不只依赖会话历史。

## 主执行任务收尾应记录

- 当前阶段、已完成事项、日期、实验名及实际证据位置。
- 正在运行任务的命令、PID、服务器路径、查询状态的方法；ETA 若是估计必须明示。
- 已验证/未验证、已提交/未提交、已推送/未推送分别记录。
- 下一步按优先级列出，并注明授权、输入冻结、环境和数据门槛。
- 已知阻塞、风险及实验边界，不能把 blocked 改成 completed。
- 新会话接手所需命令；不得包含密码、密钥或数据库凭据。

## 防止旧状态覆盖新证据

- 同一天也可能有多个历史阶段；“P2 未执行”等文字必须结合所属提交和时间解读。
- 文档与结果冲突时，优先核对 hash 绑定结果及对应提交，并明确冲突，不挑选有利描述。
- 不机械复制旧测试数量、GPU 空闲状态或后台 PID。
- 更新共享进度文档前检查另一窗口是否正在修改。侧对话仅整理记忆时不覆盖主任务的进度文件。
- 新状态尽量写入主接手文档；记忆保留稳定经验和指向证据的入口，避免再建立另一份实时进度账本。
