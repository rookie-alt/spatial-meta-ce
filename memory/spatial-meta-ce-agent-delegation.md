# 自动子代理委派、方案审查与验证

> 记录日期：2026-10-07。来源：用户在项目侧对话中确认的自动委派、方案审查及测试验证要求，并明确要求保存到项目记忆，由 `AGENTS.md` 指向。
> 性质：稳定的项目执行约定，不是实验结果或实时进度。参考当日本地 ECC 2.2.3 的代理编排规则与相关技能；角色及工具是否可用须现场核对。

## 1. 自动委派授权与边界

- 在用户已授权的当前任务范围内，允许主代理自行决定创建子代理，不必逐次询问“是否使用子代理”。这同时适用于实现、独立分析、测试验证及方案审查。
- 本授权仅允许分工，不扩展任务范围或操作权限。子代理必须遵守 [项目指令](../AGENTS.md) 的实验红线、数据边界、共享工作区规则和停止条件。
- 不得通过委派绕过审批、训练授权、GPU 使用授权、服务器访问限制、目标库禁入或用户停止指令。当前会话若明确禁止子代理，则禁止优先，本记忆不能解除该限制。
- 子代理审查通过，不意味着可以自动训练、调参、部署、推送或开展目标评估。外部操作仍以用户授权及既有规则为准。

## 2. 判断何时委派

优先委派有明确输入、输出和验收标准，且能独立推进的工作：

- 大量文件、日志或结果的只读探索，可回传摘要与证据位置。
- 可与主实现并行的统计复算、来源绑定和协议一致性检查。
- 写入范围互不重叠的代码或测试实现。
- 实现后的独立正确性、测试覆盖或安全审查。
- 实验方案、技术路线或高影响计划的独立评估。

任务复杂或耗时只是考虑因素，不是充分条件。以下通常由主代理完成：

- 少量文件读取、简单修改和短命令。
- 主代理下一步立即依赖的关键阻塞工作。
- 强依赖完整上下文，难以独立描述的任务。
- 分工与整合成本超过预期收益的工作。

长时间训练、测试或推理不自动需要子代理；是否启动、资源预算和进程管理仍遵守原有规则。不为使用多个代理而机械拆分。

## 3. 分工契约与上下文管理

委派前先建立简短计划，区分顺序关键步骤、可并行步骤及主代理当前立即执行的工作。默认同时运行最多 2 个子代理，必要时最多 3 个，并遵守工具实际并发上限。

每个子代理一次承担一个有限任务，任务说明包含：

1. 目标与可观察的完成条件。
2. 输入的绝对路径、基准提交或冻结协议。
3. 允许读取和修改的范围。
4. 禁止事项、授权边界、资源及时间限制。
5. 必须执行的验证及证据保存位置。
6. 回传格式与需要交由主代理决策的事项。

- 优先提供最小必要上下文，不默认复制完整对话；但必须传递与任务相关的项目约束，不能以隔离上下文为由省略红线。
- 独立上下文可减少主代理接收的探索日志和中间推理，不保证完全不占用主上下文。结果摘要、必要证据及整合仍由主代理接收。
- 子代理不得递归创建更多子代理，除非用户明确授权；默认继承主代理模型，不擅自切换模型。
- 主代理不重复执行已经委派的同一工作。只在确实依赖结果且暂无其他可推进工作时等待，不反复轮询。

## 4. 写入隔离与共享工作区

- 独立验证及方案审查代理默认只读；实现代理必须有明确且互不重叠的写入范围。
- 同一文件同一阶段只能有一个写入负责人。冲突风险较高时使用独立 worktree，仅使用该检出的绝对路径。
- 不切换、重置、清理或覆盖其他窗口的分支与未提交内容；不提交其他窗口的工作。
- worktree 隔离不意味着服务器、缓存、GPU 或外部资源已经隔离，使用前仍核对归属与权限。
- 子代理默认不提交、不推送、不合并，由主代理按照既有授权统一处理。
- 仅维护记忆的侧对话，不覆盖主任务进度文档、不重建生成索引、不为了同步而擅自更改主线程 Git 状态。跨 worktree 的记忆需要主任务明确整合，不自动同步。

## 5. 测试与独立验证

- 缺陷修复先复现失败，再修改并验证；新增逻辑先写能失败的测试，确认失败原因后实现到通过。
- 行为保持型修改核对前后行为。先运行针对性测试，再按影响范围运行回归测试和静态检查。
- 独立审查代理检查实际 diff、输入证据及真实测试输出，不仅根据实现代理总结判断正确。

本项目代码改动后的标准验证：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests -v
ruff check scripts tests spatial_meta_ce
```

执行前确认实际 Python、依赖、工作目录与任务授权。服务器验证、依赖安装和 GPU 实验不因本记忆而获得额外权限；必要时参考 [工作流](spatial-meta-ce-workflow.md)。

实验与统计逻辑的测试按影响范围覆盖：

- 训练、验证、目标数据库划分及目标禁入。
- query_hash 身份配对、去重和完整分母。
- 缺失、重复、错配、非有限值和来源 SHA256 变化。
- 指标定义与聚合口径；训练 seed 和 support 抽样不确定性分离。
- 冻结配置、checkpoint、预算一致性及失败停止留痕。

重要统计结论优先采用不同实现独立复算，不得仅调用被验证的生产统计函数就宣称独立核验。合成测试、smoke、工具回归、正式实验必须分别标注。

历史 lint 或测试问题单独记录，不借机扩大修改范围。不得删除测试、放宽容限、静默过滤或跳过失败项制造通过。只改文档时检查本次链接、空白和来源，不虚构代码测试通过。

## 6. 方案的独立审查

复杂实验方案、技术路线或高影响实现计划，允许主代理主动安排 1–2 个职责不同的只读审查代理，计入整个任务的并发上限；简单低风险方案由主代理直接审查。

按方案需要选择视角，不机械启动全部角色：

| 视角 | 检查内容 |
|---|---|
| 研究方法 | 研究问题与假设、变量与对照、公平性、指标与统计口径；能否回答问题；数据泄漏、开发集反复使用、描述性与因果边界 |
| 工程可执行性 | 输入和依赖、实现路径、资源预算、失败路径、数据/checkpoint兼容性、验证、归档及停止条件 |
| 验证与证据 | 成功标准是否可观察；测试、独立复算、来源绑定与负例是否充分；执行后能否做下一步决策 |

### 独立性

- 先锁定待审查的草稿版本及必要原始证据，再交给审查代理；主代理继续完成非重叠工作。
- 首轮代理独立判断，不互相传递结论；不要求“证明方案合理”，不诱导认可主代理的推荐。
- 审查代理不直接修改冻结协议、正式结果或共享进度。缺少资料时登记未知或待核验，不能从缺失证据得出通过结论。

### 发现与汇总

每项发现给出方案位置或证据、严重程度（阻塞/重要改进/可选建议）、对有效性或成本的具体影响、最小修正和验证要求，以及确定性与剩余未知。

主代理复核发现、去重并解决冲突，不按代理人数投票，不把多代理一致当正确性证明。最终区分“可执行”“修正后可执行”“证据不足或存在阻塞”，列出采纳、未采纳和未解决的意见及理由。

未执行的验证只能写成待执行，不捏造测试、显著性、收益或资源测量。审查不产生执行授权；冻结协议、数据划分和实验门槛的变更按既有规则处理。

## 7. 回传、整合与停止

子代理回传简明摘要，包含：

- 完成、部分完成或阻塞状态。
- 修改文件绝对路径；只读任务说明未修改。
- 实际命令、退出状态、结果和证据路径。
- 关键发现及文件/行号或原始证据。
- 未执行的验证、剩余风险及需要决策的事项。

大量日志留在指定路径，不全部复制回主对话，也不省略关键失败细节。

主代理负责收集相关结果、审查修改、解决冲突及必要的集成验证，不能仅凭子代理自报通过。最终报告区分已检查、已修改、已验证、已提交、已推送，主代理对结论和交付质量负责。

不得派出任务后以“等待子代理”为最终交付。完成并整合后及时关闭代理；用户要求停止时停止相关代理及自有任务，不影响他人进程。重复失败遵守 [重试限制](stop-after-three-repeats.md)。

本记录参考的本地 ECC 文件为 `rules/common/agents.md`、`skills/team-agent-orchestration/SKILL.md` 与 `skills/parallel-execution-optimizer/SKILL.md`。采用独立任务并行、依赖任务顺序、清晰负责人和验收门槛、委派后回收整合、避免重叠写入等原则，不复制会突破项目限制的技能指令。

读取链为 [AGENTS.md](../AGENTS.md) → [项目记忆索引](MEMORY.md) → 本文件。`AGENTS.md` 只保留读取入口；完整约定以本文件为准。本约定不会自动修改其他 worktree 或全局配置。
