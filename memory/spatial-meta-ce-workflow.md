# 项目工作流与结果保存

> 整理日期：2026-10-05。来源：Claude 项目记忆 `spatial-meta-ce-workflow.md`。
> 本文件是整理后的项目内副本，不会自动与 Claude 原记忆同步；原文件保持不变。

## 用户约定

1. 实验记录写入项目内 `实验文档/`；精简证据保存在 `实验文档/results/`，服务器真实产物同步回本地对应目录。
2. 改代码前使用独立任务分支，**不在 `main` 上直接提交**。分支状态必须先现场核对，不能照搬历史记忆里的分支名。
   任务验证通过并交付后，把 `main` **fast-forward** 到该分支并推送，使 `main` 始终等于最新已交付进度。护栏：本地全量测试与 `ruff` 通过才快进；禁止 force push；禁止跳过验证快进。
   （2026-10-26 修订：原写法为「不直接修改或推送 `main`」，与用户「保持 main 保持最新进度」的要求冲突，经用户确认改为交付后快进。）
3. 主执行任务形成代码、文档和证据后及时提交并同步 Gitee，保证可回溯。提交前核对实际 diff，只纳入本任务内容。
4. 原始数据、缓存、checkpoint 和大文件只留在允许的运行位置，不能当作精简证据提交。
5. 同步或提交是独立状态：本地生成、已验证、已提交、已推送必须分别陈述，不能相互替代。

## 协作安全

- 共享工作区先辨认已有修改；不 reset、stash、clean 或覆盖其他窗口的工作。
- 侧对话或仅编写文件的任务，不为遵循工作流而擅自改变主线程的分支、索引、提交或部署状态。
- 服务器同步前确认代码版本、目标路径和既有产物，禁止覆盖 PRICE 原项目。
- 只读审计的记录不能作为训练或数据库执行授权。

## 目的

论文数字需要绑定代码版本、配置和运行证据；远程备份避免本地或服务器单点丢失。
