例子 当前结构 图结构 差异 风险

Architecture note · 2026-10-28

从扁平 token
到 显式 join 图

这条思路的重点不是“加更多 attention”，而是把一条 SQL 的真实表与 join 关系先画成图，再让消息只沿真实 join 边传递，最后按表项与 join 项做因子化输出。

一句话

当前：四组 token 拼成一条扁平序列 → 全连接 self-attention → 池化 → 全局 MLP。

改法：表节点 + join 边 → edge-aware message passing → 表项/join 项/残差。

不是 ALECE 复刻
ALECE 的 X 是数据库状态；这里画的是查询自身的 join 拓扑。
不是 `attn_pair`
`attn_pair` 只给 fanout token 加 join 序号；这里是真的节点/边图。
仍是待验证假设
先做只读图构造 + ERM 源验证；不直接上目标库。
01 / EXAMPLE

先看一条具体 SQL

用 3 张表、2 条 join、2 个过滤条件，足够看清“扁平 token”和“图”的差别。

SELECT COUNT(*) FROM movie m JOIN cast_info ci ON m.id = ci.movie_id JOIN role_type rt ON ci.role_id = rt.id WHERE m.year > 2000 AND ci.note LIKE '%hero%';

这条查询的两个视角

3 个表节点
movie m
cast_info ci
role_type rt
2 条 join 边
m ↔ ci
ci ↔ rt
2 个过滤
m.year > 2000
ci.note LIKE '%hero%'
表节点 join 边 过滤条件
关键：movie 与 role_type 之间没有直接 join 边。它们只能通过 cast_info 间接通信。
02 / CURRENT

当前：所有 token 全连接

四组 token 先被拼成一条序列，再做 flat self-attention；模型没有“表节点”和“join 边”的概念。

四组变长 token

J1 join histJ2 join hist F1 fanoutF2 fanout T1 tableT2 tableT3 table C1 filterC2 filter
→

拼成扁平序列

长度 = 9（示意）
[J1 J2 F1 F2 T1 T2 T3 C1 C2]
→

全连接 self-attention

每个 token 可以看所有 token；包括没有 join 关系的 T1 与 T3。
→

池化 → 774 维

mean + max + sum；池化后 token 对应关系被压掉。
→

MLP → 残差

pg_log + r

全连接矩阵（示意）

行/列：J1 J2 / F1 F2 / T1 T2 T3 / C1 C2。所有格子都允许 attention，包括跨组、无 join 关系的 token 对。

这就是 `attn` 和 `attn_pair` 的共同问题：它们只改变 token 的内容，不改变谁可以和谁通信。

03 / GRAPH

改法：表节点 + join 边

同一条查询，先画成图；信息只在真实 join 边上传递。下面的虚线表示“没有直接边，不允许直接 attention”。

Edge-aware attention 的核心

只在邻居集合上做 softmax
m_ij = MLP([h_i, h_j, e_ij]) α_ij = softmax_{j ∈ N(i)} ( score(h_i, h_j, e_ij) ) h_i' = h_i + MLP( Σ_j α_ij · m_ij ) e_ij' = e_ij + MLP([e_ij, h_i', h_j'])

`N(i)` 是真实和表 i 有 join 关系的表；`e_ij` 直接参与 score 和 message，所以模型知道“这条边是哪个 join、fanout 多大”。

3 × 3 邻接矩阵

只有两条边：

m ↔ ci，ci ↔ rt。
m ↔ rt 没有直接边。

两层 message passing 后，rt 的信息可以经 ci 到 m；但这不是一步全连接 attention，而是有路径的传播。

两层信息流

Layer 1

m ↔ ci：交换 join ① 的 hist/fanout
ci ↔ rt：交换 join ② 的 hist/fanout
→

Layer 2

m 收到 rt 经 ci 传来的二阶信息；rt 也收到 m 的信息
→

Readout

表节点 + join 边 + 全局 query token → 因子化输出
04 / OUTPUT

输出也从“全局 MLP”改成“因子化残差”

当前是一个全局向量进 MLP；图版本按表项和 join 项分别产生修正，更贴近 log 基数的近似可加性。

当前

log_pred = pg_log + MLP(pooled 774-d)

一个 MLP 从 774 维里自己学“加法”；表越多，越难还原 Σ 结构。

图版本

log_pred = pg_log + Σ_i Δtable_i # 表节点修正 + Σ_ij Δjoin_ij # join 边修正 + Δglobal # 全局残差

所有输出头末层零初始化；未训练时仍精确等于 PG。

示意：一条查询的残差分解（数字仅示意，不是实验结果）

Δ movie-0.30
Δ cast_info+0.10
Δ role_type-0.20
Δ join ①+0.05
Δ join ②-0.15
pg_log = ln(1000) ≈ 6.908 log_pred ≈ 6.908 - 0.30 + 0.10 - 0.20 + 0.05 - 0.15 + Δglobal ≈ 6.428 → cardinality ≈ 620

这个例子的意义只是说明“每个表、每条 join 都能单独产生修正”，不是模型已经得到的数字。

维度当前 `attn` / `attn_pair`显式 join 图 + edge-aware attention
通信对象所有 token 全连接只沿真实 join 边
是否知道 join 拓扑不知道；`attn_pair` 只知道 fanout 配对知道表节点、边、方向和多跳路径
信息源全部来自同一条 SQL 的 token仍来自同一条 SQL，但按表/边重组织；不声称新增数据库状态
输出全局池化 → MLP表项 + join 项 + 全局残差
多表外推靠 MLP 自己学加法结构上按 Σ 组合，更适合表数增加
主要风险加参数但不加信息建图覆盖率、参数更多、仍可能过拟合源库
05 / RISKS

可能失败的地方，先写在前面

这不是“必然更好”的方案。现有证据已经排除了几种更简单的解释，图模型仍有四个硬风险。

建图覆盖率

子查询、别名、自连接、非等值 join、复合键都可能解析失败。目标库 SQL 必须先做只读覆盖率统计。

信息饱和

现有特征已包含被引用列的直方图和 fanout；图结构主要是重新组织同一批信息，增益不一定大。

数据量与容量

PRICE 约 1.95 亿样本，我们约 300 万；图模型参数更多，可能更容易记住 23 个源库。

库身份捷径

106 号探针 0.9858：现有表示已强烈编码“这是哪个库”。图节点/边可能放大这个捷径，需 GRL/CORAL 或探针诊断。

最小验证顺序（全部只读或源验证）

  1. 只读建图SQL AST → 节点/边；统计 4 个目标库与 3 个源验证库的解析覆盖率；不训练。
  2. ERM 源验证3 seeds、固定 4000 updates、last.pt；先比较 `sum` vs `graph`，不上 FOMAML。
  3. 只看 4+ 表桶当前差距主要在 multi-join 尾部；如果 4+ 桶没有 ≥10% 改善，直接 kill。
  4. 过门才上 FOMAMLFOMAML 只改训练目标，不改图结构；仍用 source validation 选型。
预注册门槛建议：源验证 macro mean log-Q95 < 2.617780；3/3 seed 方向一致；4+ 表桶改善 ≥10%；逐库/逐 K 不超过 `sum` 的 1.10×；目标库全程零读取。
06 / CODE

代码落点：一个模型分支，不动训练主循环

图结构应该作为新的 `arch` 分支接进 `SetEstimator`，而不是重写 FOMAML/ERM。

新文件

`query_graph.py`

SQL AST → `node_features`、`edge_index`、`edge_features`、`node_mask`。先做纯只读构造与测试。

模型

`model.py`

新增 `arch="graph"`、`GraphLayer`（edge-aware message passing）、因子化头。保留 `sum` 作为默认。

数据

`data.py`

batch 增加 graph 字段；节点/边 padding 与 mask；mapping 覆盖率校验。

node_feats: [B, T, d_node] # T = 表数 edge_index: [B, 2, E] # E = join 数 edge_feats: [B, E, d_edge] # hist 40 + fanout 40 + type node_mask: [B, T] edge_mask: [B, E]
07 / SUMMARY

一句话总结

Takeaway

当前模型：所有 token 都能互相看，池化后由一个 MLP 学全局残差。

图模型：表是节点，join 是边；attention 只沿边发生，输出按表项和 join 项分解。

它解决的不是“attention 不够强”，而是“attention 没有拓扑先验”。

说明页只描述设计与假设，不是实验结果。图中数字为示意，不代表模型已经取得的精度。实际实现前应先完成 SQL 图构造覆盖率检查与源验证 3 seed 对照；目标库不参与训练、调参或 checkpoint 选择。
