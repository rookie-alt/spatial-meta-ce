00结论摘要

一句话结论

在双方都没训练过的四个目标库上，我们的 K=0 尾部精度 4/4 全部落后于 PRICE （PRICE/我们 中位 0.561，即我们差约 1.8 倍）； 在 PRICE 训练过、我们训练过 23 个的 26 个源库上，我们 22/26 优于 PRICE （中位 1.184，其中 3 个落在 seed 噪声带内、 19 个稳赢）。

这个反转本身就是结论：赢面来自拟合，不是漂移。对传统优化器 PG，两组都好于它 （目标库 3/4 赢，源库 24/26 赢）。

三条支撑事实：

  • 差距落在排序一致性上，不是校准、也不是过度收缩：目标库 4/4 的与真值相关性低于 PRICE （dCorr 中位 +0.0212），源库只有 3/26 落后；两组的偏差中位 （+0.024 / -0.026）都贴近零，预测离散度我们反而更大。
  • 主指标口径下差距更大：4+ 表桶上 PRICE/我们 中位 0.322（整库口径是 0.561）。
  • 样本量必须随数字一起报：IMDB 只有 521 条唯一查询，其 Q95 由约 26 条决定， 4+ 桶仅 118 条、由约 6 条决定。
  • 同赛道的直接对手基本只有 PRICE：整库留出零样本这一设定，可查到的公开工作里 只有 PRICE（已发表）与一篇已撤回的预印本；CardOOD、GRASP、AHCE/DACE 的指标与我们恒等， 但设定都不是整库零样本（详见 08 与文献的同口径对照）。

第一次看到 seed、K=0、Q95 这类词时， 可直接查末尾的 11 名词表。

01使用的方案

评估协议（本次全部数字的共同口径）

三个估计量在同一批唯一查询上并列：我们是冻结的 seed42 ERM-sum baseline （baseline/last.pt， sha256 563ec1596b1a…，last.pt，未做任何 checkpoint 选择）、 PRICE 是官方提供的权重（model_params.pth， sha256 4f889c4df269…，原生 log1p(card)+1 解码到 log(card)）、PG 是缓存里的原始优化器估计。

评估是 K=0 零样本，对每个库的全部唯一查询做单次全量推理，无 support。 指标是标准 unique-query Q95：预测与真值的对数误差取 95 分位再取指数， 精确预测记 1.0，越小越好。目标库用 maxima [12, 14, 8, 10]、 源库用 [12, 12, 7, 10]，两组布局差异已实测为相对 9.1e-07。

上表「PRICE Table 2」列是 imdb 那一行的 Q95（即我们第 08 节那张表里的同一列）。三篇原文自报的 PostgreSQL 分别是 797（NeuroCard）/ 817（DeepDB）/ 6,955（FLAT），而 PRICE 表里是 49.44；NeuroCard 自己论文报 5.91，PRICE 表里是 14.25。这些差异都不来自方法实现的优劣。

统计单元：PRICE 论文的 Q-ERROR 是在每条查询分解出的子查询上算的，不是整条查询（LLM-CE 论文脚注 3 明确写出这一点，并说明它自己改用整条查询重算）。我们的 all-rows 面板与 PRICE 同单元——证据是我们的 PG 列在四个库上逐位复现 PRICE 发表的 Q95；而 DeepDB / FLAT / NeuroCard 各自论文用的是整条查询单元。

一个常被引错的数：BIRD 全文不含 'cardinality' 一词（grep 命中 0 次），也没有 Q-ERROR：它报的是执行准确率 EX 与 VES。所以「BIRD 上的 PG Q95」这个东西并不存在，任何这样写的对比都缺乏文献依据。

NeuroCard、FLAT、DeepDB、Naru、MSCN、PRICE 全部使用同一个 q-error 公式 max(真值/估计, 估计/真值)，且都把真值与估计的下界取 1——与我们 Q95 的定义恒等。所以跨论文比 Q95 的大小是可行的，但前提是统计单元与负载版本一致。

这次调研的结论

  1. 整库留出零样本这一设定，在可查到的公开工作里只有三条线：PRICE（已发表）、2502.14350（已撤回）、以及本项目。也就是说我们面对的直接同行对手基本只有 PRICE 一个。
  2. CardOOD、GRASP、AHCE/DACE 三篇的指标口径与我们恒等（AHCE 的 Q95 定义未核实），但设定都不是整库零样本：前两者是同库内留出，AHCE 是同库 workload 漂移且依赖目标库直方图。它们不与我们在同一根轴上竞争，不能用来证明我们更强或更弱。
  3. GRASP 与 CardOOD 共同支持一个与我们相同的直觉：不访问目标库数据也能取得强结果，且鲁棒训练能压低尾部；这为「零样本 + 少样本适应」这条路线提供了同行证据。
  4. 我们仍然缺的那一项（PRICE、GRASP、CardOOD 都报了，我们没有）是端到端时间。PRICE 报 5.3-14.1 ms/查询推理与三库 E2E 最优，GRASP 报 CEB 上 135%、PG 176%，CardOOD 报 DSB 上 0.634 倍 PG。我们只报误差，没有报时间——这是汇报时必须主动说清的缺口。
  5. 同一个方法在不同论文里的数可以差好几倍（PostgreSQL 从 817 到 49.44，NeuroCard 从 5.91 到 14.25），差在统计单元与负载版本，不在实现优劣。我们的数只与 PRICE 那张表可比，且这一点已由 PG 列逐位复现证明。

口径说明：本项目的 Q95 = exp(percentile(|max(log_pred,0) - log(max(true,1))|, 95))，与 max(ĉ/c, c/ĉ) 在倍数空间取 95 分位恒等（两侧下取 1）。下表 metric_identical_to_ours = true 的论文，其 Q95 可与我们同列比较，无需换算。

09边界与不可声称

  • 可写对传统估计器 PG，目标库 3/4 赢、源库 24/26 赢； IMDB 上 Q50 首次优于 PG（2.037 vs 2.278）。
  • 可写源分布内的拟合可超过给定的 PRICE 参考（22/26， 其中 19 个稳赢、3 个打平）。
  • 不可写“我们优于 PRICE”——对等漂移场景是 0/4。
  • 不可写“22/26 优于 PRICE”而不带拟合限定——PRICE 全见过这些库。
  • 不可写“四目标库完整验收”——IMDB 只有 K=0，没有 few-shot 行。
  • 不可写把源库的 4+ 桶值与 102 号的桶值混排——两份证据文件的 Q95 定义不同（倍数空间 vs 对数空间），IMDB 4+ 桶的 PG 列相差 2.68%。
  • 不可写“目标库全胜 PG”——stats 是 0.904，属于打平而非胜负。
  • 不可写“我们优于 CardOOD / GRASP / AHCE”——它们的指标口径与我们恒等， 但留出方式不是整库零样本，没有可比对象；也不把已撤回的 2502.14350 当作证据引用。

其它限定：所有 ours 侧数字为单 seed（42），标记 needs_evidence；94 号实测 seed 间标准差 6.28pp，大于本表多数效应量； 推理耗时不等于数据库端到端加速；本页只测精度。

全文出现的缩写与术语　「通俗解释」是给不熟悉这个方向的人看的，「本报告中的含义」是该词在这次实验里的具体所指。
名词通俗解释本报告中的含义
训练与模型
seed（随机种子）训练随机性的起点。同一个配置配同一个 seed，每次跑出的模型都一样；换 seed 等于换一次参数初始化、换一次数据排列顺序，得到一个不同的模型。我们只用 seed 42 这一个模型。94 号实测换 seed 会让同一方法的 Q95 波动约 ±6.28 个百分点，所以差距小于它的结论只能算打平。
checkpoint（检查点）训练过程中的模型存档文件。固定取最后一次训练的存档 last.pt，从不在目标库上比较多个存档再挑最好的——那等于按目标测试选模型。
ERM经验风险最小化，即普通训练：每条查询独立地学一个回归。我们四个臂之一。
FOMAML元学习：先学一个「遇到新库能快速适应的初始化」，再做少量调整。本课题的核心方法，与 ERM 对照。
set / sum（臂名后缀）模型内部的两种聚合结构：一个把特征当集合处理，一个做求和聚合。四个臂是 FOMAML-set / ERM-set / FOMAML-sum / ERM-sum；结构在源验证库上选定，主线用 sum。
arm（臂）一组完整的对照配置（架构 + 训练方式 + seed）。14 号主表的每一列就是一个臂。
maximaPRICE 的输入特征布局长度参数，决定特征向量怎么切分。目标库用 [12,14,8,10]、源库用 [12,12,7,10]；换它会改变特征被读到的位置，但实测数值差异相对仅 9.1e-07。
评估口径
K适应时给模型看的示例查询条数。K=0 表示一条都不给（零样本）；K=5/10/20/50/100 是少样本档位。
support（支撑查询）用来做适应的示例查询。K>0 的部分才有 support。
zero-shot / 零样本不看任何示例，直接对目标库预测。目标库侧的全部数字都是 K=0。
few-shot（少样本）给少量示例后快速适应一个新库。本课题的场景；14 号给了 K=0…100 的完整轨迹。
unique-query（唯一查询）去重后的不同查询；同一条 SQL 重复出现只算一次。所有表都是「全部唯一查询」口径，例如 IMDB 521 条、stats 2,603 条。
population（全体口径）对该库所有唯一查询一次性全跑，不抽样。与 episode 均值是两套口径，报告里不可互换。
episode（适应回合）一次支撑样本抽样加一次评估。14 号主表是 3 seed × 5 次抽样的均值。
指标
Q95误差的 95 分位，越小越好。本报告定义为 exp(percentile(|预测对数 − 真值对数|, 95))，精确预测记 1.0。四个目标库、26 个源库、4+ 桶全部用它。
log 空间（对数空间）用对数表示误差：差 10 倍变成差 1。所有偏差、相关、离散度统计都在对数空间计算。
Q50 / Q90 / Q99误差的 50 / 90 / 99 分位。Q50 是中位数，Q95 是尾部——两者可以给出相反结论，所以要分开看。
4+ 表桶参与 join 的表数 ≥ 4 的那批查询。项目主指标 macro_four_plus_q95 所在的粒度；IMDB 该桶只有 118 条，Q95 由约 6 条决定。
macro（宏平均）先算每个库自己的指标，再对库取平均。与把所有查询混在一起算不同。
corr（与真值的相关性）预测值高低与真值高低的一致程度，衡量「排序准不准」。解释误差结构的关键量；它高不代表 Q95 就好。
dCorrcorr(PRICE) − corr(我们)。正值表示 PRICE 的排序更准；目标库 4/4 为正，源库中位为负。
bias_med（中位偏差）预测与真值偏差的中位数（对数空间）。接近 0 表示既不普遍高估也不普遍低估。
over%（高估占比）预测偏大的查询所占比例。50% 附近表示居中；IMDB 是 27.6%，即 72% 的查询被低估。
离散度（std）预测值的分散程度。若远小于真值的分散度，说明模型过度收缩——报告里 22/30 库我们比 PRICE 更散，这条被否证。
库与曝光
源训练库我们训练过的库。23 个。
源验证库只用来选方案（模型结构、适应策略）、没参与训练的库。chembl / legalacts / telstra 三个。
目标库我们和 PRICE 都没训练过的库。imdb / stats / genome / ergastf1 四个；唯一对等的漂移比较点，且不参与任何选择。
拟合诊断 vs 漂移证据在模型见过的分布上比，叫拟合诊断；在双方都没见过的库上比，才叫漂移证据。26 源库表是前者，4 目标库表是后者——两者的结论方向相反，所以必须分开讲。
PG（PostgreSQL）数据库自带优化器给出的行数估计。本项目的传统基线，不是学习出来的模型。
PRICE另一个基数估计方法的官方预训练权重。非严格训练条件匹配的强参考（它在全部 26 个源库上都训练过）。
证据
噪声带（±6.28pp）由 seed 间标准差界定的「打平区间」。落在带内的差异读作打平，报告里灰色标记。
needs_evidence证据强度标记，提示该结论需要更多实验支撑。全报告 ours 侧数字都带这个标记，因为只有单 seed。
sha256文件内容指纹，内容变一点就完全不同。用于证明引用的到底是哪一份证据文件。
文献与指标口径
Q-ERRORPRICE 论文里用的误差指标：预测值与真值差了几倍，取两者的较大倍数。与我们的 Q95 是同一个量（已数值验证，相对差 2.9e-15），所以第 08 节能把我们的数直接放进论文的表里。
p-error计划代价之比：把估计值当真值去算查询代价，与用真实基数算的代价相比差多少。另一种指标，2502.14350 顺带报了；它和 Q95 不在同一个数轴上，不能互相换算或混排。
all-rows（全部行）不去重，把工作负载里每一条查询结果行都算进指标。PRICE 论文用的是这个口径；本项目主指标用 unique-query。第 08 节另算了一份 all-rows 专门用来对表。
E2E（端到端）把估计器接进真实数据库跑完整条查询链，测总耗时。PRICE、GRASP、CardOOD 都报了，我们一个都没测——这是本报告明确列出的证据缺口。
Visual Genome一个图像标注数据库。PRICE 论文与 2502.14350 论文里叫 Visual Genome 的，就是本项目与 PRICE 缓存里的 genome。
join 模板多表连接的结构骨架（表与连接条件固定、参数可变）。GRASP 留出的是模板而非数据库——它的「泛化」是同库内换骨架，与本项目的跨库漂移不是一回事。
covariate shift（协变量偏移）测试数据的分布相对训练数据变了，但预测目标没变。CardOOD 的 OOD 指的是这个，纯查询工作负载漂移，不含整库留出。
Group DRO一种鲁棒训练法：给训练集里最难的那部分加权，逼模型照顾最差情况。CardOOD 里在 forest 上把 Q95 从 102.48 压到 39.57；与本项目的少样本适应是两回事，但思路可借鉴。
