03 / Attempt ledger

之前做过的尝试，按证据排成一条线。

这不是“功能清单”，而是一份决策账本：每次只改变有限因素，先冻结协议，再看源验证结果； 失败后不自动扩大 seed、K 或参数网格。可按尝试类型过滤。

05 / What is still missing

不足不是一句“还需努力”。

当前短板分成五类：精度差距、验证选择偏差、统计强度、数据完整性，以及因果解释能力。 每一项都决定论文里能写什么、不能写什么。

尾部精度仍明显落后

critical

同评估器零样本 6 项指标中 PRICE 胜 5 项；本项目只赢 Genome Q50。 历史尾部差距约 1.6–6.7×，因此只能写“更小、更省资源、 覆盖少样本区间”，不能写“整体优于 PRICE”。

三个源验证库的选型偏差

critical

chembl / legalacts / telstra 已参与多轮策略、损失、算子和 checkpoint 选择。 继续在这三库上换 seed 或 K，不能自动增加泛化证据。当前留出协议是修复这一步， 但 21 库训练与 23 库训练仍存在数据减少与迁移收益的混杂。

单 seed / 单 K 的证据强度有限

important

Meta65 与低维 Gate 1 都是源侧单 seed、单 K 的筛选； 即使某个方向看起来更好，也只能支持后续协议，不能单独证明跨库泛化或统计显著。

IMDB 与 P2 仍有硬缺口

blocked

IMDB finetune 统计缺少必要列，完整四目标库验收未完成； P2 的真实 SQL 类型语义、同版本源表/来源链和真实选择率计数仍 blocked。 不能补随机特征、借 test 数据或静默过滤失败查询。

误差机制仍是描述性结论

unknown

S1–S3、S7 已说明“旧尾被新高尾替换”“legalacts 持久尾部退化” “seen/unseen 没有统一落差”，但这些结果不足以区分优化可达性、 表示信息缺失和跨库条件差异。不能包装成已经找到因果根因。

工程证据仍有观测边界

residual

外部 VRAM 周期采样为 0 不等于没用 GPU，cell 内 PyTorch 证据才是主证据； 部分低维屏幕没有 OS 级 I/O tracer，target_read=false 来自受限数据路径、 产物扫描和身份扫描的综合认证，不是逐系统调用追踪。

06 / Next decision

下一步不是继续调参，而是完成一次有信息量的验证。

当前路线已经冻结，应在明确授权后执行一次 50-cell 源库留出矩阵， 再由独立验证器认证结果。无论结果好坏，都应直接进入论文归因， 而不是看到不利结果就重开网格。

  1. 先完成正式留出矩阵

    一次性执行 50 cells；若 GPU 忙、输入 SHA 变化或任一预检失败，保持 blocked，不重试、不换卡。

  2. 独立认证后只写描述性结论

    分开报告 3 个源验证库与 2 个留出库；首轮不生成 selected_arm，不把 5 库合成候选 macro。

  3. 把结果写回论文与进度

    验证库与留出库同向改善、分化或同时退化，都保留完整分母和失败项；不做结果后改写协议。

  4. 新方法必须另立协议

    如果留出结果不支持继续，优先收束负结果与局限；不再在同样三个库上追加 K/seed/λ 网格。

写论文时的安全表述

  • 可以写：轻量模型以约 1/107 参数量实现同量级典型查询精度，并覆盖 PRICE 未报告的少样本区间。
  • 可以写：本项目建立了严格的目标隔离、源侧选型、unique-query 口径、配对和独立复算流程。
  • 不能写：整体精度优于 PRICE、尾部 Q95 已解决、源验证选择偏差已被消除。
  • 不能写：当前 Meta65 或 ridge 已经证明表示不足；它们只证明在特定协议下候选不成立。
“工程完成”不等于“研究成功”；
负结果只要证据完整，也是论文资产。
