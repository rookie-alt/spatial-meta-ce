join 树、变量消除与 160 桶

树由「连接键谓词」构造，与 SQL 里 JOIN 的书写顺序无关。
一棵树 = 一张因子图：表是因子，连接键是变量。

01链：4 表 3 谓词

SELECT count(*) FROM a
  JOIN b ON a.id    = b.a_id
  JOIN c ON b.id    = c.b_id
  JOIN d ON c.id    = d.c_id
WHERE a.x = 5
谓词数必须 = 表数 − 1，且并查集检测无环，否则 analyze_tree 抛 not_a_tree。环、自连接、外连接、子查询、GROUP BY / ORDER BY / LIMIT 全部拒绝。

02消元：从叶子往根发消息

任选 A 为根，D→C→B→A 依次把「不朝父节点走的变量」求和消掉：

m_DC(v₃) = f_D(v₃)
m_CB(v₂) = Σ_v₃  f_C(v₂, v₃) · m_DC(v₃)
m_BA(v₁) = Σ_v₂  f_B(v₁, v₂) · m_CB(v₂)
join    = Σ_v₁  f_A(v₁) · m_BA(v₁)

展开后就是

Σ_v₁ Σ_v₂ Σ_v₃  f_A(v₁)·f_B(v₁,v₂)·f_C(v₂,v₃)·f_D(v₃)

—— 每个键组合的贡献等于各表在该键上的行数相乘，没有任何近似。所以 C_cond 与 workload true_card 的最大相对偏差是 0.0。

图是树 → 每个变量只被消一次、每条消息只传一次，复杂度 O(表数 × 域大小)，不需要 junction tree。

03星与「重复中表列」：并查集在这里起作用

SELECT count(*) FROM mid
  JOIN t1 ON mid.k = t1.id
  JOIN t2 ON mid.k = t2.id
  JOIN t3 ON mid.k = t3.id
同一个变量意味着 mid 的因子退化成一维 f_mid(v₁)； 二维联合 F_joint 与独立假设 F_indep 在这种形态上构造性相等—— 条件化在这一形态上可证明没有任何收益。不合并的话，会把它当成两个独立变量相乘，结果偏小几十倍。

另外两种被 analyze_tree 直接拒绝的形态：环（谓词数 > 表数 − 1，例如 4 表两两相连）与自连接（同一张表出现两次）。

04为什么必须「共享边界」

05两种因子构造，同一套消元代码

路径因子怎么来近似实测 Q95（600 条 4–7 表）
C_cond 过滤后表的精确分组计数（含二维/三维联合） 无 1.000，与 true_card 偏差 0.0
C_uncond 未过滤单列边缘 × 过滤选择率，表内列间独立 独立性 + 过滤独立 9.537（精确键）
C_uncond_binned 同上，但边缘压成 160 桶共享边界 再加桶内均匀 9.736

118 号模型的锚点就是最后一行：log C_struct(q) = log C_uncond_binned，再让一个小网络学残差 g_θ(x)。

只用三件原料：行数（含非 NULL 键行数）、单列键频率（160 桶）、过滤选择率。 目标库评估时，C_struct 只读由基表数据算出的摘要，不读真实基数。
