# STATS 误差诊断与优化调研

日期：2026-11-18。范围：A1-PG 4k/24k 的既有 K=0 预测、原始结果 JSON、当前实现与公开论文/代码。状态：描述性诊断与下一轮建议；没有启动新训练、模型推理或少样本适应。

结果档案已提交 `d8e4a35`，并推送分支 `experiment/a1-pg-head-input-20261116` 至 Gitee/GitHub；[127 号](127-24k剂量实验结果.md) 及 [23 份原始 JSON](../reports/official-split-20261117/evidence/README.md) 为数值来源。关联实现仍在任务 worktree，尚未交付；长步数声明范围与模型模块哈希覆盖问题已登记，不以结果提交冒充可执行复现代码。

## 1. 判断与优先级

**还有改进机会，但没有证据证明换一个损失、增加步数或加门控就能解决 STATS。** 已观察到的退化是跨库迁移不均衡：24k 明显改善 genome/imdb，STATS 则两个配对运行变差、一个改善。应先在真正未参与该轮训练的源验证库上定位迁移差异，再改变读出结构或训练监督。

建议顺序：恢复源侧跨库验证 → 比较一个 PRICE 式读出变体 → 在教师来源合规的前提下考虑蒸馏；继续加训、残差裁剪、目标库专属回退和损失网格不列为优先项。下述建议都是待检验假设，没有承诺收益幅度。

## 2. 现有差距到底在哪里

论文对照使用 all-rows，三次训练各自计算 Q95 后取算术均值；它与 unique-query 是不同总体。

| 数据库 | A1-PG 24k all-rows Q95 | PRICE | PG | 我们 / PRICE |
|---|---:|---:|---:|---:|
| imdb | 16.48 | 16.15 | 49.44 | 1.02 |
| stats | 167.44 | 35.55 | 73.35 | 4.71 |
| genome | 45.95 | 15.67 | 383.09 | 2.93 |
| ergastf1 | 24.55 | 14.58 | 27.48 | 1.68 |

IMDB 已接近 PRICE。其余两库虽然优于 PG，尾部仍有差距；STATS 是唯一 Q95 劣于 PG 的库。以下逐查询诊断统一使用 **STATS 全部 2,603 个 unique-query，K=0**，不把上表的 all-rows 数字放进逐查询分组。

| 训练运行 | STATS Q95（4k） | STATS Q95（24k） | log-Q95 差值（24k−4k） |
|---|---:|---:|---:|
| seed42 | 89.93 | 265.60 | +1.0829 |
| seed43 | 243.15 | 182.75 | −0.2855 |
| seed44 | 101.15 | 118.05 | +0.1545 |

4k 三次 Q95 算术均值为 144.75，24k 为 188.80；PG 为 75.65，PRICE 为 39.52。**144.75 不是 seed42 的结果**，也不能用均值的一行解释所有运行。尚未生成 4k all-rows 面板，不声称该口径下的加训效果已经测得。

独立复算 [recompute.py](../reports/stats-diagnosis-20261118/recompute.py) 直接读取 8 份原预测 CSV，核对全部四库的查询身份、真值和服务器 SHA256，STATS 指标与正式摘要一致。详细数值见 [prediction-audit.json](../reports/stats-diagnosis-20261118/prediction-audit.json)。没有重跑模型，也没有为本次复算新增预测变换；沿用原协议 `max(log_prediction,0)`。

## 3. 确认的现象，以及不能从中推出的原因

### 3.1 残差修正会伤害一部分本来准确的 PG 估计

在 24k 的 2,603 条查询中，A1-PG 比 PG 更差的查询比例分别为 **62.39% / 53.78% / 53.55%**。修正幅度 `mean(abs(ours_log−pg_log))` 如下：

| 运行 | 4k | 24k |
|---|---:|---:|
| seed42 | 0.3881 | 0.9685 |
| seed43 | 0.7738 | 0.7128 |
| seed44 | 0.4775 | 0.4981 |

seed42 放大明显，seed43 缩小，seed44 近似不变。因此只能说修正与退化在部分运行中一起发生，不能说“所有运行都因残差越来越大而失败”。

PG 绝对 log 误差 ≤0.5 的查询共有 1,089 条，占 41.84%；A1-PG 24k 在其中改坏的比例为 78.97% / 64.28% / 64.46%。**PRICE 在同一组也改坏 77.13%**，同时取得更低的全体 Q95。因此这组比例本身不能证明残差锚有缺陷，也不能据此直接选择回退策略。该分组依赖真实标签，部署时无法直接知道“PG 本来准确”。

方向也有两侧：seed42 在全部 2,603 条中被改坏的 1,624 条里，PG 已高估且继续上推为 668 条，PG 已低估且继续下推为 513 条，朝真值移动但越过头后误差更大为 427 条。这些计数属于全体查询，不能当作上一段 1,089 条 PG 准确子集的分解。它不支持仅增加或减少一个全局偏置来修复所有查询。

### 3.2 STATS 有复杂相关性，但不能把一般特点当成本次因果证据

[STATS-CEB 原论文](https://arxiv.org/html/2109.05877v3) 描述了偏斜、列间相关性、多对多连接及复杂过滤条件。这些解释了为什么该基准有挑战，但 PRICE 在同一输入与评估总体上表现更好，说明“STATS 本来难”不足以解释我们的额外差距。

缓存结构统计显示，STATS 中 `n_filter_cols≥5` 的查询为 **890/2603=34.19%**；26 个源库的完整 unique-query 池为 **187375/1279218=14.65%**，各库占比等权平均为 **15.12%**。见 [structure-audit.json](../reports/stats-diagnosis-20261118/structure-audit.json)。这是过滤列 token 数分布右移的描述，不是实际训练呈现分布，也不表示源侧没有类似查询；例如部分源库的该比例高于 STATS。

`counts[:,0]` 是 join-hist token 数，`counts[:,2]` 才是表数；二者都不能直接当作 SQL join 边数或 join graph 拓扑。因此不根据这些计数断言“连接结构超出训练分布”或“连接更简单”。结构导出未在本次审计中逐字节认证全部缓存来源，结论强度低于已绑定的预测 CSV。

### 3.3 真正的实现差异在网络与训练，输入分辨率相同

| 项目 | 当前 A1-PG | 官方 PRICE |
|---|---|---|
| 特征维度 | 40 / 40 / 4 / 43 | 40 / 40 / 4 / 43 |
| 编码器 | 64 维、2 层、4 heads | 256 维、6 层、8 heads |
| 参数量 | 294,033 | 10,709,330 |
| 读出 | CLS、log1p(counts)、表规模、PG → 残差 MLP；输出 PG+r | CLS 与 counts → 中间标量；再与 PG、表规模融合 |
| 训练标签与 PG 变换 | log(max(card,1)) | log(card+1)+1 |
| 损失 | SmoothL1 | MSE |
| 抽样/更新 | 数据库等概率的 sealed episodes；ERM 合并 support/query | 全训练行 shuffle；官方推荐 batch 15000 |
| 优化配置 | 固定 outer_lr=3e-4，无 dropout | 官方推荐 lr=2.85e-5、weight decay、StepLR、dropout |

代码依据：[当前模型](../spatial_meta_ce/price_model.py)、[训练器](../spatial_meta_ce/train.py)、[官方模型](https://github.com/StCarmen/PRICE/blob/1ca9000197dbb92ecb9e71af22f47560f78cb4d5/model/encoder.py)、[官方预训练](https://github.com/StCarmen/PRICE/blob/1ca9000197dbb92ecb9e71af22f47560f78cb4d5/pretrain.py)、[官方参数](https://github.com/StCarmen/PRICE/blob/1ca9000197dbb92ecb9e71af22f47560f78cb4d5/utils/model/args.py)。官方推荐训练 batch 的资源需求不能套到单卡 3090。论文描述与当前官方代码的预训练库数量文字曾有版本差异，本报告以实际实现及本次冻结的 26/4 为准。

`max_counts=[12,12,7,10]` 是 token padding 数量上限，**不表示 12/12/7/10 个直方图桶**。当前 A1-PG 已把 PG 输入残差头，不能再把“给 head 加 PG”当作新方案。

加性形式 `PG+r(x,PG)` 在函数形式上可表示 `f(x,PG)`，不能仅由输出加法断言表达力不足。SmoothL1 在 beta=1、|error|>1 时对预测的导数为 `sign(error)`，MSE 为 `2*error`；前者仍惩罚大误差，只是梯度增幅不同。是否与这次尾部差距相关，必须做单因素实验。ERM 的 support/query 合并是普通监督批次，模型没有依赖 support 的上下文输入，故 K=0 不构成“缺上下文”的解释。

## 4. 不重复已经失败的改法

- [15 号](15-离线精度提升首轮实验计划.md) 和 [23 号汇总](23-当前任务清单与源侧改进总结.md)：旧 sum 模型的 MSE、增宽、去 PG 输出锚、复杂查询加权均没有合格候选；S6 尾部混合虽平均改善，逐库保护失败。
- [94 号](94-P1精度杠杆实现与源侧筛查.md)：log-L1、pinball、门控组合未产生合格候选。该记录不能推广为所有模型上的数学不可能，但足以降低原样重试的优先级。
- 不用 STATS 标签选择残差裁剪常数、收缩系数、回退阈值或 checkpoint。诊断代理本轮曾越界做了 45 个裁剪/收缩变换点，并据此提出幅度上限建议；根代理发现后要求停止，该扫描及其建议全部排除，未改正式预测、协议、模型或主表，不作为任何优化收益证据。

## 5. 值得做的三个后续工作

### A. 先恢复源侧跨库验证，并补一组有区分力的诊断

官方 26 库 checkpoint 已训练 chembl/legalacts/telstra；再在这三库推理只能测训练域拟合，不能称跨库验证。要筛新策略，可恢复原 **23 训练 + 3 源验证** 口径，从头训练同条件 baseline 与候选；容量只从训练库确定，最终超参数固定后另做官方 26 库重训。已有 26 库权重不能直接充当该留出实验的独立初始化。

先在源侧固定报告 `mean(abs(residual))`、全体/不同过滤列 token 数/不同表数的 Q50 和 Q95、PG 比较、训练损失与验证曲线。若训练域和跨库验证都差，优先容量/拟合；若训练域好而跨库差，优先迁移与监督。描述性分组不能替代完整库级端点，也不能据某个目标库的分组比例设计采样权重。

成本需区分：缓存计数/已有 CSV 复算只需 CPU；对 26 源库重新推理并非“零成本的已有结果读取”，要先估总查询量、确定设备、时间和输出预算。当前没有运行这组源侧推理。

### B. 第一项实现候选：只替换读出，检验 PRICE 的结构归纳偏置

保留当前 64 维两阶段 encoder、特征、PG 输入、加性输出锚、损失、训练计划及预算，只将直接 residual MLP 替为“query 标量读出 → 与 PG 和表规模再次融合”的 PRICE 式两段读出。这样只检验读出结构，避免同时扩大 encoder、换损失和去锚。

这是一个结构假设，不是声称 PG 信息缺失或两段读出必然更强。参数增量、初始 PG 等价性和输入梯度需先用合成输入核对，再在 A 的源侧划分做配对比较。观察主指标改善同时检查每个源库保护，失败就停止该变体，不自动扩大网格。

成本低于重训完整 PRICE，但仍须实际计量；既有 4k 官方 26 库运行约 1,000 秒/次只作量级参照，不能当新 23/3 实验的保证。新的 4k 筛查也不能直接解决 24k 端点的问题；若源侧有候选，再按新预注册预算确认长训练端点。

### C. 第二项候选：教师蒸馏，优先保护轻量部署目标

[知识蒸馏](https://arxiv.org/abs/1503.02531) 提供了把大模型知识迁移到小模型的通用方法。可保持 A1-PG 推理结构，用**真实源训练标签为主监督**，另加对 PRICE 解码后 log 预测的辅助一致性项；教师预测必须标为辅助信号，不替代或伪装成真值。权重与预算在源侧先冻结，不在 STATS 上挑。

该思路属于通用方法迁移，本轮未找到足以证明“PRICE→A1-PG 在 STATS 有收益”的直接论文或实验。教师会出错，蒸馏也可能只转移偏差，因此需要同预算的真值监督对照。

严格 23/3 验证要求教师也没有训练过三源验证库；官方 26 库教师不满足，不能把它用于该实验后仍宣称严格源库留出。可选择另外训练合规教师，或把官方教师路线明确作为独立的 26 库探索性蒸馏，不与严格留出结果混称。教师推理与训练成本都必须计入。

如果两项候选在源侧均无益，再考虑仅把 encoder 扩到中等规模并保持其他项不变；旧 sum 增宽无效不能证明 PRICE encoder 无效，但也不提供必然成功的依据。

## 6. 外部调研中筛掉的路线

- [PRICE 原论文](https://arxiv.org/html/2406.01027) 与官方代码支持核对特征、两阶段模型及训练配方；它们没有证明单独切换 MSE 或去 residual 就能修复本模型。
- [LiteCard / Breadbox](https://arxiv.org/html/2510.03386) 使用按子查询图模式组织的局部轻量学习，说明结构条件化值得关注。但它依赖在线真实执行反馈，不是当前 K=0 的直接替换；本项目旧 ridge 适应也已有失败记录，不能据这篇论文直接复活。
- [Robust Cardinality](https://doi.org/10.1186/s13173-021-00115-9) 讨论不确定性与回退。它不构成我们当前模型或目标库上的安全保证，项目已有门控负结果，暂不作为首选。
- [Simple PRICE / 训练数据简化论文](https://arxiv.org/abs/2502.14350) 的当前页面明确为 withdrawn，原因是实验数据质量疑虑。其性能和训练时间结论不用于本项目优化论证。
