## 1. 为什么必须先跑学习曲线

「训练不充分」目前**既未被证实，也未被充分排除**，而现有最直接的证据方向是负的：

| 证据 | 结果 | 局限 |
|---|---|---|
| P0 固定预算续训（[10 号](10-训练量假设.md) §7） | 4000→20000 步，源侧 4+ 表零样本 Q95 的 long/short 几何均值 **1.634**，7 个桶全部 >1，判定 `no_overall_improvement` | 单 seed、仅 ERM-sum、只到 6.3 遍（PRICE 150 遍）、比较计划为抽样不是全 population |
| volB 加量（[10 号](10-训练量假设.md) §4–5） | 同时改 `meta_batch 4→16`、`query_size 64→256`，1600 步停下，源侧三库全部变差 | 多因素混杂，不是纯训练量对照 |
| 训练 loss vs 验证 | 20000 步内训练 loss 0.344→0.237 持续下降，验证 2.65–2.85 横盘 | 说明优化在拟合，但不说明尾部泛化 |

同时必须承认 seed 噪声：源侧 macro 的 seed 间标准差实测 **6.28 pp**（[94 号](94-P1精度杠杆实现与源侧筛查.md)）。P0 的 best 差异只有 0.022 log 单位，**远小于该噪声**。因此任何单 seed 的「加量有效/无效」都不能作为结论，学习曲线的作用是先看形状，而不是先下判断。

## 2. 阶段 A：学习曲线协议（冻结）

### 2.1 目的

回答一个可观察的问题：**在源验证库全 population 上，4+ 表 Q95 随训练步数是否仍在下行，还是已经饱和/过拟合。** 这是决定阶段 B 是否值得投入 26 库重训的唯一依据。

### 2.2 训练设置

| 项 | 值 | 与 P0 基线的关系 |
|---|---|---|
| 配置 | `configs/erm_sum_curve_100k.json` | 新建 |
| 方法 | ERM | 相同 |
| 模型 | width 64 / arch sum / layers 2 / heads 4 / use_pg true | 相同 |
| `steps` | 100,000 | 4000→100000 |
| `meta_batch` | 4 | **相同（不重复 volB 的多因素错误）** |
| `query_size` | 64 | **相同** |
| `outer_lr` | 3e-4 恒定 | 相同 |
| `inner_steps` | 0 | 与 `p1-screen` 主表基线一致（ERM 训练不调用 `adapt()`） |
| `validate_every` | 2,000 | 100→2000（省验证开销） |
| `validation_runs` | 5 | 相同 |
| `validation_seed` | 1729 | 相同 |
| `patience` | 201 | 50 次验证内不触发早停，保证跑满 |
| `snapshot_steps` | 4000 / 8000 / 20000 / 40000 / 60000 / 100000 | 新增 |
| seed | 42 | 单 seed 曲线，不用于跨 seed 结论 |

`snapshot_steps` 是本次新增的最小机制（[train.py](/Users/williamlin/Downloads/13/spatial-meta-ce/spatial_meta_ce/train.py)）：在指定 step 额外写一份自洽 checkpoint（含 optimizer/RNG/history），不改变 `last.pt`/`best.pt` 语义，不传该键时行为与原来逐位相同。

### 2.3 评估设置（只读，不训练）

脚本：`scripts/learning_curve_eval.py`。

- **support 与 query 来自同一份 sealed plan**（`plans.build_source_eval_plan`，`support_seed=2026`），所有 step 的 checkpoint 看到完全相同的 support 查询和完全相同的 query population，因此 rung 之间是**配对比较**，差异不可能来自重抽样。
- 数据库：`chembl / legalacts / telstra`。目标库在打开任何缓存前即拒绝。
- 指标：**unique-query Q50 / Q95**（`metrics.q_values` 标准口径），另加 **≥4 表桶 Q95**（按 `offsets[:,2]` 表数分组，桶内 pooled）。
- K：0（主口径）+ 5（`--blocks 1`，单块 support）。
- **适应预算与训练配置刻意分离**：训练配置 `inner_steps: 0`（与 `p1-screen` 主表基线一致，ERM 训练不调用 `adapt()`），但评估固定用 `inner_steps: 5 / lr 1e-3 / scope all`，与 [configs/evaluation.json](configs/evaluation.json) 的主评估协议一致。脚本**不再**从 checkpoint 的 `training_signature` 读取适应预算：否则 `adapt(steps=0)` 会原样返回参数，K=5 将静默等于 K=0。传入 `--ks` 含正值而 `--inner-steps 0` 时脚本直接报错。

### 2.4 预注册判定规则（在训练启动前冻结）

以 `40000` 与 `100000` 两个 rung 的**源侧 4+ 表 Q95** 比较，聚合方式**沿用 [10 号](10-训练量假设.md) §7 的 P0 规则**：先逐库算 `Q95(long)/Q95(short)`，再对三个库取几何均值。这样 chembl 的绝对量级（Q95 数十到上百）不会压过 legalacts/telstra（个位数到十位数）。

| 判定 | 条件 | 后续动作 |
|---|---|---|
| `still_improving` | 几何均值比值 ≤ 0.95，且三个库的库内比值均 ≤ 1.0 | 进入阶段 B，预算取曲线拐点 |
| `saturated` | `0.95 < 比值 < 1.05` | **不进入阶段 B**；改查 lr schedule / loss / 容量 |
| `worse` | `比值 ≥ 1.05` | **不进入阶段 B**；确认训练量不是杠杆，写负结果 |

「三个库的库内比值均 ≤ 1.0」这一条与 `still_improving` 并列，属**强阳性**门槛；若几何均值 ≤ 0.95 但某个库变差，判为**部分改善**，仍需逐库报告，不自动进入阶段 B。

补充（不改变主判定）：

- 同时报告 `20000` 与 `40000` 的比值，用于定位拐点。
- 若 `100000` 的 K=0 全库 Q95 与 `40000` 相差 <3%（小于 seed 噪声 6.28pp 的一半），即使 4+ 桶满足 `still_improving`，也标注为**弱证据**，需要至少 2 个 seed 才能进入 B。
- 若 4+ 表 Q95 与全库 Q95 方向相反，以 **4+ 表 Q95 为主判据**（与 P0 及项目主口径一致），全库 Q95 作为辅助报告。已实测源验证库表数分布：chembl 2–7、legalacts 2–4、telstra 2–5，**4+ 桶是真子集**（chembl 33,947 / legalacts 9,298 / telstra 20,311 行），不是全库等价物。

### 2.5 已知局限（必须随结论一起报告）

1. **单 seed**，不构成跨 seed 证据；seed 噪声 6.28 pp 量级。
2. `snapshot_steps` 的 rung 与 `last.pt` 是同一条优化轨迹上的点，**不是独立训练**；可以回答「继续训练是否有用」，不能回答「不同预算独立训练是否有用」。
3. 100k 步 ≈ 31.6 遍（按 26 库唯一查询 1,279,218 计）、35.8 遍（按 23 库 1,129,714 计），**仍远低于 PRICE 的 150 遍**。本阶段只判断「是否还在下降」，不判断「是否达到 PRICE 规模」。
4. 验证集仍是 chembl/legalacts/telstra，与历史实验一致；这不是目标库证据。

### 2.6 资源预算（按实测吞吐推算，非承诺）

实测基准：ERM 纯训练 0.345 s/step（`fomaml-joint-source-smoke` A_erm 臂，200 updates / 68.96 s）；验证 75 episodes ≈ 81 s/次。

| 项 | 值 |
|---|---|
| 训练 | 100,000 × 0.345 s ≈ **9.6 h** |
| 验证 | 50 次 × 81 s ≈ **1.1 h** |
| 合计 | ≈ **10.7 h，1 张 GPU** |
| 输出 | 6 份 snapshot + last/best ≈ 4 MB |
| 磁盘 | `/gly` 余 6.2 T |

## 3. 阶段 B：26 库预注册方案（不做选择）

### 3.1 划分

| 角色 | 库 | 用途 |
|---|---|---|
| 训练 | 全部 26 个源库（现 23 + `chembl/legalacts/telstra`） | 更新参数 |
| 选择 | **无** | 不早停、不选 `best.pt`、不调超参 |
| 目标 | `imdb / stats / genome / ergastf1` | 只在训练完成后评估一次 |

**预注册规则**：

- 预算由阶段 A 的拐点确定，**在看到任何目标库数字之前**写入配置并计算 SHA256。
- 输出取 **`last.pt`**，`selection: none`。训练过程中不做任何基于验证的模型选择。
- 目标库只在最后做一次 K=0（`imdb` 仅 K=0，因服务器无 `finetune/imdb`）与 K=5/20（其余三库）评估。
- 不做中途 checkpoint 择优；不因目标结果回改预算或超参。

### 3.2 为什么这个划分在论文上更强

- PRICE 提供的权重在**全部 26 个源库**上训练（[evaluate.py:270](/Users/williamlin/Downloads/13/spatial-meta-ce/spatial_meta_ce/evaluate.py:270) 已记录该事实）。26/0/4 后两侧训练库覆盖对齐，消除了「PRICE 见 26、我们见 23」的不对称。
- 代价：`chembl/legalacts/telstra` 从「未见源验证库」变成 in-sample，**不能再作为空间漂移证据**。[102 号](102-IMDB与源库广度对照结果.md) §4 那类「23 见过 / 3 没见过」的对比必须在论文中改写口径。
- 因此 26 库方案的价值是**更公平的对照**，不是「更多漂移证据」。不能把 26 库结果写成跨库泛化提升。

### 7.4 判定（按 §2.4 预注册规则）

主判据：`40000 → 100000` 的源侧 **4+ 表 Q95** 逐库比值几何均值。

| 聚合 | 几何均值比值 | 逐库比值 |
|---|---:|---|
| 4+ 表 Q95（主判据） | **1.0080** | chembl 0.915 / legalacts 1.058 / telstra 1.058 |
| 全库 Q95（辅助） | 1.1270 | chembl 0.967 / legalacts 1.324 / telstra 1.118 |

`0.95 < 1.0080 < 1.05` → **判定 `saturated`**；且「三个库比值均 ≤ 1.0」不满足（legalacts、telstra 都变差），不是部分改善。

**必须补一句更强的表述**：主判据的 `saturated` 只描述 40k→100k 的平台期；把基线放在 4000 步看，整条曲线是**「越训越差」**。`worse` 的证据来自 4000→20000 的 +67.6%、以及 20000→100000 仅恢复到峰值以下 22%，以及训练内验证的 +13.28%。

### 7.5 对阶段 B 的影响（按 §4 停止条件）

**阶段 B 不启动。** §4 明文规定：A 判为 `saturated` 或 `worse` 时，阶段 B 不启动，改为排查 lr schedule / loss / 模型容量。本轮证据支持后者：

- **训练量不是杠杆**：100k 步、六个 rung 的单 seed 直接证据，与 [10 号](10-训练量假设.md) §7 的 4000→20000 负结果方向一致。
- **26 库扩展在当前配方下没有意义**：把训练库从 23 增到 26，无法抵消「多训 25 倍反而劣化 30.6%」这一量级的问题；此时投入 26/0/4 重训大概率复现同样劣化。
- **应改方向**：恒定 lr 3e-4 无 schedule、SmoothL1 在 log 空间、13 万参数的小容量。这三条尚未筛过。

### 7.6 局限（必须随结论报告）

1. **单 seed**。seed 间 macro 标准差实测 6.28 pp（[94 号](94-P1精度杠杆实现与源侧筛查.md)）；本轮 4000→100000 的全库 Q95 劣化 +33.7%、4+ 桶 4000→20000 劣化 +67.6%，均远大于该噪声。方向可信，具体百分比不可精确引用。
2. snapshot rung 是同一条优化轨迹上的点，不是独立训练；可回答「继续训练是否有用」，不可回答「不同预算独立训练是否有用」。
3. 100k 步 ≈ 31.6 遍（26 库口径），仍远低于 PRICE 的 150 遍。但 1.3 遍（4000 步）已是最优点，**「没训够」在当前配方下被否定**；不能排除「换配方后需要更多训练」。
4. 评估用 sealed support 的第一块（`--blocks 1`），不是五次独立 support 抽样；K=5 不进入本次判定（主判据为 K=0）。
5. 本轮只改 `steps` 与 `validate_every`；`meta_batch`、`query_size`、lr、loss、模型结构均与 `p1-screen` 基线一致。结论只适用于这套配方。
