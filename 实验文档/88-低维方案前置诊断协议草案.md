## 3. D1：low4 退化形状分解

### 3.1 数据

直接用 50 份已归档 NPZ 中 validation 三库的 `head3` 与 `none` 配对
（`log_pred / true / n_tables / query_hash`），不重新前向，不重新适应。
`low4 = (n_tables >= 4) and (true < 100)`，与 84/81 号同口径。

### 3.2 统计量（逐库，五 run 分别算，再报中位数与极差）

1. **分位数谱**：low4 Q50/Q75/Q90/Q95/Q99，none 与 head3 各一组。
2. **配对 log-Q 变化**：`Δ_i = |head3_logerr_i| − |none_logerr_i|`（负为改善）。
   报告改善/恶化查询比例、`Δ` 的中位数与 P90、P99。
3. **集中度**：low4 群体中恶化幅度最大的 1% 查询贡献了多少总 log-Q 增量。
   分母口径写清：`分母 = sum(Δ_i for Δ_i > 0)`；不截断、不近似。
4. **分桶**：按 `n_tables`（4、5、6+）、low4 内真实基数三分位、
   `|PG − true| / true` 三分位，各桶报改善/恶化比例与 Q95 ratio。
5. **support 代表性**：每个 `run` 的 100 条 support 中 low4 的条数分布；
   计算 support low4 比例与该库整体 low4 比例之差。

### 3.3 预注册判据（执行前冻结，不得事后调整）

- **D1-A「集中型」**：恶化最大的 1% 查询贡献 ≥ 40% 的 low4 总增量。
  → 说明是少数极端样本驱动，**低维约束不是对症药**；应优先审计这些查询的
    可观测特征（表数、PG 偏差、直方图缺失），而非增加或减少适应参数。
- **D1-B「弥散型」**：同一指标 < 25%，且 low4 改善/恶化比例介于 40%–60%。
  → 说明是系统性漂移，低维参数化方向有讨论价值，D2 的结论才具有决定性。
- **D1-C「中间带」**：其余情况。
  → 判为 `inconclusive`；不据此支持或否决 86 号，由 D2 单独决定。
- 附加硬条件：若任一库每 run 的 low4 条数中位数 < 100，该库只报描述性统计，
  不参与 D1-A/B 判定（小样本分位数不可靠）。已核对 81 号 `cells.json`：
  validation 三库每 run 的 low4 中位数为 chembl 2,450 / legalacts 3,011 /
  telstra 5,517，全部远超该门槛，不需要降级为描述性统计。

## 4. D2：四维子空间可表达性上界

### 4.1 定义

对同一数据库、同一 `run`、同一批 query：

```text
Δ_i = f_head3(q_i) − f_none(q_i)                 # 已有预测差，真值不参与
h_i = head_features(q_i) under none              # 64 维，末层 Linear 之前
```

用最小二乘拟合 `Δ ≈ Z c`，其中 `Z = [h, 1]`（65 维），得到 `R²_linear`。
注意：`Δ` 本身由 65 个 head 参数线性生成，`R²_linear` 应接近 1，
**它是自洽性检查，不是研究结论**。

关键量是秩约束下的解释率，定义必须写成可直接实现的形式：

```text
# 1. 全秩最小二乘解（自洽性检查用）
c_lin = argmin_c ||Δ − Z c||²,           R²_lin = 1 − ||Δ − Z c_lin||² / ||Δ||²

# 2. 秩 4 截断：取 Z 的前 4 个左奇异向量 U4（65×4），在 U4 张成的空间里重拟合
U, S, Vt = svd(Z)                        # Z 为 n×65，n 为 query 数
U4 = U[:, :4]                            # 只保留秩 4 子空间
a4 = argmin_a ||Δ − (U4 a)||² = U4ᵀ Δ
R²_4 = 1 − ||Δ − U4 U4ᵀ Δ||² / ||Δ||²
```

要点：`U4` 取自 **Z 的列空间**（与 head 特征对齐），不是取自 `Δ` 自身——
取 `Δ` 自己的主方向会把所有能量都收进秩 4，得到虚高的解释率。实现时用
`numpy.linalg.svd` 的完整分解，不依赖随机化或近似 SVD。`R²_4` 是 86 号 L 臂在
"重新训练后仍未超出 head3 表达能力"这一保守假设下的上界估计；真实 L 臂可因
theta 重训而超出，但该数值给出先验强弱。

**已知偏差，需在结论中如实标注**：D2 只用 `none` 算子的 `h`，而 86 号 L 臂的
`u` 是在支撑集适应后的特征上起作用。若 head3 的预测变化主要来自 `h` 在
适应前后的差异，`R²_4` 会低估；反之若主要来自末层权重变化，则高估。因此 D2 的
判定只作**否决用**（低值不可做），不作**通过用**（高值仍不足以证明 L 会成功）。

### 4.2 计算流程（CPU，不需要 GPU）

1. 加载 checkpoint（CPU，`map_location='cpu'`），确认 `model.config`、`next_step=4000`、`seed=42`。
2. 逐库逐 run：取该 run 的 query 全集（与 plan 一致），分块前向 `none` 与 `head3`
   两个算子，**复用** `scripts/meta65_joint_runner.py` 的 `operator_params` 与
   `certified_batch`，不重写适应逻辑。
3. 同时抓取 `none` 算子下的 `head_features`（`SetEstimator.head_features` 已由
   低维分支重构提供）。
4. 在 float64 下求解上述最小二乘与 SVD 截断。
5. **一致性门槛**：先核对重算的 `f_none / f_head3` 与归档 NPZ 的逐元素差
   小于实现时实测后冻结的容差（目标 `< 1e-6`）。不通过即停止——说明 checkpoint、
   plan 或代码闭包不一致，不能进入 D2 结论。

### 4.3 预注册判据

| `R²_4`（三库五 run 中位数） | 判定 | 对 86 号的含义（否决用，非通过用） |
| --- | --- | --- |
| ≥ 0.80 | `not_blocked` | 四维约束不是已观测的瓶颈；**不构成** 86 号会成功的证据 |
| 0.50 – 0.80 | `partial` | 86 号可讨论，但第 1 条门槛的预期须下调，或先重设门槛 |
| < 0.50 | `subspace_insufficient` | 4 维无法表达已有适应变化；86 号在现门槛下大概率 `no_development_candidate` |
| 三库极差 > 0.30 | `unstable` | 库间差异过大，不足以支持任何全局结论 |

为避免高估，判据只用于**否决**：`< 0.50` 或 `unstable` 足以暂停 86 号；
`≥ 0.80` 只能说明"没被这一项挡住"，不能替代实现契约、预检与正式筛选。

`R²_linear` 仅作自洽检查：若 < 0.95，先查实现错误（特征抓取位置、算子配对、
query 顺序），不进入判据。
