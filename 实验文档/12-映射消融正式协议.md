# P1 映射消融：正式协议（冻结）

> 状态：**9 次正式训练和源验证库端点分析已完成（2026-10-04）**。冻结协议未改；结果见第 9 节。
> 日期：2026-10-04。分支 `feat/mapping-model-gpu-smoke`。

## 1. 研究问题与主张边界

**问题**：join 列→表、filter 列→表的映射信息，对跨库基数估计的误差有多大贡献？

- **主比较**：真实映射 vs 边际保持打乱映射。两者同一 `sum_map` 架构、同参数量、同采样流，差异只在关联信息本身。
- **辅助比较**：真实映射 vs 原 `sum`。`sum_map` 参数更多（含 `mapping_fusion`/`fanout_fusion`），**容量混杂无法排除**，只能作为次要参考。
- **不可主张**：本消融完成后仍不能主张优于 PRICE；目标库在本阶段完全不参与。

## 3. 端点度量

`scripts/mapping_ablation_endpoint.py`，**源验证库 only**（chembl / legalacts / telstra）：

1. 每库取全部 unique query（按 `query_hash` 去重），**零样本**前向；
2. 按 join 表数分桶；**主指标 = 4+ 表桶的 q-error Q95**（口径同 `metrics.q_values`）；
3. 三库等权 macro 平均（每库全量 unique 的 Q95 再取算术平均）。**注意口径区别**：`train.validate` 的早停指标是 75 个 episode 的 `log_q95` 在 log 空间取均值，与本端点的线性 q-error Q95 不是同一个量，两数不可互引；`arch_select` 的 `zero_shot_by_tables`、`error_by_joins` 的分表桶口径与本端点的 q-error 公式一致，但它们只覆盖 plan 采样子集或按精确表数分桶，不是这里的全量 4+ 表池化；
4. 配对比较按 `query_hash` 逐条对齐，输出 `q95_ratio`、`left_better_fraction`、`mean_log_q_delta`；
5. **原样上报** sidecar 风险，覆盖**全部 26 个源库**（23 训练 + 3 验证）：每库 `sql_flags.multiple_filters`、`changed_fraction`、`unchangeable_rows`、`random_unchanged_rows`。打乱后未改变的比例直接限制对照强度——训练库若大量未改变，shuffled 臂在训练期仍持有真实关联，会稀释差异，因此不得只报验证库、不得平滑或省略。

## 4. 配对不变量（runner 逐项核验，违反即停）

同 seed 的三臂必须共享：`sample_plan_digest`、`sample_plan_episodes`、`counts`、`validation_plan_hash`、`optimizer_steps`、**`manifest_hashes`（全部源库 cache content hash，防止 9 次跨小时串行期间缓存被重建导致三臂输入漂移）**。
`true` 与 `shuffled` 必须共享：`initialization_hash`、`parameters`、sidecar 的 `manifest_hash`+`jsonl_hash`。
所有臂不得触及目标库。逐臂记录 device / GPU UUID / 峰值显存 / 耗时 / checkpoint SHA256。

`load_run_config` 锁定完整冻结集：`model` 全字段、`mapping.root`+`mode`、以及 `method/steps/meta_batch/accumulation/outer_lr/inner_lr/inner_steps/adapt_scope/support_sizes/query_size/loss/validate_every/validation_runs/validation_seed/patience/min_delta/data_config`；dry-run 也会读入并校验三个配置。运行时启用 `torch.use_deterministic_algorithms(True)` 并关闭 TF32，以便同臂复跑可复现、数值噪声不掩盖小效应。

## 6. 实施期间发现并修复的问题

`StorePool` 默认 `max_open=4`，而映射 store 每次打开要完整解析 sidecar。实测：26 库同时常驻一次性 92.7 秒 / 2.99 GB，**单库重开 3.54 秒**。23 个训练库均匀随机采样下 LRU 几乎每步命中失败，4000 步 × 3 臂 × 3 seed 仅 sidecar 重解析就需上百小时。已在 `train()` 中改为 `max_open=len(sources)`（每个源库只打开一次），并以 `tests/test_mapping_ablation.py::ResidentStoreTests` 固化。

## 11. 冻结预测偏移分解（2026-10-04）

证据：[drift_decomposition_verified.json](results/p1-mapping-ablation-20261004/drift_decomposition_verified.json)、[checkpoint_bias.json](results/p1-mapping-ablation-20261004/checkpoint_bias.json)；可复现脚本 [drift_analysis.py](results/p1-mapping-ablation-20261004/drift_analysis.py)。服务器同一诊断目录，统计完成于 `2026-10-04T13:44:31.626278+00:00`。只用已有27份源验证预测与九个冻结checkpoint；未重训正式模型、未适应、未执行新模型前向、未读目标库。

### 定义与验证

配对4+表unique query上令 `d = log_pred_B - log_pred_A`、`c = mean(d)`，共同平移平方变化量占比为 `c² / mean(d²)`；**不是Q95波动解释比例或因果贡献率**。仿射分析为 `log_pred_B ≈ a + b*log_pred_A` 的OLS，另报去平移RMS和排序Spearman。原始预测不变，未生成校准后的指标。
