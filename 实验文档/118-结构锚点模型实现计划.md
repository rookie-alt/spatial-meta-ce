## 1. 已经测出来的三件事

全部在**三个源库**（hepatitis / carcinogenesis / basketball）上，用**原始 CSV 的精确键值**，没有用目标库。

### 1.1 两表（G1a，600 条）

| 估计器 | median | Q95 |
|---|---:|---:|
| PG | 1.264 | 6.335 |
| `C_uncond`（无 PG，单列边缘） | 1.067 | 2.481 |
| `C_cond`（精确 oracle） | 1.000 | 1.000 |

### 1.2 三表（G2a，400 条）

| 估计器 | median | Q95 |
|---|---:|---:|
| PG | 1.418 | 7.557 |
| `U_indep`（无 PG，单列边缘） | 1.230 | 3.317 |
| `F_indep`（过滤后边缘） | 1.068 | 1.686 |
| `F_joint`（精确 oracle） | 1.000 | 1.000 |

### 1.3 四到七表（`tree_identity.py`，600 条）

| 估计器 | median | Q95 | mean | max |
|---|---:|---:|---:|---:|
| PG | 2.000 | 11.800 | 93.83 | 53,522 |
| `C_uncond` | **1.502** | **9.537** | **9.50** | 1,847 |
| `C_cond` | 1.000 | 1.000 | 1.000 | 1.0 |

逐表数（Q95）：4 表 10.84→9.56、5 表 12.93→7.40、6 表 30.46→15.97、7 表 4.60→3.06。**每一档都赢。**

`C_cond` 在 600 条上与 workload `true_card` 的最大相对偏差 **0.0** —— 树形组装是精确的。

### 1.4 这三件事合起来说明什么

- **锚点值得做**：零参数、不用 PG、不训练的结构化估计器，在 2–7 表上**全部赢 PG**。
- **但不是靠条件信息**：G1a/G2a 测的是「条件化/相关性值多少」，结论是"尾部有、中位没有"。真正起作用的是**结构恒等式本身**。
- **`C_uncond` 只用一维键边缘 + 行数** —— 这正是 PRICE 的 `histogram40.pkl` 里已有的东西。

## 2. 目标与验收

### 2.1 最终目标

一个**不使用 PG 估计**、参数量不超过现有 `sum`（132,545）、能在目标库上按项目既有口径评估的模型。

### 2.2 分步验收（每步不过就停，不往下走）

| 步骤 | 验收 |
|---|---|
| ① 摘要 | 能在不读原始表的前提下，从摘要复算出与精确键值**完全一致**的 `C_cond` |
| ② 桶对齐 | 同样的 600 条 4–7 表查询上，`C_uncond_binned` 的 Q95 ≤ **2 ×** 9.537（即 ≤19.07），且仍低于 PG 的 11.800 |
| ③ 锚点接入 | `pg_output_scale=0` 且锚点为 `log C_struct` 时，未训练模型在源验证库上的 Q95 与 `C_uncond` 直接算出的结果逐位一致 |
| ④ 训练 | 三 seed 源验证选型，任一 seed 退化不超过 10%（沿用项目既有门槛） |
| ⑤ 评估 | 四目标库 K=0，三 seed，与 PRICE/PG 同口径 |

## 3. 五步实施

### ① 摘要构建（预计 1 天）

**做什么**：为每张表的每个连接键列建 40 桶计数；为每张表的「多个连接键组合」建联合计数。

**输出**：

```text
artifacts/cache/struct/<db>/
  manifest.json          # schema、源统计哈希、构建参数
  key_hist.npz           # (table, column) -> 40 桶计数
  key_pair.npz           # (table, col_a, col_b) -> 40x40 联合计数
  size.npy               # (table,) 行数、非 NULL 键行数
```

**要点**：

- 只对**join 列**建，不对所有列建。数量级：每库几十个连接列。
- 度数 ≥3 的表需要三维联合 —— 先统计有多少这种表，再决定是建还是降级为独立假设。
- 构建一次，之后只读。

**验收**：从摘要复算 `C_cond` 与精确键值版本逐位一致（这一步还没涉及分桶，只是把精确计数换个存法）。

### ② 桶对齐（预计 1–2 天，**关键难点**）

**问题**：PRICE 的 `histogram40` 是**每张表按自己的分位数**分桶。表 A 的第 7 桶和表 B 的第 7 桶不是同一个键区间，**不能直接相乘**。

**两种做法**：

- **(a) 按 join 边建共享分桶**（FactorJoin 的做法）：对每条连接边，取两侧键值的并集，在这个并集上定 40 个边界，两侧各自映射进去。这是正确的做法，但需要**同时看到两侧的数据**。
- **(b) 按主外键侧定边界**：如果一侧是主键（唯一），用主键的域定边界，外键侧按值映射进去。更省，但要求能识别主外键。

**必须先量的一件事**：用 (a) 做出来的 `C_uncond_binned`，相对精确键值的 Q95 退化多少。**这是 §6 的第一个停止条件。**

**验收**：见 §2.2 第 ② 行。

### ③ 锚点接入（预计 0.5 天）

**改哪里**：

| 文件 | 改什么 |
|---|---|
| `spatial_meta_ce/data.py` | `batch_samples` 增加 `struct_log` 字段；**升 `TRANSFORM_VERSION`**（旧 checkpoint 全部不兼容） |
| `spatial_meta_ce/model.py` | `output_anchor` 增加 `anchor="struct"` 分支，返回 `struct_log` 而不是 `pg_log * pg_output_scale` |
| `spatial_meta_ce/features.py` | 构建 `struct_log` 需要在预处理时算好并缓存 |
| 新文件 `spatial_meta_ce/struct_summary.py` | 摘要的读取与 `C_struct` 计算 |

**要点**：

- `pg_output_scale` 保持存在（旧的对照臂还要用），但新 arch 默认 `use_pg=False`。
- 末层仍然零初始化 → **未训练的新模型 ≡ 闭式结构估计器**，这让 ③ 的验收可以做逐位比对。

**验收**：见 §2.2 第 ③ 行。

### ④ 训练（预计 0.5 天 + GPU）

**先做 ERM，不做 FOMAML。**

理由：现有证据是 FOMAML 臂不占优（104 号 §7.13），先确认「新锚点 + ERM」能不能站住，再谈元学习。

**配置**：沿用 `configs/meta_sum_4k.json` 的形状，4000 updates，三 seed（42/43/44），只在 23 个训练库上训练，checkpoint 只在三源验证库上选。

**参数量目标**：≤ 132,545。

### ⑤ 评估（预计 0.5 天）

四目标库 K=0，三 seed，unique-query Q95，`maxima` 沿用 108 号的 `[12,14,8,10]`。

**必须同时报**：PG、PRICE、现有 `sum`（PG 锚点，作为旧基线）、新模型。四列并排才说明问题。

## 4. 需要先定的决策点

新窗口开工前必须先确认，否则会返工：

1. **度数 ≥3 的表怎么办**：建三维联合（存储 ×40），还是退化成独立假设（精度可能掉）？
2. **桶数**：沿用 40，还是加大？（40 是 PRICE 的约定，改了就没法复用它的缓存）
3. **`C_uncond` 还是 `C_indep`**：§1 用的是未过滤边缘（`C_uncond`）。要不要试过滤后边缘（`C_indep`）？G1a/G2a 显示后者在尾部更好，但需要摘要支持过滤列。
4. **修正头 θ 做不做**：先只有结构锚点（零参数）也能出结果；θ 可以后加。

## 6. 停止条件（出现即停，不要硬撑）

1. **桶对齐后 Q95 超过 19.07**（精确版的 2 倍）→ 摘要方案不可行，重新设计或放弃。
2. **新模型训练后在源验证库上不如 `C_uncond` 直接算的结果** → 修正头在拖后腿，先去掉 θ 只用锚点。
3. **目标库三 seed 全部不如 PG** → 结构锚点在目标库上不成立，回到分析型论文。
4. 同一命令重试 3 次仍失败 → 停下汇报。

## 8. 已知的坑（今天踩过的）

1. **选择率只能算一次**：`C_uncond` 用未过滤边缘 × 选择率；若同时用过滤后边缘再加选择率，会双重计入。今天这个 bug 让 Q95 从 9.5 变成 4,014。
2. **重复中表列**：两表连中表同一列时，两个连接谓词是**同一个变量**，必须并查集合并，否则二维联合会算成非对角。
3. **NULL 键**：频次只在非 NULL 键上统计，分母用「连接总体」而不是整表行数，否则无过滤时也会算出虚假的条件化效应。
4. **`carcinogenesis` 的三表查询 100% 是重复中表列** —— 任何排除该形态的口径都会让这个库归零。
5. **服务器 SSH 会限速**：连续多次连接可能被拒，用 ControlMaster 复用单条连接（`-o ControlMaster=yes -o ControlPath=/tmp/cm -o ControlPersist=3600`）。
