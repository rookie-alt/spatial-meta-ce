## 1. 为什么有 G2

G1a 判定为 `conditional_signal_not_observed`，但同一批数据给出三条不能忽略的事实：

1. **Q95 通过且幅度大**：整体 Q95 从 2.481 降到 1.000（比值 0.403）；选择率 <1e-3 的桶从 13.047 降到 1.000。
2. **median 条件在基线接近 1.0 时不可达**：`C_uncond` 的 median 已是 1.067，q-error 下界是 1.0。要求比值 ≤0.5 需要基线 median ≥2.0（这是可达的**必要条件**）。实际差 1.87 倍。
3. **测的不是新架构要用的场景**：G1 只覆盖两表；三表及以上占三个库的 93.9% / 70.3% / 85.9%。

G1 回答的是「两表、过滤不落在连接键上时条件频数值多少」。多表组装是另一件事，不能外推。

## 2. 研究问题

三表在「连通、无环、恰好两条边」的限制下只有一种无向拓扑：路径。记中表为 T2，两条边分别为 `T1.a = T2.a` 与 `T2.b = T3.b`。

**本协议要求 `a ≠ b`**（中表的两个连接键必须是不同列）。若两条边引用同一列，二维联合退化为对角线，单列频数即可表达，不能用来论证二维结构；这类查询标 `unsupported(same_middle_key)` 并单独计数。

把误差来源拆成两个可交叉控制的估计器因素，各自判定：

- **Q1（条件化）**：在**固定「中表两键独立」假设**的前提下，把边缘换成过滤后的精确值，是否更准？
- **Q2（键间相关性）**：在**固定「边缘为过滤后精确值」**的前提下，把中表两键从独立改为真实联合，是否更准？

两者构成 2×2 四格，见 §5。每个差值都只在一个因素上变化、另一个固定，属于**估计器构造**上的单因素对比；这不等于两种误差来源统计上正交，差值也不代表「更准」——准不准由配对 q-error 判。

## 5. 估计器：2×2 四格

记号。所有频次只统计**非 NULL 键**。三张表各有一个「连接总体」，估计器只在这个总体上定义：

```text
M1 = T1 中 a 非 NULL 的行数
M2 = T2 中 a 与 b 同时非 NULL 的行数
M3 = T3 中 b 非 NULL 的行数
原表行数 |T_i| 另记，只用于描述，不进入任何估计器。

未过滤：c1(a)、c2(a,b)、c2a(a)=Σ_b c2(a,b)、c2b(b)=Σ_a c2(a,b)、c3(b)
        c2 只在 M2 上统计，两个边缘都由同一个 c2 求和得到
过滤后：φ1(a)、φ2(a,b)、φ2a(a)、φ2b(b)、φ3(b)、m2=Σφ2
选择率：s_i = m_i / M_i
```

**零值分支（必须在任何除法之前判）**：

- 定义 `m1 = Σ_a φ1(a)`、`m3 = Σ_b φ3(b)`；三个选择率的分母与分子分别是 `M_i` 与 `m_i`。
- 任一 `M_i = 0` → 四个估计器全部定义为 0，且 `s_i` 记为**未定义**；这类查询统一归入 `zero_join_population` 特殊桶（见 §6），不得参与按选择率分桶。
- 否则（全部 `M_i > 0`），若任一 `m_i = 0` → 四个估计器全部定义为 0；此时 `s_i = 0` 是合法数值，正常分桶。
- 其余情况才执行下表公式。

这些查询**保留**在整体指标与零基数报告里，不删除、不跳过。注意：三表均非空但没有匹配键**不属于**上述分支——此时 `M_i > 0`、独立近似仍可能给出非零估计。

| 格 | 边缘 | 中表键 | 定义 |
|---|---|---|---|
| `U_indep` | 未过滤 | 独立 | `(s1·s2·s3 / M2) · (Σ_a c1(a)c2a(a)) · (Σ_b c2b(b)c3(b))` |
| `U_joint` | 未过滤 | 联合 | `s1·s2·s3 · Σ_{a,b} c1(a)·c2(a,b)·c3(b)` |
| `F_indep` | 过滤后 | 独立 | `(1 / m2) · (Σ_a φ1(a)φ2a(a)) · (Σ_b φ2b(b)φ3(b))` |
| `F_joint` | 过滤后 | 联合 | `Σ_{a,b} φ1(a)·φ2(a,b)·φ3(b)` |

两条恒等式可验证，且是**构造性**的，不是近似：

- 无过滤时 `U_joint` = 精确连接数；`U_indep` 一般**不等于**精确值（独立性假设的代价）。
- `F_joint` **恒等于**精确连接数（它就是 oracle）。

> v1 的错误：v1 的 `C_uncond` 用的正是 `U_indep`，却写成「键分布与键间关系全部沿用未过滤假设」。它对中表两键也做了独立假设。反例：中表两行 `(A,X)`、`(B,Y)`，左表 10 行 `A`，右表 10 行 `X`，无过滤时真值是 100，`U_indep` 给 50。**v2 把这一格明确命名为 `U_indep`，并补上 `U_joint` 这一格。**

派生量：

```text
Q1 条件化效应 = F_indep − U_indep
Q2 相关性效应 = F_joint − F_indep
交互项        = (F_joint − F_indep) − (U_joint − U_indep)
```

三者都在同一条查询上逐条计算，报告配对分布，不只报聚合。

**实现注意**：`F_joint` 需要 T2 的二维键联合计数，这是 G1 没有的数据结构，也是新架构里「边表」的原型。G2 只报告**未压缩** oracle 的键对数、字节数与峰值内存；压缩后的精度与成本属 G2b。

## 6. 指标与冻结口径

**主真值**：快照上以独立实现的流式/分块计数得到的 `exact`。workload 的 `true_card` **只作来源校验**（门槛 1b），不参与主指标。

**主 q-error**：`exp(|log max(est,1) − log max(true,1)|)`，与 `metrics.py:q_values` 同口径。零基数单独报告：`true=0` 与 `est=0` 的计数、零/非零误判数、原始计数相等的比例；q-error 为 1 **不代表**原始计数相等。

**主聚合**：先算每个库的 Q95，再三库等权 macro（与项目既有主指标一致）。同时报告 pooled Q95、逐库 Q95、median、max、mean，以及逐查询配对胜负计数。

**分桶**：按 `min(s1,s2,s3)`（桶界在跑之前冻结）、按库、按 `filters_join_key`、按表三元组。任一 `M_i = 0` 的查询选择率未定义，统一归入 `zero_join_population` 特殊桶，**不参与**按选择率分桶，但继续进入整体指标与零基数报告。

**辅助指标的定义**：令 `P(A=a, B=b) = φ2(a,b) / m2`，`X = φ1(A)`，`Y = φ3(B)`，则

```text
F_joint − F_indep = m2 · Cov_P(X, Y)
```

协方差的两个变量是**左右表频数在中表联合分布下的取值**。它衡量独立近似对当前连接数的影响；`F_joint = F_indep` 不能反推两键统计独立（任一侧频数为常数时该差恒为 0）。报告时写「独立近似在多少比例的查询上保持连接数准确」。`m2 = 0` 走零值分支。

## 7. 通过标准（事前冻结）

**只以 Q95 作为通过判据。** 理由必须写明：114 号要求 Q95 与 median 同时 ≤50%；G1a 显示当基线 median 已接近 1.0 时，median 的 50% 条件在算术上不可达（q-error 下界为 1.0）。v1 曾试图引入「基线 median <2.0 时改判不恶化」的条件规则，**该规则已删除**——它在 Q2 上会使 median 条件恒真，等于取消判据。v2 改为：**median 只报告，不判定**。

**必须同时写进结论的限定**：本终点变更**受已观察的 G1a 结果启发**，不是不受先前数据影响的事前选择；它只适用于查看 G2 四格结果之前冻结的本协议，**不追溯改判 G1a**，也不得声称达到 114 号原标准。

**门槛的可解释性提示**：`F_joint` 是 oracle，其 Q95 恒为 1，因此门槛 3b 实际等价于 `Q95(F_indep) ≥ 2`；两条都达到还要求 `Q95(U_indep) ≥ 4`。这些衡量的是「基线误差足够大且改善幅度达标」，不是「相关性信息有没有价值」。

| 门槛 | 内容 |
|---|---|
| 1 正确性 | `F_joint` 与 `exact` 在 100% 抽样上相等；任一不等 → `blocked` |
| 1b 来源校验 | 逐条比较 `exact` 与 workload `true_card`：`true_card = 0` 时要求 `exact = 0`；`true_card > 0` 时计算相对偏差，最大值 ≤5%。超出 → `blocked` 并逐条调查（5% 容差本身不构成语义认证） |
| 2 执行一致性 | 抽样查询重新解析得到的 spec 与冻结 spec **100% 一致**；任一不一致即停止。覆盖不足由分母漏斗单独报告，不在此处放宽 |
| 3a Q1 | `q95(F_indep) ≤ 0.5 · q95(U_indep)` |
| 3b Q2 | `q95(F_joint) ≤ 0.5 · q95(F_indep)` |
| 4 反例 | 见下，两条都必须通过 |

**门槛 4 的两个合成用例**（数字已验算）：

1. **正对照**：中表两世界分别为 `{(A,X),(B,Y)}` 与 `{(A,Y),(B,X)}`；左表频数 `A=10, B=1`，右表频数 `X=10, Y=1`；无过滤。两世界的 `U_indep` 都是 `60.5`，而 `F_joint` 分别是 `101` 与 `20` —— 相同边缘无法区分，联合可以。
2. **负对照**：中表强相关但任一侧频数为常数时，`F_joint` 必须**等于** `F_indep`。这检验实现没有把「相关」误当成「一定改变连接数」。

> v2 曾把「强相关 + 频数恒定 ⇒ `F_joint ≠ F_indep`」写成硬门槛，这是数学上不可能成立的要求，会让正确实现必然 `blocked`。

判定（**只报阈值是否达到，不做架构推论**）：

```text
1 / 1b / 2 / 4 任一未过          → blocked
3a 达到 / 3b 未达到              → q1_threshold_met_only
3a 未达到 / 3b 达到              → q2_threshold_met_only
3a、3b 均达到                    → both_thresholds_met
3a、3b 均未达到                  → neither_threshold_met
样本不足（见 §9）或桶内有效样本 <20 → insufficient_evidence（与上述并列报告）
```

**明确禁止的推论**（写进产物与结论文档）：

- 「3a 过、3b 未过 → 边表不必存」——未达幅度门槛不等于相关性可忽略。
- 「3b 过 → 需要二维联合」——只说明当前边缘独立模型不足，没有比较其他保留相关性的表示（如条件化的一维摘要、分桶联合、低秩近似）。
- 「两者都过 → 新架构值得做」——G2 只测 oracle 的信息量，不含摘要压缩、跨库迁移与训练。**是否进入 G2b 是后续研究决策，G2 不给出存储结构的必要性、充分性或架构 go/no-go。**

## 9. 样本量与稳定性

- **主分位数算法冻结为 `numpy.percentile` 的默认线性插值**（`method="linear"`），与项目 `metrics.py:summarize` 一致。其他算法（lower / higher / nearest / midpoint）**只作敏感性附录**，不参与判定。
- Q95 是顺序统计量，不是求和，因此不存在「前 5% 查询贡献了多少比例」。对零基排序数组 `q_(0), …, q_(n−1)`，令 `h = 0.95(n−1)`、`j = ⌊h⌋`、`k = ⌈h⌉`，报告 `j`、`k`、对应数值与 `query_hash`、以及插值权重 `h − j`；边界（`h` 为整数、`n < 2`）另行说明。
- 每个桶报告有效样本量；每库、每个表三元组分别报告。`insufficient_evidence` 的判定：某库有效样本 <20，或某桶 <20，或三库中任一库无样本。
- **缺库时不得静默改为两库平均**：若任一主库无有效样本，整体 macro 标 `insufficient_evidence`，不给出三库 macro 数值。
- 同一范围内出现 `insufficient_evidence` 时，**不再同时给出确定的阈值通过/未通过结论**；数值照报，判定标为未决。

## 10. 停止与升级规则

- 精确参照与 workload `true_card` 不一致且无法解释、目标库被访问、计划 SHA 变化、OOM：立即停止并保留证据。
- G2 通过只说明三表口径下的信息量，不说明四表以上可组合，也不授权训练。
- `blocked` 时停止本口径，不改查询集重跑。
- 目标库仍不进入任何步骤。

## 11. 已知限制

- 只覆盖三表路径、单键等值内连接、中表两键不同列；四表以上的误差累积未测。
- 三个主库最大 44,822 行；抽样涉及的最大单表在 G1 中是 23,751 行。不外推到其余 23 个源库。

- `F_joint` 是 oracle，需读原表，不代表可部署成本。
