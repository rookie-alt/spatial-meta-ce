## 1. 为什么这个实验的结论强度有限（先写清）

阶段 A 已给出：在 23 库上把步数从 4,000 增到 100,000，源侧 4+ 表 Q95 从 44.08 劣化到 57.55。**训练量不是杠杆。**

本实验改变的是**训练库数量**（23 → 26），不是训练量。它要回答：

> 把 chembl / legalacts / telstra 也纳入训练，模型是否更好？

必须提前承认三点：

1. **不能推翻阶段 A 的结论。** 训练量与训练库数是不同变量。
2. **PRICE 对照会更公平，但不是精度证据。** PRICE 权重在全部 26 库上训练过（[evaluate.py:270](/Users/williamlin/Downloads/13/spatial-meta-ce/spatial_meta_ce/evaluate.py:270)）。26 库后两侧覆盖对齐，消除了历史边界里的一条不对称，但也意味着 chembl/legalacts/telstra **不再是空间漂移证据**。
3. **若结果不优于 23 库，只能说明「在当前配方下加 3 个库无用」**，不能推广成「加库永远无用」。

## 2. 划分与选择信号

| 角色 | 库 | 用途 |
|---|---|---|
| 训练 | 全部 26 个源库 | 梯度更新 |
| 选择 | 每库 **2% 唯一查询**（查询级 holdout） | `best.pt` 选择，不参与梯度 |
| 目标 | `imdb / stats / genome / ergastf1` | 训练完成后评估一次 |

**为什么用查询级 holdout 而不是留出整库**：用户要求 26 库全部参与训练，同时要求「保留最好的结果」。留出整库会退回 23/3；查询级 holdout 同时满足两点，代价是选择信号与训练数据同库（见 §5）。

**holdout 规格（冻结）**：

- `fraction = 0.02`，`seed = 1729`（与历史 `validation_seed` 一致）。
- 切分确定性：`SeedSequence([seed, 20261118, sha256(db)[:8]])`，同配置在任何机器复现同一划分。
- 每库至少 200 条 holdout、至少保留 200 条训练查询，防止小库被切空。
- 实测：26 库合计 **25,584** 条 holdout，每库 594–1,000 条。
- 摘要写入 checkpoint 元数据：`holdout_fraction`、`holdout_seed`、`holdout_digest`、`holdout_queries`。

**验证 episode 只从 holdout 取**：每库 5 个 K × 1 run = 130 episodes，实测 16.0 s/次。

## 5. 已知偏置（必须随结论报告）

1. **选择信号与训练数据同库**。holdout 查询来自参与梯度更新的库，因此 `best.pt` 的选择会有乐观偏置——模型可能记住了该库整体分布，即使没见过这 2% 的具体查询。
   - 偏置方向：**偏高估**。
   - 量级：**未测**。这是本方案最主要的效度威胁。
   - 缓解：holdout 指标**不得**当作泛化性能，只是选择机制；真正的评估只看四个目标库。
2. **2% holdout 略微减少训练数据**（每库 594–1,000 条）。与「26 库全量训练」有微小差异，需披露。
3. **目标评估一次性、四库、K=0 + K=5/20**。`imdb` 仅 K=0（服务器无 `finetune/imdb`）。
4. **不能把 26 库与 23 库结果相减当作「加库净效应」**，因为选择信号不同。严格归因须另做 23 库 + 查询级 holdout 对照臂——本轮不做。

## 6. 预注册判定

与 23 库同预算（20,000 步、seed 42/43/44）比较四目标库 K=0 unique-query Q95：

| 判定 | 条件 |
|---|---|
| `better` | 四库 macro Q95 三 seed 均值低于 23 库同预算，且逐库方向逆转不超过 1 个库 |
| `no_difference` | 差异小于 5%（低于 seed 噪声量级 6.28 pp） |
| `worse` | 高于 23 库同预算超过 5% |

**不做**：目标结果出来后不回改预算、不换 seed、不重新选择 checkpoint。

### 8.2 四目标库 K=0（unique-query Q95）

| 库 | n | seed 42 / 43 / 44 | 本臂均值 | 23 库均值（108 号） | 比值 |

外部对照（同一评估器）：PRICE macro **26.79**、PG macro **524.42**。

### 8.3 判定

按 §6 预注册规则：macro 高于 23 库同预算超过 5% → `worse`。实际 **+34.6%**，远超阈值；逐库方向逆转 2 个库（stats、ergastf1），超过「不超过 1 个库」的门槛。**判定 `worse`。**

三条必须随结论报告的事实：

1. **stats 是灾难级劣化**：81.07 → 229.90（2.84×）。三个 seed 全部差于 23 库任一 seed 的最好值，不是噪声。
2. **genome 的 seed 方差极大**：39.41 / 361.49 / 70.36，样本 SD 约 176，接近均值（157）。该库均值不可单独引用。
3. **imdb 与 genome 的名义改善不可信**：它们与 stats/ergastf1 的劣化同时出现，形态更像训练不稳定导致的随机重排，而非「加库带来泛化」。

### 8.4 与阶段 A 合并的结论

| 变量 | 结果 |
|---|---|
| 训练量 4k → 100k（23 库，[121 号](121-训练量学习曲线与26库预注册方案.md)） | 越训越差：4+ 表 Q95 44.08 → 57.55 |
| 训练库 23 → 26（20k，本轮） | 更差：四库 macro Q95 82.41 → 110.95（+34.6%） |

两个方向都否定了「靠增加数据规模提升精度」的假设。当前配方尚未筛过的候选只剩：恒定 lr 3e-4 无 schedule、SmoothL1 的 log 空间口径、13 万参数的小容量。

### 8.5 归因限制

26 库的 `best.pt` 由**同库查询级 holdout** 选择，23 库基线由**留出整库**选择。因此 +34.6% 混合了「加库」与「换选择信号」两个因素。但 stats 上 2.84 倍的劣化幅度远超这种选择差异可解释的范围，方向结论不受影响；精确归因需另做「23 库 + 查询级 holdout」对照臂，本轮未做。
