# 106 — 表示探针：DB 身份分类器结果

分支 `claude/peaceful-kare-5bb350`。只读实验，**未训练、未适应、未读任何目标库**。

## 1. 要检验的假设

103 号：我们与 PRICE 的 Q95 差距是**排序一致性**（dCorr）差距，且精确跟随训练曝光。
96 号：方向信号库内高度可预测（AUC 0.92–0.98），跨库 LODO 只有 0.38–0.60。

两条合起来指向同一解释：**表征里编码了「我是哪个库」这一捷径特征**。本实验直接测它。

## 2. 方法

| 项 | 取值 |
|---|---|
| 表征 | `SetEstimator._head_input`，即进入输出 MLP 的池化向量，**774 维** |
| checkpoint | `p1-screen-20261020/baseline/last.pt`，seed 42，method `erm`，冻结、显式传入（脚本从不选择） |
| 数据 | 26 个源库 `pretrain` split 的**唯一查询**，每库上限 1,500 条，共 **39,000 行** |
| 分类器 | 多项逻辑回归（numpy 全批梯度下降，400 epoch，lr 0.5，l2 1e-3），标准化只在训练折上拟合 |
| 主统计量 | 5 折交叉验证的 **26 类准确率**（同一批库的查询分折） |
| 负对照 | 打乱库标签后重跑同一流程，应回落到 1/26 |
| 质心比 | 留一库时，该库质心到最近训练库质心的距离 ÷ 平均库内散度 |

脚本 `scripts/db_identity_probe.py`，测试 `tests/test_db_identity_probe.py`（7 项）与
`tests/test_probe_feature_path.py`（2 项，证明手工重建的池化向量与 `_head_input` 逐元素相等，
rtol/atol 1e-6）。服务器运行 336 秒。

## 4. 结论

**假设成立，但形态与预期不同——这一点比「成立」本身更重要。**

1. **库身份在线性意义下几乎完全可读**：0.9858 对 0.0385 的随机水平，且负对照干净地回落到随机。
   表征里确实带着一个极强的「这是哪个库」信号。这与 96 号的 LODO 不可迁移、103 号的曝光跟随，
   三者互为印证：**模型学到的不是可迁移的修正规则，而是库的身份**。

2. **但这个信号不是「每个库一个孤岛」**：质心比中位仅 0.85，即多数库在特征空间里是**重叠**的。
   只有 6/26 个库（tubepricing、sakila、airline、accidents、fnhk、seznam）明显分离。
   所以捷径不是靠「各自占据一块地盘」实现的，而是**在重叠区域里仍有足够的方向性差异**让线性分类器分开——
   这比「孤岛」更难去除，也解释了为什么简单的域不变正则（只把质心拉近）可能不够。

3. **对改进路线的直接含义**：
   - CardOOD 式的 **CORAL/GRL**（对齐二阶统计量／对抗去掉库可分性）对症，但目标是**方向性差异**而非质心距离；
   - **Group DRO** 按库重加权同样对症（它压的正是「某些库被牺牲」）；
   - 但两者都要面对 0.9858 这个基线——**任何声称「去掉了库信息」的干预，都必须报告探针准确率降到多少**，
     否则无法区分「真的去掉了」与「换了个线性不可分但仍在的编码」。这条应写进后续实验的验收标准。

## 5. 边界与不可声称

- **单 seed（42）、单 checkpoint**；`needs_evidence = true`。
- 探针是**线性**的：0.9858 是线性可读性的下界，非线性探针只会更高，不会更低。
- 5 折是**查询级**随机分折，同一库的查询同时出现在训练与测试折——这测的是「库身份可读性」，
  **不是**「对未见库的泛化」。真正的泛化问题由质心比那一列回答。
- 39,000 行是每库 1,500 条的上限采样，不是全量；采样不改变结论方向，但换 seed 会让数值小幅浮动。
- **没有读任何目标库**（`target_databases_read: []`）。
