# Meta65 telstra “退化”的源侧诊断结果

日期：2026-10-10（Asia/Shanghai）。分支 `audit/meta65-telstra-diagnosis-20261010`，基于实验分支提交 f08bd49。协议见[52号](52-Meta65-telstra退化源侧诊断协议.md)。**本诊断只用既有 A/B/C 预测做只读描述性分析：CPU、无训练、无新推理、无超参搜索、无目标库、无门槛修改。**

## 1. 结论

**2026-10-10 口径更正：原 D2 是全部表数、五 run 拼接分位数，并非 4+ 表。** 原 JSON/CSV 与 52 号冻结协议保持不变；本轮新增 [54号复算协议](54-Meta65诊断口径复算协议.md) 和 [55号联合分层复核](55-Meta65联合分层复核结果.md)。原文“退化主要集中于低基数复杂查询、三库统一规则、小分母是主要原因、整体平移”均超出原证据，撤回强解释。telstra 的整体4+退化仍成立；小绝对尺度影响百分比大小，但不认证误差成因。

按真实基数分层（K=20，**全部表数、五 run 预测拼接后 Q95**，C/A 比值；不是逐 run Q95 均值，重复跨 run 查询是出现次数，<1 为改善）：

| 真实基数桶 | telstra C/A | chembl C/A | legalacts C/A |
|---|---:|---:|---:|
| <100 | 1.32 | **3.28** | 1.33 |
| 100–1e3 | 0.80 | **2.81** | 0.78 |
| 1e3–1e4 | 0.89 | 1.21 | 0.71 |
| 1e4–1e5 | 1.12 | 0.69 | 0.88 |
| 1e5–1e6 | 0.99 | 0.49 | 0.98 |
| ≥1e6 | — | **0.29** | 0.99 |

仅 `<100` 桶三库在这一 all-table 拼接口径上同向变差，不能泛化成所有低基数与中高基数的统一规则。telstra 的 100–1e3 桶改善、1e4–1e5 桶退化即为反例。跨库完整4+端点的 C−A 也并非同样偏移：chembl −15.695051、legalacts −2.705238、telstra +1.937502。

按表数分层（K=20，telstra，五 run 拼接 Q95）：2 表 C/A=0.74、3 表0.83、4表1.07、5+表1.76。旧D1对1表的计数/份额和“2表”标签有混淆，本轮单列1表。两个边际分层不能证明“低基数 × 高表数”交集或统计交互；联合分层须看55号实算。

## 2. 稳定性：不是个别 support run

D5（telstra，5 run 逐个）：

| K | 五 run 均值 C/A | 绝对差 C−A | 去单 run 后符号翻转 |
|---:|---:|---:|---|
| 5 | 1.253 | +1.758 | 无 |
| 10 | 1.226 | +1.585 | 无 |
| 20 | 1.287 | +1.928 | 无 |
| 50 | 1.333 | +2.141 | 无 |
| 100 | 1.357 | +2.275 | 无 |

旧D5留一run调用键名错误，原JSON `leave_one_out=[]`，**原来写成已验证属于错误**。本轮独立读取逐run数组复算：telstra删一均值差符号均不翻转，但删run0会改变K排序；K10逐run C/A最小0.931226，并非每run退化。只能说这五次抽样均值退化符号稳定，不可说与support抽样无关。原D5采用exp(log分位数)插值，和完整端点standard Q95全三库逐项最大差0.000121144458、telstra最大差0.000017439815；新复算用后者，不覆盖旧值。

D6尾部集中度（Top5%的sum(log_q)占比）all-table约0.1864–0.2070；legalacts的4+约0.1370–0.1518，不能混写成统一0.17–0.20。集中度接近仅为描述性观察，不能排除尾部增厚或证明整体分布平移。

D4配对（telstra，K=20，49500条共同查询）：`Δ(C−A)` 的p50≈−0.019、p10≈−0.427、p90≈+0.439，均值≈−0.016。这些描述统计不能认证原始误差分布整体平移，或证明变化主要来自两翼。

## 3. PG 锚与方向分层

PG 锚 `verified`：从只读源缓存 `cards.npy` 按 `query_id` 行号逐项对齐，`cards[rows,0]==npz true`、`offsets` 表数 `==npz n_tables` 全部通过（telstra）。PG 方向分层（D3）已按预期输出，**只对 telstra 执行**，chembl/legalacts 记为 `not_attempted`（冻结保留里没有它们的 PG 列绑定）。

## 4. 能得出与不能得出的结论

**能得出**：在原固定seed42的五次support计划下，telstra整体4+的C/A均值退化符号对删一run稳定；旧all-table `<100` 桶三库同向变差。联合桶结论、反例和跨run稳定性以55号为准，不能从旧D1/D2直接推断交集。不能把小分母当成退化的主要原因。

**不能得出**：不能说“65 参数适应容量不足”“last 是好/坏方案”“低基数查询需要某特定修复”。因为

- B/C分别采用head/3与last/3元训练及部署，是**两次独立元训练**，末态不同，并非同checkpoint仅交换部署scope；
- A→B 同时改 scope 与 inner steps；
- 只有 seed42 和三个被反复使用的开发库；
- 诊断只描述误差结构，不分离表征、元初始化与适应算子。

## 5. 建议的下一步方向（候选，不是结论）

“低基数 × 高表数”作为待联合验证的描述性假说，不能直接认定参数或表征信息不足。下一步 [56号同初始化协议](56-Meta65同初始化适应算子最小受控协议.md) 先分离给定checkpoint内的适应操作与区组差异；能问适应前误差是否存在、适应是否加剧，但不能据此认证表征不足。另需实现、冻结与执行授权。
