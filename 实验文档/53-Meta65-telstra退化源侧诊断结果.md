# Meta65 telstra “退化”的源侧诊断结果

日期：2026-10-10（Asia/Shanghai）。分支 `audit/meta65-telstra-diagnosis-20261010`，基于实验分支提交 f08bd49。协议见[52号](52-Meta65-telstra退化源侧诊断协议.md)。**本诊断只用既有 A/B/C 预测做只读描述性分析：CPU、无训练、无新推理、无超参搜索、无目标库、无门槛修改。**

## 1. 结论

**telstra 的“退化”不是 telstra 特有的、也不是尾部随机变差；它主要出现在低真实基数的复杂查询上，而这个模式在三个源验证库上共同存在。** 由于 telstra 的 Q95 绝对尺度最小（约 6–9，而 chembl 约 90–110），同样的绝对偏移在百分比上被放大，才显得最严重。

按真实基数分层（K=20，5 run 汇总，4+ 表 Q95，C/A 比值；<1 为改善）：

| 真实基数桶 | telstra C/A | chembl C/A | legalacts C/A |
|---|---:|---:|---:|
| <100 | 1.32 | **3.28** | 1.33 |
| 100–1e3 | 0.81 | **2.81** | 0.78 |
| 1e3–1e4 | 0.89 | 1.21 | 0.72 |
| 1e4–1e5 | 1.12 | 0.69 | 0.88 |
| 1e5–1e6 | 0.99 | 0.49 | 0.98 |
| ≥1e6 | — | **0.29** | 0.99 |

**同一个规则在三个库上成立：低基数查询上 C 变差，中高基数查询上 C 变好。** chembl 在低基数上比 telstra 恶化得更严重。所以先前“telstra 特别差”的印象，是**百分比放大 + 只看 4+ 汇总量**两个因素造成的。

按表数分层也支持这一点（K=20，telstra）：2 表 C/A=0.74、3 表 0.81（均改善），只有 4/5+ 表恶化（4 表 1.08、5+ 表 1.76）。**telstra 的问题集中在“低基数 × 高表数”这一小块。**

## 2. 稳定性：不是个别 support run

D5（telstra，5 run 逐个）：

| K | 五 run 均值 C/A | 绝对差 C−A | 去单 run 后符号翻转 |
|---:|---:|---:|---|
| 5 | 1.253 | +1.758 | 无 |
| 10 | 1.226 | +1.585 | 无 |
| 20 | 1.287 | +1.928 | 无 |
| 50 | 1.333 | +2.141 | 无 |
| 100 | 1.357 | +2.275 | 无 |

五个 K 全部同向，去掉任一 run 都不翻转，K 顺序也不变 → **不是个别抽样驱动**。

D6 尾部集中度（Top 5% 的 sum(log_q) 占比）三库各臂约 0.17–0.20，A/B/C 之间基本无差 → **不是尾部变厚**，而是分布整体平移。

D4 配对（telstra，K=20，49500 条共同查询）：`Δ(C−A)` 的 p50≈−0.019、p10≈−0.427、p90≈+0.439，均值≈−0.016 → 中间段几乎不动，变化主要在两翼。

## 3. PG 锚与方向分层

PG 锚 `verified`：从只读源缓存 `cards.npy` 按 `query_id` 行号逐项对齐，`cards[rows,0]==npz true`、`offsets` 表数 `==npz n_tables` 全部通过（telstra）。PG 方向分层（D3）已按预期输出，**只对 telstra 执行**，chembl/legalacts 记为 `not_attempted`（冻结保留里没有它们的 PG 列绑定）。

## 4. 能得出与不能得出的结论

**能得出**：C（last/3）相对 A 的 telstra Q95 上升是稳定的、与 support 抽样无关的，并且集中于低基数高表数查询；同一模式在 chembl/legalacts 也存在。telstra 的高百分比主要是小绝对尺度放大。

**不能得出**：不能说“65 参数适应容量不足”“last 是好/坏方案”“低基数查询需要某特定修复”。因为

- B→C 只改 scope，但 B/C 是**两次独立元训练**，末态参数不同；
- A→B 同时改 scope 与 inner steps；
- 只有 seed42 和三个被反复使用的开发库；
- 诊断只描述误差结构，不分离表征、元初始化与适应算子。

## 5. 建议的下一步方向（候选，不是结论）

证据指向“**低基数 × 高表数**”这一交集，而不是“telstra”或“参数少”。若要继续，可优先设计一个能区分“表征信息不足”与“适应算子行为”的受控源侧实验，并把低基数/高表数作为明确分层；但需要**另行制定协议、预算与授权**，本任务不自动启动。
