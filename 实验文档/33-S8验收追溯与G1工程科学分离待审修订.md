## 1. 推荐路线及明确的否决条件

**推荐：仅批准 G1 resource-only 的工程验收分离；小拟合面板旧 pass 保持，正式机制验收不自动放行。** 固定rcond与原objective/normal/参考预测门槛、工程SVD投影/metadata/backend、数据隔离/资源全部不变；在完整P资源路径新增显式 engineering_verified。数值秩稳定性仍用30号原公式报告，不变阈值、unknown不转passed。无严格证明时strict_certificate.status仍unknown。

理由：27§1明确完整P系数只作资源测量、不参与预测/选择，却与1216小拟合面板共享pass，当前resource路径被数值秩稳定性区间阻断时，连后续工程封存/H入口/端点闭环都不能验证。工程profile可回答“代码实际能求解/重载/输出且资源是否受控”，不需要先证明原完整线性类最优。但这是**修改27§5停止条件和§6完成条件的真实协议变更**，不是不影响验收的字段整理；必须先获用户批准并绑定新版本。

只影响未来新run。原smoke failed保持；旧P新proof也不能追认旧G1。新工程完成仍formal_ready=false，正式阶段必须另审/授权。

如果用户坚持24§1“排除线性读出欠求解后比较表示”必须作为不可削弱的主要科学问题，则**否决将engineering替代正式数值认证**：工程一致性不能排除弱方向/截断方向或证明最优，正式G2–G4保持暂停。替代路线是先完成G1工程闭环，再由用户选择冻结一个有限求解路径/可达拟合改进的经验研究，或暂停S8强机制问题；不默认开启下一轮数学研究。

## 4. 待批准的最小状态与 gate 契约（明确到条件）

### 4.1 数值函数结果：保持旧接口含义，新增字段

`certify_pair`保留旧 `pass == solver_verified` 与30号原合取、`rank_stability`、`rank_limited/numerical_rank_limited`、`fullrank_numeric_solver`、所有旧门槛和full_linear_optimality=False。**不能把旧pass重新解释成engineering**，旧消费者/测试不得静默变宽。

新增 `observed_ranks={reported_ls,svd,reference_ls}`、`observed_rank_agreement`。
新增 `engineering_verified` = 以下所有布尔条件的合取：

- 现有 metadata_pass（含完整reported谱比较）、normal_residual_pass、objective_pass；
- reference_objective_pass、reference_prediction_pass、reference_spectrum_pass；
- svd_backend_pass、retained_subspace_pass、reference_retained_subspace_pass；
- observed_rank_agreement（各自rank仍严格自谱计数）。

畸形/非finite/linalg失败仍raise；字段缺失不得默认True。本式仅去掉 `rank_stability==stable` 的全局合取需求，不去掉其它已冻结数值门槛。新数值engineering flag的scope仅`same_matrix_fixed_cutoff_numeric_consistency`，不包含数据/资源/实际运行全链，后者由runner独立合取。

另外新增不驱动G1工程gate的摘要：

```text
strict_certificate = {
  status: unknown,
  scopes: [true_rank, rigorous_retained_subspace, strict_linear_optimality],
  reason: no_verified_arithmetic_certificate
}
numerical_rank_stability = 原 rank_stability（stable/unknown）
```

stable只是旧工程包络内稳定，不将strict_certificate改为verified。`numerical_rank_limited`与stability、strict_certificate彼此独立。理由`dimension_envelope_insufficient`只能说明可推导的包络局限，不能断言真实谱远离cutoff；保留每谱margin/区间作为证据。不增加新margin阈值。

### 4.2 runner：只改一处 gate，必须新版本

- **小拟合面板：仍要求 `certificate['pass']`**（既有E+N全检查）。失败保持原hard fail，不因为strict unknown放行预测所用系数。
- **完整P resource-only：改为要求 engineering_verified**；若工程失败立即failed；工程True、N1 unknown时保存`resource_profiled_with_rank_stability_unknown`，只继续资源和工程端点闭环，丢弃此LS系数，不用于predict/select。
- 所有F0、checkpoint、端点、seal/H、输入/源码一致性、实际预算继续硬gate。未到stage用`not_run`，不是unknown/failed；工程错误用`failed`及stage；严格证据不足用unknown及scope。
- summary/status只有工程全链完成且独立工程核验通过才写`completed_engineering_smoke`（新版本状态），run-level `engineering_verified=True`、`strict_certificate_status=unknown`、`formal_ready=False`、`candidate_decision=smoke_not_selection`、所有强最优性False。中途resource success不是G1 success。
- 增加numeric阶段细项记录、observed ranks、stability margins、E checks、CPU/backend/源码/输入hash及actual factorization计数；同worker源码实际调用计数和record绑定是执行证据，不冒充第三方独立求解真实性证明。
- profile同时记录standardization时间/solver_certification时间/total时间，matrix_bytes明确单数组payload，run RSS与RLIMIT_AS预算口径分开。不改预算或声称实测峰值=矩阵字节。

选择新bindings schema2 + 固定 `numerical_acceptance_policy=s8-g1-resource-engineering-v2`，仅允许mode=smoke；新协议/修订内容SHA纳入signature。旧schema1/v1语义保留，新策略未批准/缺字段/未知策略/用于formal即拒绝；不提供自动fallback或 `--ignore-certification` 开关。运行入口必须新执行包/新目录，不能加载旧failed checkpoint/旧合约作为schema2。旧27原字节不改，批准后的修订附件成为新协议绑定的一部分。

### 4.3 可报告的结论白名单（尤其正式阶段）

本次smoke只报告P-only执行、工程一致性、资源/计时、端点完整性；不报G>=10%机制或研究收益。

今后若用户另行批准完整正式经验性probe协议，可报告同固定表示/同P下**一个合法有限系数给出比有限步Adam更低的J**，以及固定求解路径在Q/H的配对表现。前者不需要宣称全类最优，26§1.1已有这一有限解释。各原门槛仍全保留，身份/完整分母/原V-Hgate及单seed开发偏差不得变化。

禁止：无优化差距、达到原线性最优/最小范数的严格证明、已排除欠求解、真实秩已证、真保留子空间已证、层级信息缺失/压缩因果、已解决空间漂移。LS与Adam接近不能证明没有更好读出，层级差异不能排除求解/截断/隐式偏好影响。

**该未来正式弱化解释不在本次批准范围。** 24§1/§7/§8中“LS已数值认证”的正式契约仍未替换，`development_promising`/`promising_single_seed_probe`不因resource-only E通过自动许可。若原问题要求不缩窄，暂停正式强机制部分，不为获得研究结果放行。
