## 1. 要检验的假设

当前 `last3` 适应只更新输出层 `64 × 1` 权重和 1 个 bias，共 65 个参数，但通过 3 步普通梯度下降求解。K=20 时，这是一个高维小样本、强正则化问题；3 步梯度的结果依赖学习率和局部曲率，不一定接近带正则的最优解。

本轮原型检验：

> 在参数族与预测形式相同的前提下，用 proximal ridge 闭式解直接求最后一层，能否比 3 步梯度更稳定地利用 20 条 support，并保留向元学习初始化收缩的机制？

这不是模型结构改造，也不是新的正式实验协议。它会同时涉及最后一层的求解器和损失口径，必须通过下面的 MSE 梯度对照解耦，不能把组合差异全部归因于求解器。

## 2. 对照设计

共同部分：

- 同一 checkpoint、同一 encoder、同一 support/query plan、同一 K。
- 只更新 `head.4.weight` 与 `head.4.bias`，其余参数不变。
- 预测形式保持 `anchor + head(x)`，目标仍是 log-cardinality 残差。
- 目标库不进入任何环节。

**损失口径必须显式区分**：现有部署 `last3` 使用 3 步 SmoothL1；本原型的 proximal
ridge 使用平方损失。二者只在残差落入 SmoothL1 的二次区（`|residual| < 1`）时局部
等价。因此 `last3_gradient_smooth_l1` 对 `last3_ridge_mse` 同时改变了目标函数和求解器，
不是严格的同目标单因素对照。

| 算子 | 更新参数 | 求解 |
|---|---:|---|
| `none` | 0 | 不更新 |
| `last3_gradient_smooth_l1` | 65 | 现有部署：3 步 SmoothL1 梯度 |
| `last3_gradient_mse` | 65 | 3 步 MSE 梯度，用于隔离损失函数 |
| `last3_ridge_mse` | 65 | MSE + proximal ridge 闭式解 |

`last3_ridge_mse` 的目标：

```text
min_w,b  ||Xw + b - y_residual||²
       + λ_w ||w - w_meta||²
       + λ_b (b - b_meta)²
```

其中 `X` 是 checkpoint 的 64 维输出层输入特征，`w_meta/b_meta` 是元学习得到的最后一层参数。`λ` 只控制向元参数收缩的强度，不另调 3 步梯度学习率。

严格解释：

- `last3_ridge_mse` vs `last3_gradient_mse`：相对隔离“闭式求解器”；
- `last3_gradient_mse` vs `last3_gradient_smooth_l1`：相对隔离损失函数；
- `last3_ridge_mse` vs 现有部署 `last3_gradient_smooth_l1`：是组合干预，不得把全部差异归因于求解器。

## 3. 原型范围

本轮只实现：

1. `SetEstimator` 的只读特征/锚点访问接口，保持现有 `forward()` 行为不变。
2. `last3_ridge_mse` 适配求解器，返回与 `adapt()` 同形式的非原地参数映射。
3. 审计字段：support 数、特征维度、正则、support 残差前后、参数更新范数、Gram 条件数、是否有限。
4. 单元测试：闭式解正确性、proximal 收缩、非原地、query 标签隔离、encoder 梯度路径和无 NaN/Inf。

本轮不实现：

- 不修改旧 runner、冻结配置、binding 或正式协议。
- 不启动 GPU、训练、推理、服务器访问或目标库读取。
- 不选择正式 λ，不在三验证库上报告正式精度；这些必须由后续独立屏幕协议授权。

## 4. 后续实验阶梯

### Gate 0：本地原型

- 本分支实现与单元测试通过。
- 现有 `SetEstimator.forward()` 行为与 state dict 完全不变。
- 独立只读审查通过。

### Gate 1：离线只读屏幕

获单独授权后，在既有源验证 checkpoint 上比较 `none / last3_gradient_smooth_l1 / last3_gradient_mse / last3_ridge_mse`。复用同一 support/query plan，只报告 4+ 表 Q95、低基数主桶和逐库逐 query 配对结果。此阶段不训练模型，不读目标库。

### Gate 2：正式元训练候选

只有在 Gate 1 同时满足主指标改善和逐库保护后，才另立协议，把 ridge 求解器接回 FOMAML 外循环。该阶段需要重新冻结 code/input SHA、预算、运行器和批准链。

## 5. 停止与判定

- 求解器不得通过放宽现有指标或静默回退到恒等映射制造通过。
- support 特征或目标非有限时直接报错。
- 若闭式解病态、参数爆炸或 support 残差未改善，记录失败并停止，不自动扫大范围 λ 网格。
- 单 seed、单 K 的屏幕结果只可作为候选筛选，不构成跨库或目标库泛化结论。
