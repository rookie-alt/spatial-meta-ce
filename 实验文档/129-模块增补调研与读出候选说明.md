## 1. 第一候选的作用

当前 A1-PG 在 [price_model.py](../spatial_meta_ce/price_model.py) 中读取最终 filter encoder 的 CLS，取一个 64 维向量；数量特征经 `len_net` 变成 16 维，再拼接表规模和 PG：

```text
c: 64 维 CLS
l: 16 维数量特征
k: 各表 log(size) 的和，即 log(笛卡尔积规模)
p: log(max(PG,1))

当前： [c, l, k, p] (82维) → MLP → r → p+r
候选： [c, l] → u → s (1维)
       [s, k, p] → v → r → p+r
```

128 号的“第一候选”是 **PRICE 式两段读出**。第一段把 query 侧表示组织成一个中间坐标，第二段学习它与 PG、表规模的关系。潜在价值是限制任意特征混合、提供结构归纳偏置，可能改善拟合或跨库迁移；不增加新信息。当前 PG 已进入 head。中间标量没有独立监督，不能自动叫“真实选择率”或“可信度”。

官方 [PRICE 读出](https://github.com/StCarmen/PRICE/blob/1ca9000197dbb92ecb9e71af22f47560f78cb4d5/model/encoder.py) 先将 query 表示压成标量再与 PG、表规模融合；此候选保留本项目 `p+r` 输出，不是完全复现官方 PRICE。

**代价是主动引入标量瓶颈。** 当前 head 本来就能让 64 维 query 表示与 PG 做非线性交互；先压成 1 维可能丢掉只有结合 PG 才能判别的信息。不能以“增强表达能力”“找回遗漏关系”作为依据，也没有实验说明它一定更好。它适合做低成本读出对照；若目标是加入更有针对性的模块，分组聚合支路更值得优先检验。原先的“第一”是实现顺序建议，不是已证明收益最大的排序。

## 2. 新模块优先级

当前已有两阶段、各 2 层的 self-attention，CLS 是可训练的全局读出。它与标准 PMA 并非完全相同，但功能重叠；“再加 attention”或增加全局 seed 数不等于增加新信息。

| 顺序 | 模块 | 检验什么 | 数据依赖与主要风险 |
|---|---|---|---|
| 1 | 保留 CLS 的分组注意力聚合支路 | 同时读取四类 token 汇总，检验单 CLS 读出是否不足 | 使用现有 token/mask；可能只是增加容量，不能恢复缺失语义 |
| 2 | 关系感知 attention bias | 显式使用过滤列→表、连接列→表、fanout→连接列的关联 | 需认证 mapping；当前仅源侧可用，旧 sum_map 未超过简单 sum |
| 3 | 查询条件 FiLM 调制 | 根据数量/规模/PG 上下文调节特征通道 | 使用现有 query 特征；可能学源库捷径，迁移证据有限 |
| 对照 | PRICE 式两段读出 | 改融合顺序和瓶颈结构 | 无新数据；可能降低表达自由度 |

排序基于接入成本、现有输入和方法依据，不依据新的目标库实验筛选。

## 3. 优先模块：分组注意力聚合支路

现模型只读 `filter_encoder(... )[:,0,:]`。可保留 CLS 路径，同时从最终 encoder 输出按 join_hist、fanout、table、filter 四段分别取有效 token，学习加权汇总：

```text
四组最终 token → 各组打分网络 → masked softmax → 四个64维汇总
                                                   ↓
原 [CLS, 数量, 表规模, PG] ────────────────────────→ 拼接 → 残差头
```

这给 head 增加四个按类型组织的读取窗口，减少对单 CLS 完成全部压缩的依赖。它不证明 CLS 已经丢了信息；最终 token 已有跨组交互，某组汇总也不等于“只含这一组的纯信息”。

方法依据：[Set Transformer（ICML 2019）](https://proceedings.mlr.press/v97/lee19d.html) 的可学习 attention pooling、[官方 PMA 实现](https://github.com/juho-lee/set_transformer/blob/73432c640ac78140496d6738416c54d32c686d65/modules.py)。此处是分组打分聚合的轻量变体，并非照搬完整 PMA；原论文没有证明其在本项目 STATS 上有效。

**接入可行**：raw group 虽经 flatten，但上限固定、embedding 按偏移恢复 token，组边界仍可恢复，不需 SQL sidecar。上限 12/12/7/10 对应 41 个 feature token，加 1 个 CLS。必须按原 mask 排除 padding，空组返回零；padding query 的 encoder 输出可能非零，不能直接对整段求均值。

**纯算术估计，未实现/计时**：每组 `64→16→1` 打分，四组增加 `4×(64×16+16+16+1)=4,228` 个参数；拼接 256 维到 head，第一层增加 `256×128=32,768`，合计 **36,996**。A1-PG 将从 294,033 变为 **331,029（约 +12.6%）**，不含额外投影或 LayerNorm。参数量不是实测统计。

验证应比较原 A1-PG、分组简单均值、分组可学习汇总，并用参数量接近的 head 对照识别容量因素。不能把“新增参数后变好”直接归因于注意力；先在源侧冻结小矩阵和预算，不根据 STATS 增加层数或 seed 数。

## 4. 关系感知 attention：语义直接，工程边界更大

当前 [attention](../vendor/price_baseline/module.py) 的 score 只有内容相似度与 padding mask。候选增加关系类别偏置：

```text
score_h(i,j) = dot(Q_h(i), K_h(j))/sqrt(d_h) + b_h[relation(i,j)]
```

关系可表示同表、连接配对、fanout 来源等，增加当前模型未消费的查询关联信息，不增加真值标签。跨库应使用查询内关系，不引入全局数据库/表名 ID。

直接依据：[CardBench（2024）](https://arxiv.org/html/2408.16170) 的图 attention 结构编码及 [原始实现](https://github.com/google-research/google-research/tree/master/CardBench_zero_shot_cardinality_training/graph_transformer)；[JGMP](https://www.vldb.org/pvldb/vol17/p740-reiner.pdf) 的表、连接、谓词关联图。二者输入/评估范围不同，论文收益不能当本项目预期，CardBench 也报告零样本 join 的困难。

例如 8 种关系、4 heads，共享 bias 表仅 **32 个参数**，四 block 独立则 128；这只是 bias 表，不是全模块成本。关系矩阵、解析、缓存绑定和校验才是主要工程工作。

项目已有 [mappings.py](../spatial_meta_ce/mappings.py) 和 [sidecar 构建器](../scripts/build_mapping_sidecar.py)，但当前 `price_lite` 拒绝 `mapping`，`MappingStore` 限 source/pretrain，不能直接在目标库启用。需先在源侧认证 token 顺序、query_hash、过滤列归属、有向配对，使用真实/打乱关系的同参数对照。

历史 [12 号映射消融](12-映射消融正式协议.md) 已测 concat/fusion：完整源验证 4+ 表主指标三 seed 均值 true 51.6143、shuffled 59.6171、sum 43.3766。真实关系优于打乱，整体仍不如简单 sum。可研究不同的关联使用方式，但不能宣称“补图就会更好”或原样重跑旧模块。

## 5. FiLM：内部条件调制，作为备选

```text
x = [log1p(四类数量), PG_log, log_cartesian]   # 6维
[delta_gamma, beta] = MLP(x)                  # 128维
h_new = (1+delta_gamma) * h + beta            # h为64维表示
```

它让相同 encoder 特征在不同查询规模或 PG 条件下以不同方式组合，是显式乘法交互的计算偏置，没有新数据。与旧 `p+g*r` 残差门控不同，但仍须与原模型比较，不能因机制名称不同就预设有效。

[FiLM（AAAI 2018）](https://ojs.aaai.org/index.php/AAAI/article/view/11671) 支持通用调制方法；[DistJoin](https://arxiv.org/html/2503.08994v3) 在 CE 中使用 HyperNetworks 和低秩调制，但预测单表分布、训练路径不同，不是 FiLM 在 A1-PG 上的实验证据。

一个 `6→32→128` 网络纯算术为 **4,448** 个参数；调制一个 64 维读出无需改输入数据。要检查条件分布、调制幅度与跨库保护，避免数据库身份或目标误差进入条件。当前 MLP 能学习部分类似交互，收益可能有限。

## 6. 暂不直接接入的路线

- [CorrBound（SIGMOD 2026）](https://doi.org/10.1145/3786633) 使用相关性统计、度向量压缩及优化求解，不是可直接放进 neural head 的小模块。
- [MultiCard（2026）](https://arxiv.org/html/2610.27019) 侧重 LIKE 与数值谓词混合编码，当前 PRICE 特征没有匹配的字符串输入，不直接套用其 LSTM/Transformer 分支。
- [ALECE](https://arxiv.org/html/2310.05349v2)、[ACE](https://arxiv.org/html/2503.14929) 的 data-query attention 依赖额外数据库表示，且任务不同；当前两阶段 attention 已存在，不建议无新信息地堆叠。
- 结构锚点、更换 PG 锚、损失网格、简单输出回退已有 [120 号](120-结构锚点ERM训练与目标库评估结果.md)、[94 号](94-P1精度杠杆实现与源侧筛查.md) 负结果，暂不优先。

模块不能凭一维边缘分布恢复所有未知联合分布。如果源侧认证发现原因是缺失相关性统计或 SQL 语义，pooling/FiLM 只改变近似方式，不能保证消除信息不足。
