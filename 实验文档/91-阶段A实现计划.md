## 0. 写计划时发现的一个协议冲突（必须先说）

90 号草案假设 A3 可以"只换 support、复用现有 query"。读完
`scripts/meta65_joint_runner.py:487-513` 的 `certify_plan` 后确认**这不可行**：

```
query != [i for i in indices if i not in set(support)]  →  raise
```

81 号协议要求 query 是**全集减去整个 100 条 support**，support 与 query 严格互斥。
所以每次新抽样都必须同时重建 support 与 query（第 51–95 次各自一套）。
后果：

1. **每次抽样的 query 分母不同**（49,404 或 49,900 减去 100，几乎不变，
   但逐条不同），不能与 81 号的 50-cell 结果逐条配对，只能比分布。
2. **每组 (库, run) 都是完整的一遍全 query 前向**，成本 = 50 组 × 3 库。
   按 D2 实测（15 个 cell 414 秒，含 head 特征抓取），A3 是不抓特征的路径，
   预计单 cell 15–25 秒，**总量 40–60 分钟量级**。
   这是估计，不是承诺；实测后如实记录。

**这是对 90 号草案 §3-A3 描述的一处修正**，需要你知晓；草案本身不改（它是方案
文本），在本计划里更正并说明理由。

## 3. 抽样设计（A3）

```text
S0 = {run 0..4}                        # 已存在的 5 次，来自 plan-20261018.json
S1 = {run 5..49}                       # 新增 45 次
seed_new = 20261019                    # 独立序列，不复用 1729
sample: random.Random(f"{seed_new}:support-coverage:{db}:{run}").sample(indices, 100)
support = sample[:20]                  # 与 81 号同样的"取前 20"约定
query   = [i for i in indices if i not in set(sample)]
```

- `indices` 取自 `build_meta65_holdout_plan.validate_store`（首现去重、唯一 query 口径），
  与 81 号**同一函数**，避免分母漂移。
- 每组抽样记录 `support_digest` 与 `query_digest`，写入新 plan 文件，
  单独冻结 SHA，**不覆盖** `plan-20261018.json`。
- 新 plan 输出到 `…-code-rerun1/reports/support-coverage-20261019/plan-20261019.json`。

## 4. A1 特征刻画

对每组 (库, run) 的 20 条 support 计算（只用可观测输入）：

| 特征名 | 计算 |
| --- | --- |
| `tables_4/5/6p_share` | `n_tables` 在 {4,5,≥6} 的占比（也报 1–3 表占比） |
| `true_tercile_share` | 该库全体 low4 查询的真实基数三分位阈值下，support 落在各三分位的占比 |
| `pg_dev_tercile_share` | `|PG−true|/true` 三分位占比 |
| `pg_over_share` | `PG > true` 的占比 |
| `group_len_mean` | 组 0/3 的 token 数均值（`offsets` 差分） |
| `log_cartesian_mean` | 组 2 首列的 `log1p` 之和均值 |
| `low4_share` | support 中 low4 查询占比 |

**边界**：只用可观测输入。`true` 仅用于**定义桶**（与 81 号 low4 定义一致），
不用于给 support 打分排序。

## 5. A2 方差归因

- 因变量：每组的 `better_share`（low4 改善占比）与 `low4_q95_ratio`。
- 自变量：A1 的 7 个特征。
- 方法：Spearman 相关（n=50 时用全部；对照报告中现有 5 个 run 的相关系数）。
- 判据（沿用 90 号）：
  - 任一特征 `|ρ| ≥ 0.8` → `predictable_by_support_composition`
  - 全部 `|ρ| < 0.5` → `not_predictable_from_support`，**停止，不做阶段 B**
  - 中间 → `inconclusive`，同样停止

**n=5 与 n=50 必须分开报告**，不能把 50 次的结果说成"验证了 5 次结论"。

## 6. A3 分布统计

输出：

1. `better_share` 与 `low4_q95_ratio` 的 50 点分布：min / P5 / P25 / P50 / P75 / P95 / max。
2. 现有 5 个 run 在该分布中的**分位位置**。
3. 达到 95% 置信（±10% 相对误差）所需的重复次数估计（自助法 bootstrap，
   seed 固定）。
4. 三库分别报告，**不跨库合并**（与 81/85/89 号一致）。
