## 0. 一句话结论

**"学数据分布"和"跨数据库零样本"在原始设定下互相排斥。** 真正学分布的模型（DeepDB/Naru/NeuroCard/FLAT/BayesCard）
参数编码的是**某一个库的联合分布**，换库必须重建；它们无法满足本项目"目标库不进训练"的红线。
可迁移的只有四条路：预训练+统计特征（PRICE）、零依赖（ZeroCard/GRASP）、通用统计量上界（SafeBound）、
单表分布+因子图（FactorJoin）。**其中只有第四条真正用数据分布做跨表组合，且它仍需扫目标库建单表分布。**

**第二层结论（对项目更关键）**：核查后发现，PRICE 论文 §4 的四类特征——属性值分布、join scaling factor 分布、
过滤谓词信息、表级启发式估计——**本项目的管线里已经全部具备**。因此"换成用数据分布的模型"
在本项目上**不会带来输入信息层面的增量**；差距只能来自这些信息如何被使用。

**第三层结论**：跨库 + 真元学习（inner/outer loop + support/query）在关系型 CE 上是**文献空白**——
PRICE 全文 MAML/meta-learning 词频为 0，它是 pretrain + finetune。这一点使元学习在 CE 上的有效性
**至今没有任何正面或负面的公开证据**，需要本项目自己消融。

### 1.1 已有统计文件的语义（本轮实测）

`datas/statistics/{split}/{db}/` 下的 5 个 pkl，实测语义：

| 文件 | 结构 | 实测 |
|---|---|---|
| `histogram40.pkl` | `{table: {col: {hist, bin_edges, len, min_value, max_value}}}` | `hist.sum == len == 该列行数`；`bin_edges` 长 41 |
| `fanout40.pkl` | `{(left_col, right_col): [side0_40, side1_40]}` | 每侧是**按 join 键聚合的平均 fanout 直方图**；TPC-H supplier 侧 ≈ 600 = 6M/10k |
| `summary40.pkl` | `{table: {col: {keys, values}}}` | 离散列的 top-40 频次 + `OtHeRs` |
| `size.pkl` | `{table: {size, num_cols, num_rows}}` | 表行数 |
| `abbrev_col_type.pkl` | `{abbrev, col_type}` | 表别名与列类型 |

四目标库的 `statistics/test/{db}/` 均存在。**这是"数据分布"在本项目里唯一已进入管线的形态。**

## 2. 主要方法一览与可迁移性判定

### 2.1 学分布的模型（换库必须重建）

| 论文 | 出处 | 用到的分布信息 | build 成本 | 跨库 |
|---|---|---|---|---|
| DeepDB (RSPN) | arXiv:1909.00607, PVLDB 2020 | 全量 row-level；跨表 RSPN | IMDB 48 min (V100)；单表 5 min | ❌ 模型即该库 |
| Naru | arXiv:1905.04278, PVLDB 2020 | 全量 tuple 流，自回归 | 每 epoch 50–75 s；模型 2.5–12.7 MB | ❌ 列绑定、仅单表 |
| NeuroCard | arXiv:2006.08109, PVLDB 2021 | 全库 join sample | 秒–分钟（采样）；模型数 MB | ❌ 一库一模型 |
| FLAT (FSPN) | arXiv:2011.09022, PVLDB 2021 | 全量，自适应因子化 | — | ❌ |
| BayesCard | arXiv:2012.14743, SIGMOD 2021 | 全量，每表 BN | 推理快 1–2 数量级 | ❌ |
| UAE | arXiv:2107.12295, PVLDB 2022 | 全量 + workload | — | ❌ |
| Duet | arXiv:2307.13494 | 全量，谓词注入自回归 | 推理 O(1) | ❌ |
| ALECE | arXiv:2310.05349 | 全库数据编码器 | — | ❌ |

### 2.2 可迁移的四条路

| 档 | 代表 | 为什么可迁移 | 主要代价 |
|---|---|---|---|
| **A. 预训练 + 统计特征输入** | **PRICE** arXiv:2406.01027 | 输入是各表 1-D 统计 + 查询；30 库预训练 | 需目标库**统计量**；join 精度靠微调补 |
| **B. 零依赖** | ZeroCard arXiv:2510.07983（只要 schema）、GRASP arXiv:2506.16007（只要 workload） | 不需要数据 | 精度未经独立复现；GRASP 仍要目标库 workload |
| **C. 通用统计量上界** | SafeBound arXiv:2211.09864、LpBound arXiv:2502.05912 | 只需 degree sequence，方法不学库特性 | 只给上界，不给点估计 |
| **D. 单表分布 + 因子图** | **FactorJoin** arXiv:2212.05526, SIGMOD 2023 | 只扫基表建单表条件分布，不做 join 反规范化（IMDB-JOB 用 **1% 采样**） | 仍要扫目标库；尾部/高选择性仍退化；输出是**概率上界** |

**语义澄清（必须写进论文，否则会被审稿人抓）**：PRICE 的"不需要目标库数据"准确说是
"不需要目标库**原始行/查询执行**"，但**仍要目标库统计特征**。若连统计量也不给，只剩 B 与 C。

## 3. 综述给出的失效条件（这是"参考价值"的核心）

来源：Are We Ready?（PVLDB 14(9):1640–1654, 2021，DOI `10.14778/3461535.3461552`）、
Design Space Exploration（PVLDB 15(1):85–97, 2022，DOI `10.14778/3485450.3485459`）、
CardBench（arXiv:2408.16170, NeurIPS 2024 D&B）。

### 3.1 跨库零样本的直接证据（CardBench，20 个真实库，19 训练 1 测试）

| 设定 | 结果 |
|---|---|
| 单表 zero-shot | "promising"，但尾部明显更差 |
| **binary join zero-shot** | 相对 instance-based，中位最多 **20×**、P95 最多 **5300×** |
| + 500 条目标库查询 fine-tune | binary join GNN 从 P50 1.57 / P95 280 → **P50 1.32 / P95 120** |

**这是唯一系统评估跨库零样本的基准。** 它没有拆开 schema 差异与规模差异的各自贡献。

### 3.2 数据分布模型的已知失效模式

| 失效条件 | 证据（原文数字） |
|---|---|
| 函数依赖（相关=1.0） | learned 方法 q-error **上升 10–100×**（Are We Ready? §6.2） |
| domain 1K→10K | Naru 退化 **100×**；MSCN/DeepDB 约 **10×**（同上 Fig.11） |
| 高偏斜 | Naru progressive sampling 出现 0-tuple；DeepDB 频率表丢低频值 |
| 小基数/空结果 | MSCN/LW-XGB/LW-NN 全部违反 Fidelity-B（无效谓词应返回 0） |
| **Naru 稳定性** | 真值 1036 的查询跑 2000 次，估计散布 **[0, 5992]** |
| 多表 join | IMDB 上 Naru 95% **11.2**、DeepDB **25.3**、max 477/789（Design Space Table 4） |
| 数据更新 | IMDB 5% 插入：Naru 全量重训 **795 s**，DeepDB **289 s** |

### 3.3 "单表统计替代全量数据"是否可接受

**有条件的"是"，但不是 1D 直方图。**

| 做法 | 结论 | 证据 |
|---|---|---|
| PG 1D 直方图（10k buckets）单表 | 中位 1.06–1.40，**95% 15–78**，max 10⁵ | Are We Ready? Table 4 |
| 1.5% 均匀采样 + 独立性假设 | 中位 1.01–1.16，95% 1.25–11，**max 仍 2×10⁵** | 同上 |
| 多维直方图 MHIST | 中位 4.25/3.83/4.46/1.58，**全部差于 PG** | 同上 |
| 单列统计+独立性 on join | 中位 **55.54**，P95 **4.4×10⁶** | CardBench §5.2 |
| **单表条件分布 + 因子图** | STATS-CEB 端到端 19,116 s vs PG 35,341 s；IMDB-JOB 1,324 s vs 2,472 s | FactorJoin Tables 3–4 |
| bound-based join 直方图 | STATS-CEB 比 PG 好 **+46.2%**；MultiHist **−28.3%**、WJSample **−75.0%** | CEB benchmark Table 3 |

**钥匙不是"直方图"，而是"能否用廉价单表条件分布保留足够的跨表相关性"。**

## 4. 对本项目的判断

### 4.1 现有输入与"用分布"的差距（本轮代码核查）

逐行核对 `vendor/price_features/features_tool.py`（94–135、333–451 行）后确认：

**已经用上分布的**（此前一轮记录有误，此处更正）：

- 过滤谓词的选择率**确实来自直方图积分**。`calculate_hist_selectivity()` 做标准分桶累加积分；
  离散列 `=` 谓词走 `summary40.pkl` 的 top-40 频次，其余走 `histogram40.pkl`。
- 表级 `avi / minsel / ebo` 是该表各过滤列选择率的乘积/最小值/加权积，**全部源自上述积分**，
  不是 `1/D` 独立性近似。（`avi=1` 只出现在该表无过滤列时。）

**join 侧同样已经用上了分布**（第二次更正，此前两轮记录均有误）：

本轮对 `fanout40.pkl` 做了定量验证。对 TPC-H `li.l_suppkey = s.s_suppkey`：

```
li_hist(每 bin 行数) / 250     = [599.99, 600.76, 597.30, 604.78, 602.35, 597.58]
fanout side1(每 bin 平均扇出) = [599.99, 600.76, 597.30, 604.78, 602.35, 597.58]
```

（250 = `s_suppkey` 的每 bin 键数 = 10000/40。）两者逐位相同，说明：

- **`fanout40.pkl` 的 40 个 bin 按 join key 值域分桶**，每个 bin 是该值域段内 join key 的**平均扇出**；
- 左右两侧的第 i 个 bin 对应**同一段 key 值域**，即左右天然对齐；
- 这和 PRICE 论文 §4 特征 #2 描述的 "distribution of the scaling factors ... encoded as histogram vectors"
  是同一类特征。

偏斜确实被保留：实测各库 fanout 向量的变异系数（SD/mean）最高到 **3.85**（genome `att_class_id`）、
accidents 3.50、ergastf1 3.14、stats 2.02，并非压成单一均值。
（TPC-H 是均匀分布，40 个 bin 全 = 600 属于预期，不能用来判断是否被压缩。）

**结论：PRICE 论文 §4 的四类特征，本项目的管线里全都有了。**

**仍然与 PRICE 不同的两处**（这才是真正的差距）：

1. **没有任何"跨 bin"的显式对齐运算**。左右两侧的 fanout 向量是**分别作为 token 送入**的，
   网络需要自己学会"第 i 个 bin 对第 i 个 bin"。值域重叠比例、对齐后的期望扇出这类标量没有显式算出。
2. **列间相关性只剩三个标量**：`avi / minsel / ebo` 把多谓词压成单值，
   无法表达"两列同向偏斜"这类联合分布结构。

第 1 条是否值得显式化，需要看网络是否已经学到了它——这一点**尚未验证**，不能当成已知缺口。

### 4.2 三条候选路线（成本递增）

| 路线 | 内容 | 是否违反红线 | 成本 |
|---|---|---|---|
| **R1 元学习 vs 微调严格消融** | 同架构同数据同查询预算，`FOMAML-init` vs `pretrain 权重直接微调`，≥3 seed | ❌ | 低-中，可复用 `run_experiments.py` |
| **R2 因子分解模型** | FactorJoin 式：单表条件分布 + 因子图组合，跨库预训练 | ❌ 不违反（源库统计量训练，目标库只用统计） | 中，需新模型与推理 |
| **R3 逐库重建 DeepDB/Naru** | 每个目标库用原数据训练 | ✅ **违反**"目标库不进训练" | 高，且磁盘 98% |

**R1 的必要性**：文献里"跨库 + 真元学习（inner/outer loop + support/query）"在关系型 CE 上是**空白**。
PRICE 全文 MAML / meta-learning / inner-loop / episode 词频均为 **0**，它是 pretrain + finetune；
RELOAD（TKDE 2026）是唯一用真 MAML 的数据库工作，但对象是查询优化器、任务定义是查询簇不是数据库，
且论文自述 "none of the configurations outperforms expert-level performance"。
唯一有 MAML vs 微调直接对比的是 Subgraph Counting（DASFAA'23 Table 4），MAML 的 MAE 是其他方法的
1.6–2.6 倍且两个任务 OOM。**因此"元学习在我们这条线上到底有没有用"必须自己做消融才能回答。**

**R1 的风险**：结果可能是"元学习没用"。但这是有价值的负结果，且能直接回答导师最可能问的问题。

**R2 的成本与精度锚点**（PRICE PVLDB 18(3) Table 2 第三方实测）：
FactorJoin 在 IMDB 建一次 **78.45 min / 5.59 MB**、STATS **0.55 min / 1.86 MB**；四目标库合计约 2 小时、<20 MB。
但**精度上限有限**：同一张表里 FactorJoin 在 IMDB 上 P50 **13.86**、P90 **348.96**，远差于 PRICE 的 1.77/8.39。
它强在便宜 + 有上界保证，不强在精度。

R3 在协议上是禁区，但它可以作为**诊断上界**：单独测"若允许用目标库数据，精度能到多少"，
从而量化"跨库迁移本身损失了多少"。**此路线须用户明确批准，且结果不能写成我们方法的性能。**
