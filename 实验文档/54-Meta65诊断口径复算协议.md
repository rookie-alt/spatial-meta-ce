## 复算口径

1. 每个 `(db,K,run)` 按 query hash 排序配对，unique-query 分母不交叉取交集、不删失败行。标签用原 NPZ FP64，standard Q-error 按 pred/true 下界 1；Q50/Q95 在 Q-error 本身做 linear percentile，不使用 `exp(percentile(log_q))` 替代。逐 query 配对变化在 log-Q 上另报。
2. 主联合桶：真实基数 `<100 / 100-1e3 / 1e3-1e4 / 1e4-1e5 / 1e5-1e6 / >=1e6` × 表数 `1 / 2 / 3 / 4 / 5+`。另报 all-table、4+、各真实基数 × all/4+，以及 `<100 × 1-3` 和 `>=100 × 4+` 比较。所有桶计数和为完整 run 分母。
3. 每 run 报 n、分母占比、A/B/C Q50/Q95，以及 B-A/C-A/C-B 的分位数绝对差、比值、log10 比值、逐 query Δlog-Q 均值/中位数和变好/变差/相等数量。
4. `n<30` 标注 `below_min_n`，仍保留经验分位数但不作稳定结论；n=0 标注 empty、分位数 null。任何一个 run 空桶时，该桶五 run 主均值 null，不删除空 run 后求均值。
5. 主汇总为五 run 分位数的等权算术均值、均值之比；稳定性报逐 run 比值范围、Q95 变差 run 数、留一 run 后均值差为正的次数。support run 相关、同一 seed，不作显著性或独立泛化推断。
6. 独立字段 `pooled_run_occurrences_not_unique_across_runs` 复算跨 run 拼接分位数，专门对照旧 D1/D2。重复跨 run query 仅为出现次数，不能冒充全局 unique-query 分母，也不能替代主汇总。

## 判读与停止

“低基数 × 高表数”仅作事后描述性假说。比较其与低基数低表数、非低基数高表数及其他联合桶的绝对误差、配对变化和五 run 方向；发现反例必须写明，不把 marginal 两个结论当成交互证据。真实基数不能用于推理分流。尾部集中度相近不证明整体平移；现有臂间比较不分离元初始化和适应算子，不证明表征不足。

CPU 单进程、BLAS/OMP 各 1 线程、CUDA_VISIBLE_DEVICES 为空；远端硬 timeout=300 秒、客户端=360 秒，内存只加载单组 A/B/C 和一组 pooled（上限 2 GiB 预算，实际不声称已测）。输入不符、非有限值、缺 cell、重复/错配、空主分母或超时立即失败；不自动重试、不扩矩阵。远端脚本通过 stdin 内存运行，不写服务器，不反序列化 checkpoint；只将精简 JSON 保存本地新目录。
