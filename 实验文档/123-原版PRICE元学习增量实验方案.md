# 123 原版 PRICE 加入元学习：增量实验方案

日期：2026-11-16。状态：`design_only / execution_not_authorized`。

用户要求：先设计具体实验方案。本轮只形成方案及审查记录；文中运行数、阈值、资源上限均为设计值，不是执行记录。本方案独立于 122，不修改其冻结协议或绕过其停止条件。

## 1. 问题与最小研究范围

**保留完整 PRICE 的特征、模型、原生输出和 MSE，在同一个预训练起点上增加 FOMAML，能否改善 K20 适应后的精度，同时控制 K0 精度损失？**

首轮只改变后续训练方式。固定原版 256 维、每阶段 6 层、8 头、dropout 0.2 的 `RegressionModel`，约 10,709,330 参数；保留 PG 作为原输出头的输入，不增加 PG 残差锚，不加入 LoRA、结构摘要、尾部损失或容量搜索。元学习是训练流程，不是额外网络层。

这里有三个不同的判断：

1. 元训练后 K0 是否保住原有预测能力；
2. 元训练模型 K20 是否优于自己的 K0；
3. 元训练模型 K20 是否优于普通继续训练后微调，并优于共同起点 K0。

只满足其中一个不能声称元学习全面有效。K0 改善也可能来自元训练，不能预先判定 K0 与元学习无关。

## 3. 源验证查询：support、校准与报告永久分开

每库对 query_hash 去重；同 hash 的标签或特征冲突立即停止，代表行按 `(query_hash,id,source_line)` 稳定确定。数据库顺序固定 `(chembl,legalacts,telstra)`，索引从0开始；每库使用 `Generator(PCG64(SeedSequence([20261116,db_index])))`。保存 NumPy 版本、全部 ID/hash 与生成器状态，不依赖 Python 的随机 hash。

每库一次无放回排列后：

1. 前 100 条为保留支持区 S，顺序分成 5 个互不重叠的 20 条 block。
2. 接下来的 2,000 条为校准集 C，只用于下文规定的 LR 选择。
3. 其余全部 unique query 为报告集 R。所有臂、训练流、K 和 support run 共用同一 R。

K5 取相应 block 前 5 条，K20 取全部 20 条；每次只消费本 block 的标签。不重抽、不按误差/基数选择查询。S、C、R 的 query_hash 两两不交叠。计划构建可为去重一致性核验读取源缓存全体标签/特征，记录这一访问；“报告集关闭”专指所有 checkpoint 和校准决策封存前，不对 R 做模型前向、计算 loss/误差/指标或用其选择方案，不能声称从未接触 R 的标签字节。

五个支持block始终共享相同C或相同R，支持集合虽互斥，所得分数仍因共享查询和公共权重而相关；它们不是五个独立训练重复，不为制造独立性轮转/缩小查询集。

按已有 unique 数量推导，R **计划值**为 chembl 47,900／legalacts 47,404／telstra 47,900，共 143,204；须执行前重新认证，不能把历史值当本轮实测。不把新 R 的绝对数值与旧 149,204-query Qd 混作同条件比较。

## 4. 原版 PRICE 语义与模型模式

- 输入：原四组特征、40 桶、原 mask 和 `-1000` padding；table padding 首维为 0。
- 缓存 fanout 在 batch 中已做 `log1p`，原版输入按现有 [PriceAdapter](../spatial_meta_ce/baselines.py) 还原一次，避免重复变换。
- PG 输入保持现有适配器的 `logaddexp(pg_log,0)+1`；标签为 `z=log1p(true_card)+1`。支持和查询都使用原生 z 空间的逐样本 MSE 均值。
- 原版预测 z 通过 `price_log_predictions` 解码成标准 log prediction，再计算标准 Q-error。禁止把 z 当 `log(card)` 或使用 PRICE-style 残差输出路径。
- E 的监督前向、M 的适应后 query 前向为 `train()`，保留原 dropout 0.2。
- M 的 support 内循环以及所有评估适应/预测均为 `eval()`，以匹配部署时的适应算子；`eval()` 不关闭梯度。上下文退出后恢复每个模块原模式。
- 所有评估 run/K/数据库均从相应公共 checkpoint 重置。fast weights 不写回公共模型，不跨任务累计；缓冲区也不得被任务修改。

首轮保留以上模式，不额外扫 dropout；M 的 query 训练仍有随机正则化，不能声称训练与推理所有操作完全相同。

## 5. 三臂与固定训练配方

| 臂 | 后续训练 | 评估 |
|---|---|---|
| P：共同起点 | 不做后续训练 | K0、K5、K20；普通微调参考 |
| E：普通继续训练 | 同一 P，普通监督训练 | 同上；排除继续训练本身的收益 |
| M：元学习 | 同一 P，FOMAML post-only | 同上；唯一候选 |

E/M 各用后续训练流 **42、43、44**，共 **6 次后续训练**。P 只有一个权重，不复制为三个独立模型。六次运行均事前列入，不按流 42 的效果决定是否补其余两条。

| 固定项 | 设计值 |
|---|---|
| 更新与任务 | 每运行 2,000 次 outer update；meta_batch=4，4 个任务串行累积后更新一次 |
| 数据采样 | 23 库等概率；每任务 K=20、query=64，库内按 unique hash 无放回、不交叠 |
| 计划 | 每训练流 8,000 个任务，E/M 共用相同 S/Q 身份与顺序；采样 RNG 与模型/dropout RNG 分离 |
| 外优化器 | 新建 Adam，LR `2.85e-5`、weight_decay `5e-5`、betas `(0.9,0.999)`、eps `1e-8`；不继承 P 的优化器状态 |
| 梯度处理 | 四任务损失等权平均；outer gradient norm clip=1.0，两臂相同；不裁剪 inner gradient |
| 内循环 | M 用全参数 SGD、5 步、MSE，LR α 按 §6 校准后冻结；无 momentum、无 inner weight decay |
| checkpoint | 只用第 2,000 次更新的 `last.pt`；训练中无验证、无早停、无 best 选择 |
| 精度与调度 | FP32，无 AMP／调度器／动态 accumulation；不得按结果延长某臂 |

训练任务生成器固定为 `Generator(PCG64(SeedSequence([20261116,123,stream_seed])))`，数据库顺序沿用配置中的 train 列表，每库的 unique 代表行排序同 §3。不同任务允许再次抽到同一查询；无放回约束作用于单个任务的84条查询，不表示跨2,000更新耗尽后停止。模型/dropout RNG用对应stream_seed初始化，E/M任务顺序配对但不声称全部dropout mask相同。报告推理batch固定128，最后不足128条原样保留。

两个训练目标为：

```text
E: L_E = mean_(S∪Q) MSE(f_θ(x), z)

M: φ_0 = θ
   φ_(j+1) = φ_j - α stop_gradient(∇_(φ_j) mean_S MSE(f_(φ_j)(x), z)), j=0..4
   L_M = mean_Q MSE(f_(φ_5)(x), z)
```

`stop_gradient` 只作用于内梯度（`create_graph=False`）；φ 到 θ 的恒等梯度路径保留，不能 detach 整个 φ 或 query loss。所有基础参数都接受 outer gradient。只做 post-only，不因 K0 下降临时加 joint 目标。

**成本与解释**：每臂每流见到的独立标签身份相同，但 E 对 S∪Q 监督、M 多次用 S 且对适应后 Q 监督，属于完整训练配方比较。E 每流计划样本呈现 672,000；M 为 1,312,000（不含额外日志前向），另记实际 forward/backward、重复支持呈现、更新数与墙钟。相同 outer update 不等于等计算成本，不声称纯机制因果或成本更低。

## 6. 有限 LR 校准与强基线检查

### 6.1 训练前选共同 α

只在 P 上，使用 S 与 C，对 `α∈{1e-7,1e-6,1e-5}` 做全参数 SGD 5 步、K20、5 个 block 的校准。该集合是限制成本的预注册搜索范围，偏向较小步长；历史普通微调的 LR 搜索使用过不同损失，不能据其推导MSE安全区间、换算最优步长或声称范围覆盖最优点。`1e-4`不属于本轮候选，并非已证明它在MSE下不可行。若最小分数在边界，记录 `lr_boundary_selected=true`，仍按当前范围执行，不事后扩网格；失败只否定这一受限配方。

对每候选 `β`，定义 `cbar[a,s,d,β]=(1/5)Σ_r Q95_C[a,s,d,β,r]`，`J[a,β]=mean_(s,d) log(cbar[a,s,d,β])`；P只有一个s。最小J者为α，J与最小值绝对差≤`1e-8`时取更小LR。此处及§6.2均先在支持抽样上算术平均Q95，再取log并对库/训练流等权平均，与§7同一聚合顺序。候选出现非有限则完整记为rejected，不从失败单元删查询重算；三个候选均失败则停止当前配方。

共 `3 库×(1 K0+3 LR×5 block)=48` 个校准单元；R 不打开。α 固定用于 M 的训练内循环及 P/E/M 的主评估适应。即使 P 微调不如 K0，也不因此否决“元学习能否改善适应”这个问题；记录该事实并依 §8 的强比较判断。

共同α定义的是“同一适应算子下的训练配方效果”，不假定它对P/E/M分别最优。M正是在这个固定α下元训练；M相对自身K0和相对E的方向不同时，报告具体权衡，不能未经干预验证就命名为“LR伪效应”。校准和报告保留每个support block的原始Q95、support适应前后MSE及梯度范数供诊断，不用这些诊断追加选参。

### 6.2 所有训练封存后，额外优化 E 的微调 LR

为避免主比较只赢一个适应配方不合适的 E，在六个 last 的 SHA 封存后，用相同候选集合在 **E 的 C 集 K20** 上选择一个跨三训练流共享的 α_E，使用上文J公式及平局规则。校准不改变 E 权重或 M 配方。

另需 E 的 C 集 K0：这一阶段最多 `3流×3库×(1+3×5)=144` 个单元。主比较仍使用共同 α；另外报告 E(α_E) 的 R 集 K20，并将其作为 §8 的收益保护。若 α_E=α，复用结果，不重复增加独立样本。

只给 E 增加这项预定强基线检查；不为 M 再扫 outer LR、步数或 α，不把这个固定配方结果描述为“双方全面调优后的算法上限”。E 的候选只要任一校准单元非有限，该候选整体rejected，不能删除单元后选择；三候选均失败则停止源报告。任何非有限的主 α 单元使主矩阵 invalid，不能用 α_E 偷换主对照。

## 7. 评估、指标与“差多少”的计算

源侧评估固定 K={0,5,20}；K20 为唯一主终点，K5 为诊断。每模型／库 K0 只预测一次，K>0 各 5 个独立 support block；完整遍历 R 后计算分位数，不平均 batch Q95。

主矩阵：P 的 33 单元，加 E/M 的 `2×3×33=198` 单元，共 **231**。E(α_E) 最多增加 45 单元，报告矩阵最多 **276**。校准最多 192 单元另列，不与报告矩阵或训练重复混计。

标准指标沿用 [metrics.py](../spatial_meta_ce/metrics.py)：

```text
ell_i = abs(max(decoded_log_pred_i,0) - log(max(true_i,1)))
q_i = exp(ell_i)
Q95 = numpy.percentile(q_i,95,method="linear")
```

逐库完整报告 Q50/Q90/Q95/Q99、五个support block原始指标及其SD、分母、逐查询配对 log-error 差、恶化查询比例、适应/推理成本。支持抽样SD只描述给定公共权重/查询集的变化，不当作五个独立训练重复。`price_shifted_q*` 和 `percentile(ell,95)` 只作独立诊断，不冒充标准 Q95。

对臂 a、训练流 s、库 d、K k：

- `qbar[a,s,d,0]` 为唯一 K0 Q95；K>0 为五个 support Q95 的算术平均。
- 聚合分数 `L[a,s,k]=mean_d log(qbar[a,s,d,k])`，对应几何均值 `G=exp(L)`；三库等权，不跨库 pooled。
- 主配对差 `Δ_s=L[M,s,20]-L[E,s,20]`；报告比值 `exp(mean_s Δ_s)` 和相对变化 `100×(exp(mean_s Δ_s)-1)%`，负值表示改善。
- P 以同一参考值参与每条配对差，不能将其复制值当三个独立预训练重复。另报每库三训练流 `qbar` 的均值、范围及各流原值，support 方差单列。

这套聚合是本方案新定义，既不等于 Q95 的跨库算术平均，也不等于旧 122 的 `log_q95` 平均。报告同时给出三库 Q95，不能用聚合隐藏单库恶化。

“差多少”最终分别给出 M0/P0、M0/E0、M20/M0、M20/E20、M20/E(α_E)20、M20/P20、M20/P0、M20/E0 的比例。均由同一 R 计算，不与历史不同 population 的数字相除。

## 8. 事前决策与失败停止

以下 5%／10% 是本轮开发性操作阈值，不是预测、功效估计或显著性检验；不按结果修改。

`promising_source_screen` 必须同时满足：

1. **适应后相对收益**：M20/E20 聚合比值 ≤0.95，且至少 2/3 配对训练流改善；M20/E(α_E)20 和M20/P20也均≤0.95。E(α_E)是预注册的额外强基线检查，M未作同等事后α搜索；不将通过解释为双方全面调优后的算法优势。
2. **有用的适应**：M20/M0 聚合比值 ≤0.95，至少 2/3 训练流改善；M20/P0及M20/E0聚合比值也均≤0.95，防止只胜过被微调或继续训练拖坏的基线。
3. **K0 保护**：M0/P0 及 M0/E0 聚合比值均 ≤1.05。
4. **逐库保护**：用各库三训练流的平均 qbar，M0 对 P0/E0、M20 对 M0/E20/E(α_E)20/P20/P0/E0 的 Q95 比值均 ≤1.10；同口径 Q50 也均 ≤1.10。P 为单一参考。新增P20/E0比较直接使用已有矩阵，不新增运行。

部分正向但未全过为 `partial_source_signal`；主 M20/E20 无正向平均收益为 `no_source_gain`。任何缺格、来源错配、S/C/R 重叠、非有限或分母不一致为 `invalid`，不当成科学负结果。

逐格负迁移按“适应后 Q95 > 自身 K0”计数并完整报告；不能用聚合正向声称所有库/支持集都改善。阈值通过最多支持当前初始化、当前开发集下继续确认，不自动打开目标库。

科学门未过则结束本配方：不自动加步数、换初始化、换 loss、扫 LoRA 或读目标找收益。工程错误停止并保留首次失败证据；修复后须重新审查、绑定并明确获准重启，不覆盖旧 run 或自动恢复。资源超限不自动放宽预算。

| D3：校准 | 生成 S/C/R 身份；只读 P 的 S/C，完成48单元，封存 α 与6运行计划 | 全部输入 SHA、成本预算、授权绑定完整 |
| D4：正式源训练 | E/M 三条训练流、各2000更新；训练不读取验证库 | 六个 last及运行完成证据全部封存 |
| D5：源报告 | E 的144单元C校准，冻结 α_E；再运行最多276个R单元、独立复算 | 完整矩阵、判定与失败记录；不自动目标评估 |

D2 拟定硬上限：1 张确认空闲的 RTX 3090、VRAM 12 GiB、RSS 24 GiB、总墙钟 30 分钟、输出 512 MiB。只能用训练库作计时，使用新临时副本，探针权重不进入 D4。探针inner LR固定 `1e-6`，仅验证数值/成本，不据其精度选配方；校准出的α不同时，在D3后对真实α补做最多2更新闭环并重新绑定，不把探针权重接入正式训练。

两臂各50-update计时使用封存训练任务前缀，并额外记录训练库实际token长度接近冻结容量的批次成本、20条support的5步适应成本、batch128推理/写CSV成本、2,000查询与完整训练库约50,000查询推理成本。采用实测覆盖的较保守值外推C/R，列出更长R长度/首次装载的未覆盖风险；不从目标或R的误差选择计时样本。若探针在30分钟内不能给出可信成本，就停止，不无限加探针。

D3–D5 **成本接受上限**拟定为合计 16 GPU 小时、单训练 run 2 小时、每评估单元 120 秒、VRAM 12 GiB、RSS 24 GiB、总输出 6 GiB；这是可行性上限，不是已有授权或实测耗时。正式预算须在 D2 后用实际数值生成并覆盖校准、启动、缓存扫描、checkpoint、审计与独立复算，不能只算训练循环：

```text
T_plan = 1.3 × [T_setup_and_io
               + 3×2000×t_E_update + 3×2000×t_M_update
               + (48+144)×t_C_cell_upper + (231+45)×t_R_cell_upper
               + T_verification]
```

`t_E_update/t_M_update`各为一条训练流的一次完整outer更新秒数，包含4个串行任务，因此两个`3×2000`分别覆盖E/M各三次运行，没有漏计。C单元含支持适应与2,000条校准推理，R单元含支持适应与完整R推理，二者数据不同不能当重复成本。144个E校准单元无论α_E是否等于α都需先运行才能完成选择；仅额外45个R单元在二者相同时可复用。`t_*`用测得的保守批次/任务长度上界，记录取值来源和启动开销；30%余量不是置信区间。若T_plan不满足16小时或单项/输出上限，停止并另修预算或明确缩小协议，不能悄悄减少任务、query或训练流。

按历史记录，普通 PRICE 4000步耗时640.75秒；它没有元学习内循环、采用不同 batch，**不得据此承诺本方案耗时或显存**。先计时再决定执行预算。

主报告预计至少 11,026,708 行预测；E额外LR不同则最多13,174,768行，校准另约384,000行（均为按计划分母推导的设计值）。用探针实测字节/行核对6GiB上限；逐行审计文件可压缩，不删失败或坏查询。

资源监督必须覆盖 worker 子进程组的实际 RSS/墙钟/输出，记录当前阶段、首异常与清理结果。不能因旧122 runner存在就声称它已支持本原版模型/原生标签/新计划。尚无可直接执行的合规命令，本轮不伪造启动脚本。
