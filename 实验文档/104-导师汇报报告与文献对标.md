## 2. 为什么需要一份 all-rows 面板

本项目主指标（doc 25 §1.2）是 **unique-query Q95**；PRICE 论文 Table 2 报的是同一误差量在 **all-rows** 总体上的分位。两者是同一批数据的不同总体，不能直接混排，但把总体对齐后可以直接放进同一张表。

`allrows_target_eval.py` 做的就是对齐，并且**顺带当复现检查**：它的 PG 列来自缓存里的原始 PostgreSQL 估计、不含任何模型，所以四库都必须落在论文数值上。实测四库最大差 0.04%（ergastf1），PRICE 列四个分位也全部吻合（Q50 最大差 0.40%、Q90 0.06%、Q95 4.55%、Q99 1.05%）。Q95 的 4.55% 出现在 imdb，是该库尾部插值位置差异。

脚本内置曝光守卫：从 checkpoint 的 `state["metadata"]` 读 `train_databases` 与 `validation_databases`，与 `--databases` 求交，非空即拒绝运行。四目标库都不在并集里。

## 4. 文献调研结论

完整书目、口径、留出方式、可引数值与未核实项见 `实验文档/results/p2-2-allrows-lit-20261022/related_work.json`。要点：

1. **整库留出零样本这一设定，公开工作里只有三条线**：PRICE（PVLDB 18(3), 2024，已发表）、arXiv 2502.14350（同设定但**已于 2025-05-28 被作者撤回**，理由为数据集质量问题；其 ErgastF1 行与 IMDB 行逐位相同）、以及本项目。也就是说直接同行对手基本只有 PRICE 一个。
2. **CardOOD**（VLDB Journal 35(4), 2026）：OOD 指同库内的查询工作负载偏移（谓词配比 / join 数 / 整模板留出 / 表数留出），**没有整库零样本**。q-error 口径与我们恒等（`max(c/ĉ, ĉ/c)`，两侧下取 1），可同列比大小，但设定不同，不能用来证明谁更强。
3. **GRASP**（PVLDB 18(8), 2025）：留出的是 **join 模板**而非数据库，同库训练同库测试。它证明「不访问数据库数据」也能强，并报了端到端时间（CEB 上 135% vs PG 176%）。
4. **AHCE/DACE**（ESWA 276, 2025）：依赖 PostgreSQL 直方图等数据侧元信息，违反本项目「不看目标库数据/统计」的约束；全文在付费墙后，Q95 定义与表格数值**均未核实**，报告不引用其数字。
5. **LLM-CE**（arXiv 2603.28080, 2026-03）：与本项目同为四库，但统计单元是整条查询。它的脚注 3 明确写出 **PRICE 的 Q-ERROR 算在分解后的子查询上**——这正是我们 all-rows 面板所对齐的单元。

### 4.2 两个常见的引用错误

- **BIRD 没有基数指标。** 全文 grep `cardinal` 命中 0 次，也没有 Q-ERROR；它报的是执行准确率 EX 与 VES。任何「BIRD dev 上 PG 原生 Q95」的说法都缺乏文献依据。
- **不要在倍数口径上再做 exp。** q-error 本身已是 `exp(|Δln|)`；`percentile(exp(x),95) = exp(percentile(x,95))` 只在同一批误差、同一插值规则下恒等。本项目实测整库差 ≤1e-7，但 118 条的 4+ 桶差 2.68%——两套数字各自成立，不可互相替代。

## 5. 必须主动说明的缺口

> **2026-10-26 更新：本节描述的缺口已由 110 号补上。** 110 号实测了三层延迟，结论是**前向单项快 34.5–38.1×（CPU，按 110 §3.1 的 ERM 补位口径）/ 15.6–16.6×（GPU），整条估计链快 3.7–7.5×，但真实 PostgreSQL 执行时间无可测收益**（四库比值 0.966–1.004，注入精确真值也只到 0.975–1.005）。所以「参数少不等于更快」这句话现在有实测支撑，而不只是谨慎措辞。详见 110 号（含其 §0 的口径勘误）与报告第 08 节。

**（10-22 原文，保留作历史记录）我们没有测推理延迟与端到端时间。** PRICE 报推理 5.3–14.1 ms/查询、E2E 在 stats/ergastf1/genome 三库最优；GRASP 报 CEB 上相对 True-Card 135%、PG 176%；CardOOD 报 DSB 上 0.634 倍 PG。我们只报误差。参数少 80.80×（10,709,330 vs 132,545）**不等于更快**，汇报时不能把参数量差当成效率优势。

   按本表直方图分桶」，不是乘积。已改为该表述，并在表下补一句说明（含「不是两侧行数的乘积」）。
