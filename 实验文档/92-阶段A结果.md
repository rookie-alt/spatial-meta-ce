## 0. 结论

**整体判定：`not_predictable_from_support`。**

按 91 号 §5 的 n=50 判据，三库中 telstra 的全部特征 `|ρ| < 0.5`（最强 `0.404`），
因此整体判为不可由 support 成分预测。chembl（最强 `0.522`）与 legalacts
（最强 `0.579`）落在 `[0.5, 0.8)` 的中间带，单库判为 `inconclusive`。
按 90 号 §3 与 91 号 §10，**阶段 B 失去依据，本轮就此停止，不进入阶段 B**。

**必须同时写在结论旁边的三点：**

1. **n=5 与 n=50 的结论相反，且 n=5 是假象。** 三库在 n=5 上全部判为
   `predictable_by_support_composition`（最强 `|ρ|` 分别为 chembl `0.900`、
   legalacts `0.900`、telstra `1.000`），扩到 n=50 后全部跌到 `0.522 / 0.579 /
   0.404`。这正面验证了 91 号 §5「n=5 只作方向提示」的限定：5 个点上的高相关
   是小样本秩相关的结果，不构成 support 可预测的证据。
2. **这不证明 support 无影响。** A3 显示 support 抽样带来的 run 间差异极大
   （legalacts `better_share` 从 `0.0306` 到 `0.8578`），90 号 §1 的定性观察成立。
   本文件只否定「用 A1 这 9 个可观测特征、以 Spearman 线性秩相关就能预测收益」。
3. **判据是相关的，不是因果的。** A2 做的是相关分析（90 号 §3-A2 明确「不是回归
   预测」）。`|ρ| < 0.5` 不能排除非线性、交互或未观测成分的影响，只能说这 9 列
   特征在本样本上没有线性秩关联。

## 5. A1：support 特征刻画

每个 (库, run) 的 20 条 support 计算 9 个特征列：

| 特征 | 定义 |
| --- | --- |
| `tables_4_share` / `tables_5_share` / `tables_6p_share` | `n_tables` 在 4 / 5 / ≥6 的占比 |
| `true_tercile_share_1..3` | 落在该库全体 low4 真实基数三分位的占比 |
| `pg_dev_tercile_share_1..3` | `|PG−true|/true` 三分位占比 |
| `pg_over_share` | `PG > true` 的占比 |
| `group_len_mean` | 组 0 与组 3 的 token 数（逐行、两组平均） |
| `log_cartesian_mean` | 组 2 首列 `log1p` 之和的逐行均值 |
| `low4_share` | support 中 low4 查询占比 |

三分位阈值取**该库全体 low4 查询**（不是 support 自身），与 89 号 §4 的
`tercile_ids` 同一算式（`100/3`、`200/3` 分位，`method="linear"`）。
`true` 只用于定义桶与 low4 掩码，未用于给 support 打分或排序。

## 7. 限制

1. **每次抽样的 query 不同。** 91 号 §0 已指出：support 与 query 必须互斥，
   所以 50 次抽样各自有 49,404 / 49,900 条 query。50 个点之间不能逐条配对，
   只能比分布。本文件的所有分布统计都按此解读。
2. **A2 只做线性秩相关。** 未做非线性、交互项或多元模型。`|ρ| < 0.5` 只否定
   这 9 列与收益的单调秩关联。
3. **A1 的特征不代表全部可观测信息。** 例如查询的具体 join 结构、谓词选择性
   等都未纳入。
4. **bootstrap 的次数估计依赖 ±10% 口径。** 换口径（如 ±5%）会显著改变所需
   次数，本文件未做敏感性分析。
5. **CPU 与 GPU 的数值差异仍在。** 前向最大差 `1.907e-6`，对 50 点分布的影响
   未单独量化；该量级远小于分布本身的跨度（如 legalacts `better_share` 跨度
   `0.83`），但这是判断，不是测量。
