3. 按 297 单元执行 source-only 评估；K0 唯一、K>0 五个 run；Q95 从完整 Q_d 重算，不平均 batch Q95。

任一情况立即停止并保留失败证据，不 retry/resume/换卡/改配方：NaN/Inf、OOM、超时、输出超 4 GiB、SHA/config/身份错配、目标库访问、正式训练读取 validation 库、support/query 重叠、缺格、非 last checkpoint、非 4000 步。单个训练或评估失败即使整个矩阵不完整，标 `invalid`，不把它当科学负结果。

### 4.1 执行前提（当前未满足）

当前 `scripts/run_fomaml_joint_source.py` 只负责串行编排 9 个训练 run（评估由 `evaluate_fomaml_joint_source.py` 另行驱动），这些脚本本身不设 timeout、RSS、VRAM 或输出硬限；因此本文的 43,200 / 3,600 / 600 秒与 8 GiB VRAM / 12 GiB RSS / 4 GiB 输出只是申请上限，尚不能强制执行。正式启动前必须补齐外层 supervisor，至少满足：

- 每个训练 run 建一个 child，单 child 3,600 s；每个评估单元建一个 child，单 child 600 s。若 `evaluate_source` 仍一次处理 33 个单元，必须先拆分或提供单元级入口，否则 600 s 不能算硬 timeout。
- 训练 supervisor 以 9 次独立 run 调用（每次一个 arm/seed 输出目录）实现，或小改现有 runner；不得在一个进程串行跑完 9 个 run 后再套单 run 3,600 s timeout。9 次独立调用后，由 supervisor 汇总各 `run_protocol.json` 生成总 `runs.json`。
- 父进程累计 wall time 到 43,200 s 时终止所有 child。
- 每个 child 用 `torch.cuda.set_per_process_memory_fraction` 或外部 nvidia-smi 监控 8 GiB VRAM；轮询 `/proc/<pid>/status` 的 RSS，超 12 GiB 即终止。
