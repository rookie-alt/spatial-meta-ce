# 04 适应策略源验证搜索与冻结评估（2026-09-27）

## 1. 目的

只在源验证库（chembl / legalacts / telstra）上选本项目的适应策略，冻结后再跑目标库，检验能否消除 STATS 负迁移。目标库在选择阶段不读取。

## 2. 设置

| 项 | 值 |
|---|---|
| 脚本 | `scripts/adapt_strategy_search.py`（选择）、`scripts/eval_frozen.py`（冻结后目标评估） |
| checkpoint | `runs/formal-fomaml-20260925-seed{42,43}/best.pt` |
| 网格 | steps 0/1/3/5/10 × lr 1e-4/3e-4/1e-3/3e-3/1e-2 × scope head/all × 保守回退 off/on，共 81 组（step=0 去重） |
| 保守回退 | support 二折交叉：适应后留出折 loss 不低于未适应则回退零样本（只用 support 标签） |
| 验证 episode | 3 库 × K∈{5,10,20,50,100} × 5 次 = 75，`plan_seed=2718`（≠ 训练早停用的 1729） |
| 指标 | macro mean log-Q95，两个 checkpoint 取平均 |
| 平局规则 | 差 < 1e-4 时：步数少 → head 优先 → lr 小 → 不回退 |
| 设备 | 单卡 3090（卡 1），搜索约 5.5 分钟；目标评估两 seed 并行（卡 1/2）约 4 分钟 |

## 3. 源验证结果

| 策略 | macro log-Q95 |
|---|---:|
| 零样本（steps=0） | 2.7013 |
| 旧默认（5 步, 1e-3, all） | 2.6623 |
| **选定（3 步, 1e-3, head）** | **2.6597** |
| 最佳回退策略（10 步, 3e-4, all） | 2.6735（接受率 51%） |
| 最差（3 步, 1e-2, all） | 3.072 |

要点：
- 前 8 名差距 < 0.003，远小于 seed 间差异（0.008），**源验证对这些配置基本不可区分**。
- lr=1e-2 在源验证上明显劣于零样本，是唯一被清楚排除的区域。
- 保守回退在源验证上**没有收益**：接受率约 50%，说明 K≤100 的二折 support loss 噪声太大，不能可靠判断适应是否有益。

## 5. 结论

1. **STATS 负迁移未消除**：冻结策略把恶化幅度减小（s43 K=5：106→93），但所有 K 仍劣于零样本 74.5/79.3；配对改善比例 s42 30~40%、s43 12~21%。
2. **代价是 genome 收益变小**：更保守的适应（3 步、只调 head）让 genome 的 Q95 从 143~163 回升到 191~208（s42）。
3. 按协议，**正式报告用冻结策略**（源验证选出），不能因为目标库上旧默认 genome 更好而换回。两者差异本质上是"适应强度"的取舍，源验证无法分辨。
4. 调超参这条路已基本穷尽：STATS 问题不是适应步长/范围能解决的，更可能来自表示层（池化丢失 join 结构）或 STATS 与源库分布差异过大。下一步应转向 P1（第 3 个 seed）和 P2（join 结构编码）的证据收集。
