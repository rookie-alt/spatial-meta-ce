## 1. 问题与既有证据

本协议接续 [P1 映射消融正式协议](12-映射消融正式协议.md) 第 14–15 节，不是新的 join 结构实验。P1 正式九臂结果不变，保留 `sum` 参考基线。

P1 已证明的范围：

- 三源冻结审计与 sidecar 覆盖 149,504 条唯一查询，标签并集仅有 `EQ/LT/GTE`；这来自既有标签管线，不是独立全量语义认证。
- 4+ 表主桶中 10,884 条 `multiple_filters` 查询已从原始 SQL 重解析。12,271 个同列重复过滤列均为一个 `GTE` 与一个 `LT`，标记子集无 OR、反向或空区间。
- 在上述范围列上，独立直方图插值与缓存选择率的最大绝对差小于 `3e-8`；按缓存 token 重算 AVI/MINSEL/EBO 与缓存表级聚合的差小于 `7e-8`。这是**冻结统计到特征的数值自洽性**，不是数据库真实过滤比例的准确性证明。
- 所有被核验区间都落在直方图范围内；合成边界测试不能冒充真实 workload 已覆盖边界分支。

P2 分开回答三个问题，状态分别记录，不允许互相代替：

| 子项 | 审计问题 | 独立参照 |
|---|---|---|
| P2-A：全量重解析与身份对齐 | 未标记查询是否也符合既有标签、映射与布尔结构描述？ | 从原始 SQL 自行构建 AST、别名解析与谓词清单 |
| P2-B：语义与编码契约 | 对确定的 SQL 类型、NULL 和边界规则，缓存编码是否忠实表达支持范围？ | 独立布尔语义实现、固定测试表与 PostgreSQL 执行结果 |
| P2-C：真实选择率 | 冻结统计给出的选择率与同一数据快照的真实行过滤比例相差多少？ | 真实源表上的精确 `COUNT(*)`，而非直方图、PG 估计或查询基数标签 |

**独立性分层**：另写审计逻辑但仍用 SQLGlot，只能称“实现独立、解析器共享”；PostgreSQL 实际执行才提供另一套引擎语义参照。两者都必须保留版本与共享假设，不能统称完全独立。

## 4. P2-A：逐条全量重解析

### 4.1 独立审计路径

从每一行原始 SQL 建 AST，独立遍历 FROM/JOIN/WHERE，解析 table occurrence、schema、alias、列归属、列间连接与列—常量过滤。可用固定版本 SQLGlot `read='postgres'`，但不得调用 `parse_price_sql`、vendor 提取器或 sidecar 的解析结果来生成参照；后者仅在参照完成后作为被比较对象。

不得只统计谓词类型集合。必须记录完整布尔树、括号、AND/OR/NOT、操作符、常量原文、类型转换、左右操作数、NULL、重复同列谓词，以及 WHERE 和 JOIN ON 的归属。区分列—列连接与列—常量过滤；`10 <= x` 等反向写法需独立规范化，不能依赖旧标签中只有 EQ/LT/GTE 的先验。

必须显式发现并分类 `IN/BETWEEN/LIKE/IS/NEQ`、函数、算术、子查询、外连接、自连接、带引号标识符及无法解析/消歧的引用。没有在数据中出现只意味着实际覆盖数为 0；出现而超出契约时记录 unsupported，不降级成普通范围。

### 4.2 比较与输出

- 独立 counts、table occurrence、join/filter 列及归属与冻结 sidecar/cache 对比；token 对齐按独立列身份与缓存位置进行，不能以 sidecar 同序即一致作循环证明。
- 单独报告同列多条件的真实约束：交集/并集、端点开闭、相等/反向区间、多个 EQ 的一致或矛盾、NULL 语义；尤其覆盖此前未标记的查询。
- 逐数据库、表数、独立谓词类别、标记/未标记、原始行/unique-query 口径报告覆盖及不一致。独立标签与旧标签的交叉表必须有完整分母；不能把多个可重叠 flag 相加当互斥查询数。
- 全量结果保留行级状态与有限个确定性示例，不以头中尾抽查替代全量。若解析失败或语义不支持，仍计入总分母。

**A 通过条件**：150,000 原始行身份覆盖与 149,504 唯一查询口径经核验；全部可独立解析/消歧；counts、列身份/归属及既有布尔结构描述无未解释差异。否则为 `failed/partial`，不能写“全量语义正确”。A 通过也不等于 B/C 通过。

## 5. P2-B：SQL 语义与数值编码契约

### 5.1 独立参照

把 A 的布尔树转为带类型、NULL 三值逻辑的参照，不照抄 vendor 按运算符固定次序取界的实现。`WHERE` 仅保留 TRUE；FALSE 与 UNKNOWN 均不保留。实际列类型、隐式/显式转换、collation、时区和数值精度来自源 schema，不从 float 化的统计值猜测。

在**隔离的项目测试数据库**准备固定小表（不是替代源数据），以 PostgreSQL 执行结果核对参照真值与过滤行集合。记录测试表内容、建表 SQL、版本与预期结果。源数据库缺失时，这仍只能证明合成用例的语义，不证明真实 workload 类型上下文。SQLGlot AST 检查与 PostgreSQL 参照的共享/非共享部分分别登记。B 的固定合成参照自检与离线编码检查可在 G0/A 后开始；真实 workload 的类型语义认证必须等 G1 来源身份通过后才能完成。G1 的授权盘点不以 B 完成为前提，且不能在盘点前对未经来源核验的数据进行 workload 计数。

固定合成用例至少包括：

1. 无过滤、EQ、LT/GTE 及互换左右操作数；端点内外、端点相等、空区间。
2. 同列多 EQ（相同/冲突）、同类型多界、不同列 AND、带括号 AND/OR/NOT。
3. NULL、NULL 常量比较、IS NULL、整数/小数/文本/日期/时间、转换失败与带引号列名。
4. JOIN ON 与 WHERE、内/外连接、自连接、IN/BETWEEN/LIKE/NEQ、函数/算术、子查询。
5. 直方图最小/最大边界、越界、重复边界、空桶、空表、统计中的 NULL 与总行数不一致。

应分别断言“参照正确”和“生产表示能/不能表达”；已知不支持的合成反例可以作为期望的限制测试通过，不能因此宣称生产表示支持。合成反例未在冻结 workload 出现时，只记表达上限，不归因于本批预测误差。

### 5.2 特征比较

- 分开核对过滤列 token 的规范化上下界、端点语义、等值摘要定位/频率与选择率，以及 token→table 归属。不可只验最后一维就认证整个 token。
- 从同一冻结统计独立重算所有实际出现的过滤列选择率，包括单 EQ、单边范围及同列多条件；无法在冻结统计下定义的模式报 unsupported，不随意设为 0/1。
- 独立重算 AVI=`∏s_i`、MINSEL=`min(s_i)`、EBO=选择率降序前四项 `∏s_i^(1/2^i)`；无过滤时均为 1。比较缓存 `group2` 对应维度，分清数值契约与统计建模假设。
- 浮点重算统一 float64，缓存差异容差固定为最大绝对差 `1e-6`；SQL 真值、行集合、离散身份必须精确一致，不用浮点容差掩盖语义差异。报告全部差值、非有限数、越界值与分母异常，禁止裁剪后对比。
- 数据未触发的分支标为 `synthetic_only/not_observed`，不是覆盖完成。缺 schema 或 PostgreSQL 执行参照时，相关语义认证为 `blocked`，不是“推测通过”。

**B 覆盖分母**：在任何编码比较前，按 A 的独立身份冻结每条唯一 query 的 table occurrence、过滤列布尔束及预期 token/表级聚合槽位清单；缺失 token 仍是待核验槽位，不能从缓存中枚举已有槽位作为完整分母。分别报告合成用例数、实际类型/操作符/布尔模式上下文数、过滤列束数、表级束数，以及各槽位的已核验/不一致/unsupported/blocked/未执行数量。原始行映射另报，不让重复行加权唯一查询结果。真实类型/模式清单包含零出现项但标为 `not_observed`，不计作实际覆盖；固定合成用例只计入参照自检。凡实际槽位缺类型上下文、无法表达或超出统计契约，都保留身份与原因，不能折叠为“通过”。

**B 状态分开记录**：参照自检、真实 workload 语义覆盖、冻结统计编码一致性。只有固定参照用例全部符合预期、真实上下文及槽位全覆盖、实际 workload 无 unsupported/blocked/未解释差异且编码差在冻结容差内，才可写 B 完成；合成反例的预期限制通过不等于真实 unsupported 通过。统计编码一致不要求 C 的真实误差为零；AVI/MINSEL/EBO 是组合估计，不承诺准确表达列间相关性。

## 6. P2-C：真实表过滤比例

### 6.1 数据可用性门槛 G1

**当前未确认真实源表或可只读访问的数据库可用，本协议不将其视为已具备。** 未来先盘点源 schema、原始数据来源、各表总行数、NULL 比例、类型、编码/collation、时间与快照身份。

必须核验**源数据版本→导出/数据库加载→冻结统计生成→当前只读表**的可信身份链：原始发布版本/不可变快照、各表数据与 schema 的导出哈希、加载记录，以及生成 P1 冻结统计的输入 manifest、生成程序/配置/版本和输出哈希须可互相绑定。数据库不可变快照标识只有能追溯到上述冻结统计输入时才足够；本轮新建 manifest 不能倒推出历史来源。若没有历史 manifest，可用既有可信原始导出建立等价证明，但必须逐表认证当前数据内容及 schema，并在不替换冻结统计的前提下证实其由该输入生成。仅有相同表名、相同 size、当前表的新哈希或当前统计的新副本均不够。身份链缺失、只能获取另一版本或抽样表时，记录 `blocked_snapshot_unverified/blocked_snapshot_mismatch` 原因，状态为 `blocked`，不得给出 P2-C 同版本精确参照结论。不得在原 PRICE 目录安装、导入或写数据；若需另建源数据副本或重现统计生成以认证历史来源，作为额外任务授权。

精确计数采用同一只读一致性快照，记录事务隔离与开始/结束；统计若来自采样，显式区分采样估计与全表分母。空表分母为 0 时选择率记 `null/undefined`，不人为设为 0 或 1。

### 6.2 冻结计数计划

G0/A 通过、G1 来源身份核验通过、B 三项均完成后，在看到计数结果前生成并哈希 `reference_plan.jsonl`。先按 A 冻结全体唯一查询的每个 table occurrence 及所有应有参照槽位，不能只从能生成计数 SQL 的子集建计划。对于以下束无法安全定义的语境，仍保存占位槽位及 unsupported 原因，不编造谓词或参照值；如出现这种实际 workload 限制，完整 C 的启动门槛不满足，状态为 `blocked`，不能自行降级执行受支持子集。提取：

- 每个过滤列的**完整同列布尔束**，如 `x >= a AND x < b`；不是将其当两个独立过滤率相乘。
- 同一表全部本地过滤条件的完整布尔束；与缓存 AVI/MINSEL/EBO 比较以观察列间相关性/近似误差。
- 无过滤表的总行数及缓存无过滤编码为 1 的契约；真实表仅在 `N_total > 0` 时参照比例为 1，空表 `0/0` 为 `null/undefined`，不能与缓存 1 计算误差。不把 join 条件当本地列过滤。

只对可分离的本地过滤定义单表参照。跨表 OR、外连接语境或不可安全投影的表达式，保留 query 身份并报 unsupported；不能删掉跨表项后声称得到原 SQL 的单表选择率。

同一快照内可按 `(database, table, typed_predicate_digest, scope)` 去重精确计数，保存全部 query→参照单元映射与复用次数；`scope` 区分列束、表束和无过滤表。原始 query/table occurrence 槽位与去重参照单元是不同分母，分别冻结；无法形成合法谓词的槽位用独立占位身份保留，不与合法单元合并。覆盖表分别报告每库原始行、唯一 query、table occurrence、列束槽位、表束槽位、无过滤槽位和去重计数单元的预期/完成/unsupported/failed/blocked/未执行数，状态互斥且合计等于对应分母。一个复用单元失败时，其全部映射槽位与 query 都继承不完整状态。所有需要的单元进入计划；运行失败后不得改为只报已完成的易查询样本。

每个参照单元记录 `N_total`、`N_nonnull`（涉及列）、`N_pass`、typed predicate、引擎与快照标识。选择率为 `N_pass/N_total`，分母包括 NULL 行；`COUNT(column)` 不能替代 `COUNT(*)`。只执行生成器构造、标识符正确转义、字面值参数化的单表 SELECT，不直接执行带 workload 后缀或未知语句的整行 SQL。

### 6.3 指标与解释

每个过滤束及表级束报告缓存估计 `s_hat`、精确参照 `s_true`、有符号差、绝对差；逐库与 EQ/单边范围/同列区间/多列组合分层，报告 unique 参照单元等权与 unique-query 等权两种汇总，避免复用次数改变含义。query 等权先在每条唯一 query 内对相应参照单元取均值，再对 query 取均值，列束与表束分开报告；单库汇总之后另报三库等权 macro，不以大库主导跨库均值。真实/估计为零分别列数；两者均正时才报比值与 `abs(log(s_hat/s_true))`，不加 epsilon、不裁剪来掩盖零值。

**误差汇总的有效分母**：只有参照比例已定义且估计有限、合法的单元才进入数值误差汇总；undefined 空表、unsupported、失败、未执行及非有限/越界估计分别计数，始终保留在覆盖总分母中，不替换为零。unique-query 等权只纳入该 scope 全部预期槽位均有有效比较的 query，不对部分有效槽位重新取均值；另报无该 scope 槽位的 query、零有效槽位和部分有效 query 数。按 table occurrence/列身份保留 query 内槽位，去重仅复用计数，不丢掉同一 query 的重复 occurrence 权重。单库或分层有效分母为零时，其均值/分位数为 `null`，同时报告覆盖；三库 macro 仅在三库该指标都已定义时计算，否则为 `null` 并列缺失库，不重加权其余库。比值/log 指标另报双正有效分母，零值类别不得混入双正分母。

描述性绝对差档位冻结为 `≤1e-6 / (1e-6,1e-3] / (1e-3,1e-2] / >1e-2`，并报告原始差值 Q50/Q95/Q99（NumPy `method='linear'`）与最大值。量化分布同时报告各自权重口径、覆盖总分母和有效分母，不将 query 均值分位数写成参照单元分位数。这些是报告档位，**不是准确性合格阈值**，也不能据结果重新定档。

**C 完成条件**：全部冻结槽位与去重计数单元均有可追溯计数，且无 unsupported/failed/blocked/未执行项。精确完成的空表计数可记 `completed` 并另标 `undefined_zero_denominator`，但不能声称其选择率已定义或准确性已认证。仅完成受支持子集或全量分类不能写 C completed。计数计划全覆盖、快照与语义参照可追溯不意味着选择率误差小。明确区分：身份/编码错误、统计估计误差、NULL/类型/边界错误、不同列相关性与不可用参照。高误差不能直接证明其导致模型高尾；本轮不做预测误差归因、校准或显著性结论。

## 7. 预算、停止条件与状态

以下预算是未来运行的上限，不是本轮运行承诺：CPU-only、GPU 不可见；A/B 离线重算最多 4 个 CPU worker；C 按库顺序执行，每次仅一个只读数据库连接/一个计数语句。数据库单语句超时 60 秒，C 累计执行墙钟上限 2 小时。不得改数据库配置、建立索引、ANALYZE/VACUUM、写源表或启动后台不限时查询；只读事务的 session-local 超时设置须记录，不改变持久配置。

身份冲突、hash 变化、未授权数据源、写操作、快照失配立即停止。解析/语义不一致完整记录后不进入后续门槛；超时或预算用尽停止 C，并按计划保存完成/失败/未执行数量，状态为 `partial`。禁止通过跳过、减分母或动态抽样把结果改为 completed；继续或提高预算须另行授权并沿用同一计划或声明新协议版本。

状态枚举：`planned / blocked / failed / partial / completed`。分别保存 A、B 三项、G1、C 状态；只有预定门槛全满足才可写“本协议范围内审计完成”。不得为了统一 completed 覆盖失败状态。
