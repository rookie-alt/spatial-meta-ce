## 0. 目标与口径

**目标**：提升 held-out 目标库（stats / genome / ergastf1，IMDB 阻塞中）估计精度，重点是两处已确认缺口：

| 缺口 | 现状（实测） | 出处 |
|---|---|---|
| 尾部 q95 落后 PRICE 1.6~6.7× | unique-query Q95：stats 74.5~79.3 vs 39.5；genome 200~326 vs 31.3；ergastf1 23.5~24.9 vs 15.3 | [01](01-PRICE-baseline对比.md) §3.2/§3.3、[03](03-PRICE少样本评估.md) |
| STATS 少样本负迁移 | K=5/20/100 全部劣于 K=0（s43 K=5 达 106.04 vs K=0 79.32），约 70% 查询恶化 | [00](00-实验总览.md) §6.3/§6.4 |

附带机制事实（[00](00-实验总览.md) §6.4）：所有方法**平均绝对 log 误差都略差于 PG，只有聚合 Q95 改善**——模型在"修极端错误、牺牲典型查询"，这是 STATS 负迁移的直接来源。

**成功判据（源侧筛选门槛，沿用 [86](86-低维元适应精度改进方案草案.md) §5 冻结语义）**：
- macro 改善 ≥10%（源侧 4+ 表 Q95）；
- 每库 all / 4+ / low4 保护 ≤1.10×；
- 合格候选冻结配置后，目标库按协议只跑一次。

**红线（全程有效）**：目标库不进入训练/超参选择/checkpoint 选择；不伪造标签；不裁剪输出（文献中"输出分位数 clamp"类做法因此不采纳）；数字只写实测输出；`/gly/weilin/PRICE-master` 只读。

### 1.2 剩余嫌疑（按可信度排序）

1. **筛选协议统计功效不足** —— support 抽样方差使 `better_share` 全距 0.0306~0.8578（[92](92-阶段A结果.md) §3.1）；适应超参前 8 名差距 <0.006 < seed 间差异 0.008（[04](04-适应策略源验证搜索.md)、[05](05-三seed评估.md)）。单 seed 筛选会把真改进误判成 `no_candidate`——S6 差 0.58pp 被否即为例证。
2. **损失/选择指标错配** —— SmoothL1 在 log 域对大误差退化为 L1，**无尾部放大**；模型选择指标却是 log-Q95。
3. **"修尾牺牲典型"机制未被针对** —— 无任何杠杆直接约束"不得把典型查询变差"。
4. **输入信息缺口**（join 条件相关性、真实选择率）—— 唯一未验证的大嫌疑。attn/sum_map 负结果**不能**排除它（[14](14-离线实验统一对照与论文结论.md) §5.1 明确写了该限制）；13 号 P2 真实选择率审计协议冻结后从未执行。

## 3. 详细卡片

### P0-1 共享 query 配对筛选设计

- **假设**：当前 arm 间比较混入 query 集合差异 + support 抽样噪声，效应量被淹没。
- **改动**：筛选 runner 改为同一 query 集上成对比较两臂（support 集可不同，query 固定为交集），报告逐 query 配对 Δlog-Q，而不是两个独立 Q95 相减。[92](92-阶段A结果.md) §8 已点名这是重做 support 可预测性检验的前提。
- **验证**：用已冻结的 A/B 历史数据回放新口径，确认判定不变或更锐。
- **成本**：低（CPU，1~2 天）。**这是所有后续筛选的地基。**
- **风险**：81 号协议要求 query = 全集 − 整个 support（[91](91-阶段A实现计划.md) §0），逐条配对需在比较层做交集，不改 81 号冻结 plan 本身。

### P0-2 筛选样本量升级：3 seed × 多 support run

- **假设**：S6 的 −9.42%、Meta65 B/C 的 −12% 是真效应被单 seed 判死。
- **改动**：筛选臂从 seed42 单点扩到 42/43/44，support run ≥5，结论只报均值±区间；门槛判据改为"均值过线且逐库保护在区间内"。
- **成本**：中（每臂 3×GPU 4000 步约 2 小时 + 评估）。
- **风险**：多 seed 后门槛"过线"更难（方差显式化），但这正是诚实口径。

### P0-3 失败查询审计

- **假设**：STATS 负迁移查询与 low4 退化查询有稳定的可观测特征（表数、PG 偏差方向、直方图缺失、join 形态），直接告诉我们缺什么输入信息。
- **改动**：只读分析——对"适应后恶化最狠的查询"做特征画像 + 按 PG 高估/低估分桶；同时覆盖 STATS K>0 恶化查询与 chembl/legalacts low4 退化查询。
- **产出**：决定 P2-1 要加什么特征的依据。
- **成本**：低（CPU）。已存在于 [88](88-低维方案前置诊断协议草案.md) §3.3（D1-A 的指向）但从未执行。

### P0-4 目标库评估补齐与报告纪律

- 补 seed44 目标库评估（当前目标侧只有 2 seed）。
- 所有表格必报 K=0 基线。K 是部署超参不是免费午餐——genome K=20 最优、K=100 回升已证明非单调（[00](00-实验总览.md) §6.3）。

### P1-1 损失对齐 log-Q95 ★首推

- **假设**：SmoothL1/MSE 都不直接优化 q-error 尾部；S6 的粗暴尾部混合已拿到历史唯一正向（−9.42%，[23](23-当前任务清单与源侧改进总结.md) §3），正统化后有望过 10% 线。
- **改动**：`spatial_meta_ce/meta.py:loss_value` 新增 `log_l1`（≈ mean log-Q）与 `pinball_tau`（τ∈{0.8, 0.9} **预注册，不做网格**）；可选 CVaR/batch 尾均值作为第三个变体。**S5/S6 旧路径不动**（`train.py` 硬性要求它们用 smooth_l1，`test_s5_loss`/`test_s6_loss` 锁定）。
- **文献依据**：MSCN（CIDR 2019）直接优化 q-error；Flow-Loss（VLDB 2021, arXiv:2101.04964）指出 q-error 训练在查询模板外推时退化、plan-graph 目标泛化更好；tabular 回归实证（arXiv:2610.13909）quantile loss 稳定优于调好的 MSE，且警告"全局早停会在不同噪声区域间妥协"。
- **实验设计**：新臂进 P0 升级后的筛选协议；候选合格后冻结配置跑一次三目标库。
- **成功门槛**：源侧 4+ Q95 macro ≥10% 改善 + 每库保护；目标侧 unique-query q95 不劣于当前 FOMAML/ERM。
- **成本**：低（约 20 行 + 一晚 GPU）。
- **风险**：尾部样本少、梯度方差大；FOMAML `create_graph=False` 下排序操作需 detach。文献报告 q-error loss 在 pred 极小时梯度不稳，需要在 log 域做、无需 clamp 输出（红线兼容）。

### P1-2 选择性残差门控 g(q) ★直打 STATS 负迁移

- **假设**：[00](00-实验总览.md) §6.4 的机制是"平均变差、修尾部"。让模型学门控 `输出 = pg_log + g(q)·residual`，`g∈[0,1]` 由查询特征决定——典型查询上 g→0 回退 PG，尾部查询上 g→1 发挥学习能力。
- **改动**：`spatial_meta_ce/model.py` head 输出 (r, g) 两路（g 走 sigmoid）；r 末层仍零初始化 ⇒ 初始预测 = PG，`test_arch.py:test_initial_prediction_is_pg` 不破。
- **与已排除的 04 保守回退的区别**：04 是 support 二折 holdout 的**离散接受/拒绝**（小 K 上噪声大、接受率约 50%、无收益）；P1-2 是**元训练时学出的连续门控**，用 23 个源库任务监督，不依赖 support 现场决策。若 P1-2 也失败，则"门控/回退"整族可以盖棺。
- **文献旁证**：TiCard（arXiv:2512.14358）"conservative integration policy / join-only policy 保留近完美中位行为"思路相近（其数字不可直接比，设定不同）。
- **成本**：低-中。
- **风险**：g 坍缩到 0（需监控 g 分布，可加轻微熵正则）；输出仍是加性残差形式，不触"裁剪输出"红线。

### P1-3 episode 分层采样

- **假设**：均匀选库/选 K 让简单查询主导训练；按表数×log 基数分层（或按源库难度加权）让难例分布进入训练。
- **与 S5 的区别**：S5 是 episode 内 loss 权重（已排除，+45.10%）；这是采样分布，机制不同。
- **改动**：`train.py` episode 采样逻辑加 strata，保留采样 digest 可审计性。
- **成本**：低。预期温和，放在 P1-1/2 之后。

### P1-4 三 seed 预测集成

- **假设**：尾部误差有方差成分，跨 seed 预测平均可直接压 q95。
- **改动**：evaluate 层对 3 个 seed checkpoint 的 K-shot 预测取均值。
- **协议合规**：各 seed 独立源侧训练、不引目标信息，协议允许（`run_experiments.py` 目前只做跨 seed 统计、明确不做集成——此改动是新增可选路径）；**不得按目标指标挑 seed**。
- **成本**：极低。稳但幅度有限，适合与 P1-1 叠加。

### P1-5 checkpoint 选择指标复合化

- **假设**：单一 macro log-Q95 选 checkpoint 会在 4+ 与 low4 之间妥协——head3 适应的 4+ −12.96% / low4 +66.24%（[85](85-Meta65源库留出实现与双预检记录.md)）就是这种取舍的放大版。
- **改动**：源 validation 选择指标改为 `log_Q95 + low4 保护项`（例如 max(4+ log-Q95, 归一 low4 log-Q95)），在源侧对比选择行为。
- **红线安全**：只用源验证库。文献旁证 arXiv:2610.13909（全局早停跨区域妥协）。

### P2-1 join 结构标量/低维指纹特征

- **假设**：attn/sum_map 的失败说明"token 交互式"编码在当前特征下无效，但**结构统计量**（join 边数、度序列摘要、星型/链型指纹、join 列基数比）从未进过模型。
- **改动**：优先做成 head 旁路标量（类似现有 counts / log_cartesian），从 SQL AST 现场解析，**尽量不升 `TRANSFORM_VERSION`**（升版 = 全量重建缓存 + 旧 checkpoint 不兼容，成本高）。
- **成本**：低-中（旁路）/ 高（重建缓存）。
- **风险**：表达力弱于真图模型，天花板有限——但性价比高。若 [14](14-离线实验统一对照与论文结论.md) §5.1 的"不能排除表示层瓶颈"要正面回答，最终仍需 P2-3。

### P2-2 执行 13 号 P2 真实选择率审计

- **假设**：模型缺"过滤条件下的 join-key 相关性 / 真实选择率"（[86](86-低维元适应精度改进方案草案.md) §7 第 2 条点名的方向）。
- **产出**：确认或否定"输入信息缺口"假设，决定是否值得 P2-3。
- **状态**：13 号协议已冻结、未实现未执行（历史"用户暂缓"状态，重启需确认）。

### P2-3 重建 join 图/真实选择率特征缓存

- 视 P2-2 结果启动。成本高（提取器、缓存 schema、旧 checkpoint 全不兼容）。IMDB 侧仍阻塞于原始表缺失（[00](00-实验总览.md) §7.1）。

### P2-4 低维元适应（86 号，条件性重启）

- **状态**：`paused_by_user / implementation_not_started`（[86](86-低维元适应精度改进方案草案.md) §8，2026-10-19）。
- **重启前提**（86 §8.4 原文三条）：用户重新授权 + 补齐两条 CPU 契约 + **先解决 support 敏感性**（即 P0-1/P0-2 先行）。
- **排序建议**：排在 P0 完成之后、P1 失败之后。D2 只证明"能表达"不证明"有收益"；容量-精度单调趋势（none→last3→head3 收益递增、low4 损伤递增，88 §1 表）预示 4 维的 4+ 收益会明显小于 head3 的 10% 门槛。

### P3-1 论文口径（不提精度数字，但提"有效精度主张"）

- 目标侧一律 unique-query 主指标 + 配对分析 + K=0 必报。
- STATS 负迁移若被 P1-2 缓解，这是可写的干净故事（"学出何时该回退 PG"）。
- 诚实边界见 §6。

### 4.2 被红线挡住（文献有、但不能做）

| 做法 | 挡在哪 |
|---|---|
| 输出分位数 clamp / 硬裁剪（TiCard 等） | 触"不裁剪输出"红线；原 PRICE [0,30] 裁剪正是已确认缺陷（[00](00-实验总览.md) §8） |
| 在目标库上调 clamp/λ/步数/seed/阈值 | 目标库不进超参选择 |
| 引用 arXiv:2002.04274 的实验数字 | 作者已声明实验有误并撤稿 |
| EgeNet / GraPPLE 具体数字 | 本次调研未定位到可靠原文，**未核实**；引用前须人工核对 |

### 4.3 设定不适配

- 数据驱动方法（DeepDB / Naru / NeuroCard / FLAT）：需访问原始数据建联合分布，与 held-out 目标库 + 少样本设定不兼容。
- 端到端执行时间优化（Bao / Lero / Flow-Loss 全套）：收益指标是运行时，本项目口径是 q-error，混用不可比（且触"推理耗时≠端到端加速"红线）。
- 纯参数扩容：PRICE 1070 万参数尾部仍只领先 1.6~6.7×，扩容收益递减且摧毁"轻量 107×"卖点。

## 6. 诚实预期

- **最可能见效**：P1-1（S6 已给 9.4% 的方向性证据，正统化后过 10% 线概率最高）+ P0（把 S6 这类"差一点"的候选救回来）。
- **对 STATS 负迁移最对症**：P1-2；失败一次即可对"回退门控"整族下结论。
- **上限最高但最贵**：P2 输入信息路线——只有它有机会动 genome 6.7× 级别的尾部差距。
- **必须接受的可能**：做完 P0/P1 后目标侧仍是"中位数同量级、尾部 1.2~2×"的格局。论文主张落在 **107× 轻量 + 少样本覆盖 + 适应稳定性**，而不是精度胜过 PRICE——除非 P2 路线给出结构性证据。
